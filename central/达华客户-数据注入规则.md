# 鲶鱼 catfish · 数据注入规则说明

**版本**: v0.18.0 (2026-07-17)
**Owner**: 陈鸿波 · 鲶鱼团队

---

## 1 · 总原则

**"复杂度集中在中央 gateway 一层 · 客户端零负担"**

**数据零出端**: 员工个人数据 (身份 · 记忆 · 文件) **只在员工机本地 + 企业内 gateway 之间流动** · **不出企业内网**.

---

## 2 · 什么数据被注入 (6 类)

Companion 每次员工发一条 chat 时 · 从员工机 `~/.hermes/` 读 6 个文件 · 打包发到 gateway:

| # | 字段 | 员工机文件路径 | 内容 | 典型大小 |
|---|---|---|---|---|
| 1 | `soul` | `~/.hermes/SOUL.md` | 鲶鱼核心人格定义 | ~15 KB |
| 2 | `soul_customer` | `~/.hermes/SOUL_<CUSTOMER>.md` | 客户特定业务环境 (SOUL_FFCS.md · SOUL_DAHUA.md 等) | ~2-3 KB |
| 3 | `soul_browser` | `~/.hermes/SOUL_BROWSER.md` | 浏览器工具场景纪律 (仅调 `browser_*` 时注入) | ~3-4 KB |
| 4 | `soul_execute_code` | `~/.hermes/SOUL_EXECUTE_CODE.md` | 代码执行场景纪律 (仅调 `execute_code` 时注入) | ~3-4 KB |
| 5 | `user_memory` | `~/.hermes/USER.md` | 员工个人身份/偏好/习惯 (员工手动 or LLM 帮写) | 1-5 KB |
| 6 | `memory_dir` | `~/.hermes/memories/*.md` | 主题级 memory (工作/项目/关系笔记) | 变 · 通常 ~5-20 KB |

**总注入量**: 典型 30-50 KB · 场景不触发时 15-25 KB · 全部都是**员工本人可见的 markdown 文件**.

## 3 · 数据流 · 3 阶段

```
┌───────────────┐      HTTP POST      ┌──────────────┐      HTTP POST      ┌──────────────┐
│   员工机 mac   │  ──── /v1/chat ──→  │  达华 gateway │  ──── /v1/chat ──→  │  上游 LLM 服务 │
│  ~/.hermes/*   │                    │  (企业内网)   │                    │  (Qwen 等)   │
└───────────────┘                    └──────────────┘                    └──────────────┘
      读 6 文件                        pop _identity                       只见 messages 里
      塞 body._catfish_identity_bundle  拼 system prompt                    的 system prompt
                                       forward
```

**阶段 1 · 员工机上** (数据不出员工机):
- Companion 打开 chat 前 · 读 `~/.hermes/` 6 文件
- **员工能查看/修改这 6 个文件** (纯 markdown · 明文)
- 若员工删了某文件 · 那字段就空 · 该段不注入

**阶段 2 · gateway 上** (企业内网):
- 收到 body 里的 `_catfish_identity_bundle` (6 字段)
- **立即 pop 掉** · **不 forward 给上游 LLM**
- 按 `body.tools` 命中的场景决定注入哪些 (省 token)
- 拼成 1 个 `role: system` message · 插到 messages[0]
- 转发给上游 LLM

**阶段 3 · 上游 LLM 上**:
- 只见 messages (含新拼的 system) + tools + model
- **上游 LLM 看到 SOUL + memory 内容 · 但看不到员工机的原文件路径 · 也看不到 `_catfish_identity_bundle` 字段**

---

## 4 · 注入策略 · 何时注入 / 何时不注入

### ✅ 默认注入 (无 skip · 无自带 system):
Companion 发的 messages 里**没** `role: system` → gateway 在最前插 SOUL + memory 作为 system message.

### 🛑 尊重客户端 (若已有 system):
若 messages 里**已有** `role: system` (Hermes 或第三方 client 自己注入了) → gateway **不动** · 尊重客户端意图.

### 🛑 强制不注入 (opt-out):
Header `X-Catfish-Skip-Identity: true` → gateway 直接不注入.

### 🛑 员工没装 SOUL:
若 6 文件全空 → 该段不注入 · gateway 静默跳过 · **鲶鱼退化成 ChatGPT (无人格 无记忆) 但服务不挂**.

### 🎯 场景纪律 · 按 tool 命中动态挂:
| 员工本次调的 tool | 才注入 |
|---|---|
| `browser_*` (自动化浏览网页) | `soul_browser` |
| `execute_code` (跑代码) | `soul_execute_code` |
| 其他 (纯 chat / journal 等) | 都不挂场景段 · 省 3K token |

## 5 · 3 类 HTTP header · 员工个性化

Companion 用 header 控制 gateway 行为:

| Header | 值 | 效果 |
|---|---|---|
| `X-Catfish-Agent-Name` | e.g. `老李` | 员工给鲶鱼起的别名 · gateway 拼 "员工偏好覆盖 SOUL 默认人格" preamble 插 SOUL 前 |
| `X-Catfish-Agent-Personality` | `gentle` / `direct` / `roast` | 3 档人设 (温柔 · 直爽 · 毒舌) · `gentle` 是默认不改 |
| `X-Catfish-Teaching-Mode` | `1` | 教学模式 · gateway 关 9 个干扰 inject + feedback retry · 员工能看清 raw prompt |

**默认值**: 全部为空 → gateway 用 SOUL.md 里的默认人格 (温柔同事 · 名字 "小鲶").

## 6 · 两条 chat 路径 · 行为不同

### 路径 A · Companion 直连 gateway (`useHermes = false`)
```
Companion → gateway 8999 /v1/chat/completions
  body._catfish_identity_bundle = { 6 字段 }
```
gateway 用 `identity_inject.py` 的规则拼 system prompt.

### 路径 B · Companion → hermes proxy 8642 → gateway (`useHermes = true`)
```
Companion → hermes 8642 → gateway 8999
```
**hermes 自己有 identity 注入层** (通过 `catfish-memory` plugin) · 5 kind 路由 (identity/project_fact/workflow/journal/todo/expense).
- `identity` → `~/.hermes/USER.md` (员工本人 · 稳定事实)
- `project_fact` → `~/.hermes/MEMORY.md`
- `workflow` → 员工的工作流程
- `journal` · `todo` · `expense` → 各自专用文件

**hermes 路径不走 gateway 的 identity_inject** · 因 hermes 自己有更细的 memory 路由能力.

## 7 · 数据出境边界总结

| 数据类型 | 员工机 | gateway (达华内网) | 上游 LLM (Qwen 等) |
|---|---|---|---|
| SOUL.md 内容 | ✅ 明文文件 | ✅ 拼进 system prompt | ✅ 作为 system 的 content 看到 |
| USER.md 员工个人 memory | ✅ 明文文件 | ✅ 拼进 system prompt | ✅ 作为 system 的 content 看到 |
| memories/*.md | ✅ 明文文件 | ✅ 拼进 system prompt | ✅ 作为 system 的 content 看到 |
| `_catfish_identity_bundle` body 字段 | ✅ Companion 塞 | ✅ 收到后 pop 掉 | ❌ **不 forward · LLM 看不到这个字段** |
| 员工 chat 输入 (user message) | ✅ 员工输入 | ✅ 透传 | ✅ LLM 看到 |
| tool call 结果 | ✅ 在员工机跑工具 · 结果回 chat | ✅ 透传 | ✅ LLM 看到 |
| gateway 服务端配置 (models.yaml · users.yaml) | ❌ 员工看不到 | ✅ IT 维护 | ❌ 不涉及 |

**关键**:
- **上游 LLM 看到 SOUL 和 memory 的内容** (作为 system prompt · LLM 必须看到才能人格化回复)
- **上游 LLM 看不到员工机本地文件路径 / 员工设备信息 / 员工个人隐私 (除非员工自己在 chat / memory 里写了)**
- **数据不"跨企业出境"**: 员工机 + gateway 都在达华内网 · 只有 chat body (含 system prompt 的 SOUL 内容) 走出企业到公网 LLM

## 8 · 员工可控性

**员工 100% 可控自己的注入内容**:

| 员工能做什么 | 效果 |
|---|---|
| 编辑 `~/.hermes/SOUL.md` | 改人格 · 立刻生效 (下次 chat 就用新版) |
| 编辑 `~/.hermes/USER.md` | 改个人 memory |
| 删除某个 `~/.hermes/memories/xxx.md` | 那条 memory 不再注入 |
| 全删 `~/.hermes/` | 鲶鱼退化 · 无人格无记忆 · 但服务不挂 |
| 教学模式开 (Companion UI toggle) | gateway 关掉 9 个额外 inject · 员工看清 raw prompt |
| 传 `X-Catfish-Skip-Identity: true` | 完全禁注入 |

**审计闭环**:
- Companion 里有 `PrivacyCard` · 员工能查看 `~/.catfish/outbound_log.db` (所有出员工机的 HTTP 请求记录)
- 员工机跑 `cat ~/.hermes/SOUL.md` 就能看 gateway 会用什么内容

## 9 · 达华 IT 侧配置

### 服务端 gateway 配置 (`/etc/catfish/gateway/.env` 或 docker-compose env):

- `CATFISH_CUSTOMER=dahua` → 影响读哪个 `SOUL_<CUSTOMER>.md` (员工机上)
- `HERMES_HOME=/home/user/.hermes` → 允许自定义员工机路径 (通常用不上)

### 关闭注入 (若达华某个员工不想要人格化):

**员工端 Companion 设置里加**:
```yaml
# ~/.catfish/companion.yaml
identity:
  skip: true    # 添加 X-Catfish-Skip-Identity: true header
```

## 10 · 常见问答

**Q: 员工的 SOUL 会不会被别的员工看到?**
A: 不会. SOUL 只从员工本机读 · 塞进他自己那次 chat 请求的 body · pop 后拼进 system prompt · 只影响他本次对话.

**Q: 员工删了 SOUL 后 · 鲶鱼还能用吗?**
A: 能. 静默跳过 · 退化成通用 LLM 对话.

**Q: 上游 LLM (公网 Qwen 等) 能看到员工的 memory 吗?**
A: 能看到 memory 内容 (作为 system prompt 的一部分). 但**看不到员工机文件路径 · 看不到员工 IP · 看不到员工设备信息**. Memory 的内容员工自己完全可见可编辑.

**Q: 如果达华要求"任何员工数据不出企业" · 怎么办?**
A: 3 种方案:
1. **服务端 LLM 也内网化**: `INTERNAL_LLM_BASE_QWEN_MAIN` 指向达华内网 Qwen · 上游 LLM 也在企业内 · 数据不出企业
2. **Skip Identity**: 全员用 `X-Catfish-Skip-Identity: true` · 但鲶鱼退化成通用 chat
3. **员工 memory 加密 · 只在员工机存明文 · gateway/LLM 只见 hashed 或本地检索结果**: 需要 v0.19+ 才能上线

**Q: 教学模式关的 9 个 inject 是啥?**
A: `X-Catfish-Teaching-Mode: 1` 时 · gateway 关:
1. SOUL_BROWSER / SOUL_EXECUTE_CODE 场景段
2. Memory (user_memory + memory_dir)
3. Personalization preamble (agent_name/personality)
4. 客户特定段 SOUL_<CUST>
5. Feedback retry
6-9. 其他内部注入 (工具引导 / few-shot 等 · 让员工看清 raw prompt)
