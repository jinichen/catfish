## 2. 环境准备 · 判断服务器架构

### 服务器硬件规格

- **OS**: Ubuntu 22.04+ / CentOS 8+ / Debian 11+ / macOS 12+ / Windows 10+ (WSL2)
- **硬件**: 4 vCPU / 8 GB RAM (最小) · 8 vCPU / 16 GB RAM (推荐 1000+ 员工)
- **磁盘**: 20 GB 空闲 (image + PG data + audit + logs)
- **Docker**: Docker Engine 20+ 或 Docker Desktop
- **网络端口**: 员工可达 5173 / 8998 / 8999 · 只本机 5432 / 8994 / 8996 / 8997

### 关键 · 装 image 前**必查服务器 CPU 架构**

Docker image 是**特定架构**的 · 装错架构直接跑不起来!

```bash
uname -m
```

**返回**:
- `x86_64` → **amd64** (99% 政企 Ubuntu/CentOS 是这个) → 用 `catfish-central-images-amd64.tar`
- `aarch64` → **arm64** (国产鲲鹏 / 部委服务器) → 用 `catfish-central-images-arm64.tar`

**若鲶鱼团队发的 tar 跟你架构不匹配** → 立即联系 catfish-support · 我们换正确架构的 tar 发你.

### 员工机器架构判断

**mac 员工**:
```bash
uname -m
```
- `arm64` → Apple Silicon (M1/M2/M3/M4) → 装 `_aarch64.dmg`
- `x86_64` → Intel CPU → 装 `_x64.dmg`

**Windows 员工**: 直接装 `_x64_zh-CN.msi` (支持 Intel + AMD x86_64).

## 3. 服务栈架构 · 8 个 Docker service

| # | Service | Image | 端口 (0.0.0.0=对外, 127.0.0.1=只本机) | 功能 |
|---|---------|-------|------|------|
| 1 | postgres | `postgres:16-alpine` | 5432 (127.0.0.1) | 主数据库 (users / quota / audit / facts) |
| 2 | identity | `catfish-identity:0.1.0` | **8998 (0.0.0.0)** | OIDC 认证 · 员工 SSO 登录 |
| 3 | gateway | `catfish-gateway:0.1.0` | **8999 (0.0.0.0)** | LLM 网关 · 员工 chat · fallback 链路由 |
| 4 | skills-hub | `catfish-skills-hub:0.1.0` | 8997 (127.0.0.1) | 技能包托管 · manager 发布 skill |
| 5 | mcp-registry | `catfish-mcp-registry:0.1.0` | 8996 (127.0.0.1) | MCP 连接器仓库 · Jira/GitLab 订阅 |
| 6 | wiki-hub | `catfish-wiki-hub:0.1.0` | 8994 (127.0.0.1) | Wiki 中央 · 员工发布知识 |
| 7 | web | `catfish-web:0.1.0` | **5173 (0.0.0.0)** | admin 面板 (员工管理/审计) |

## 4. 服务端部署 · 10 步

### Step 1 · 建部署根目录 (30 秒)

```bash
# Linux / macOS (推荐 /opt/catfish, 也可 ~/catfish)
sudo mkdir -p /opt/catfish
sudo chown $USER:$USER /opt/catfish
cd /opt/catfish

# Windows PowerShell
mkdir E:\catfish
cd E:\catfish
```

### Step 2 · 装 image tar (选架构对应的 tar!)

```bash
# uname -m 结果 x86_64 → 用 amd64.tar
docker load -i /path/to/catfish-central-images-amd64.tar

# uname -m 结果 aarch64 → 用 arm64.tar
docker load -i /path/to/catfish-central-images-arm64.tar

# verify 8 image 都在
docker images | grep -E "catfish-|postgres:16-alpine|nginx:1.27-alpine"

# verify 架构 · 必须跟 uname -m 一致
docker inspect catfish-gateway:0.1.0 --format '{{.Architecture}}/{{.Os}}'
# 期望: amd64/linux 或 arm64/linux
```

### Step 3 · 解压 config tar (10 秒)

```bash
tar xzf /path/to/catfish-central-config.tar.gz

# 现在 /opt/catfish/ 下有 central/ 目录, 里面 18 个文件
ls central/
```

### Step 4 · cd 进 central 目录 (关键 · docker compose 必须在这跑)

```bash
cd /opt/catfish/central
```

**为啥关键**: docker-compose.yml 里 volume 是 relative path (`./llm-gateway/config`), 在别的目录跑会找不到.

### Step 5 · 建 .env + 改 6 项必填 (5-10 分钟)

```bash
cp .env.production.example .env
vim .env       # 或 nano/notepad
```

**必填 6 项**:

```env
# 1. Postgres 密码 (16+ 位强 · 大小写+数字+符号)
PG_PASSWORD=Dahua_PG_2026_STRONG_pwd

# 2. 内网 LLM API key (达华内网 qwen 平台申请)
INTERNAL_LLM_KEY=达华内网qwen平台的真key

# 3-5. 内网 LLM 3 个端点 URL (换成达华内网真实 IP:port)
INTERNAL_LLM_BASE_QWEN_MAIN=http://10.10.40.102:32730/openapi/xxx/v1
INTERNAL_LLM_BASE_QWEN_VISION=http://10.10.40.102:32730/openapi/yyy/v1
INTERNAL_LLM_BASE_BGE_M3=http://10.10.40.102:32730/openapi/zzz/v1

# 6. Skills Hub token (32 位随机 · manager 发布 skill 用)
SKILLS_HUB_TOKEN=aad226ad9ad83bacbe95e554a07864b0e4d9a215117696b79a161c726d522561
```

**可选 3 项** (公网 LLM · 测试期建议至少填 1 个作为 fallback):

```env
DASHSCOPE_API_KEY=你的阿里 dashscope key    # 申请 https://dashscope.console.aliyun.com/
DEEPSEEK_API_KEY=你的 deepseek key            # 申请 https://platform.deepseek.com/api_keys
GEMINI_API_KEY=你的 gemini key                # 申请 https://aistudio.google.com/app/apikey
```

**Linux 生产环境需改 OIDC issuer**:

```env
# Docker Desktop mac/Win → 默认 host.docker.internal 直接生效
# Linux 生产 (Ubuntu/CentOS) 无 host.docker.internal → 换成服务器 IP 或域名
CATFISH_OIDC_ISSUER=http://<你的服务器 IP>:8998
# 或若有域名 + SSL 反代
CATFISH_OIDC_ISSUER=https://catfish.dahua.com/sso
```

**Windows 记事本保存注意**: 编码选 **UTF-8**, 不要 UTF-16 / ANSI.

### Step 6 · 建 identity users.yaml seed admin 账号 (5-10 分钟)

**先启动 identity + postgres** (生成 hash 要用):

```bash
docker compose up -d postgres identity
sleep 20    # 等 postgres init + identity migrate
```

**生成 admin 密码 hash**:

```bash
# 换成你的强密码
docker compose exec identity python -c \
  "from catfish_identity.users import hash_password; print(hash_password('Dahua_Admin_2026!'))"
```

**输出 copy 整段 hash** (从 `$2b$12$` 开始):
```
$2b$12$abcXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
```

**建 users.yaml**:

```bash
cp identity-server/config/users.yaml.example identity-server/config/users.yaml
vim identity-server/config/users.yaml
```

**替换 CHANGE_ME 为刚生成的 hash**:

```yaml
users:
  - email: admin@dahua.com
    password_hash: $2b$12$abcXXXXXX...   # ← 粘贴 hash
    name: 达华管理员
    department: IT
    role: sysadmin
```

**Truncate PG.users 让 seed 触发** (若已 up 过一次):

```bash
docker compose exec postgres psql -U catfish -d catfish -c "TRUNCATE users CASCADE;"
docker compose restart identity
sleep 15

# verify · 期望 "PG users 首次 seed: 从 yaml 灌 1 条"
docker compose logs identity --tail 20 | grep -E "seed|users 加载"

# verify PG 里真有 user
docker compose exec postgres psql -U catfish -d catfish -c "SELECT email, name, role FROM users;"
```

### Step 7 · 启动全栈 (不含 nginx · 测试期不需 SSL 反代)

```bash
docker compose up -d postgres identity gateway skills-hub wiki-hub mcp-registry web
```

### Step 8 · 等 60 秒 warm up

```bash
sleep 60           # Linux / macOS
Start-Sleep 60     # Windows PowerShell
```

### Step 9 · verify 7 服务健康

```bash
docker compose ps
```

**期望**:
```
NAME                   STATUS
catfish-postgres       Up (healthy)
catfish-identity       Up (healthy)
catfish-gateway        Up (healthy)
catfish-skills-hub     Up (healthy)
catfish-wiki-hub       Up (healthy)
catfish-mcp-registry   Up (healthy)
catfish-web            Up (unhealthy)    ← 已知 healthcheck 路径问题, 功能正常
```

### Step 10 · verify 关键 endpoint

```bash
# identity OIDC 服务发现 · 应返 JSON
curl http://localhost:8998/.well-known/openid-configuration

# gateway 健康 · 应返 {"status":"ok"}
curl http://localhost:8999/healthz

# web SPA 首页 · 浏览器打开
# http://<你服务器 IP>:5173
```

## 6. 模型清单编辑 · 4 个真实场景

**位置**: `~/catfish/central/llm-gateway/config/models.yaml`

**docker-compose 已挂 volume**:
```yaml
volumes:
  - ./llm-gateway/config:/app/config:ro
```

**host 端改, container 立即看到**. 改完 `docker compose restart gateway` 生效.

### 场景 1 · 加达华定制模型 (e.g. daodian-qwen-r1-72b)

**Step A** · `.env` 加 URL + key:

```bash
DAODIAN_QWEN_BASE=http://10.0.5.30:9999/v1
DAODIAN_QWEN_KEY=sk-daodian-xxxxxxxxxxxxxxxx
```

**Step B** · `models.yaml` 加条目:

```yaml
- name: daodian-qwen-r1-72b
  tier: private
  display_name: "达华定制 · Daodian Qwen R1 72B"
  mode: chat
  upstream:
    model: openai/daodian-qwen-r1-72b
    api_base: ${DAODIAN_QWEN_BASE}
    api_key_env: DAODIAN_QWEN_KEY
    timeout: 240
  context_window: 128000
  supports_tool_use: true
  supports_streaming: true
  recommended_for: [general, chat, tool_use, code]
  cost_tier: free
  fallback:
    on_errors: [429, 502, 503, 504, "timeout"]
    chain: [catfish-private-main]
    max_hops: 2
```

**Step C** · verify + restart:

```bash
python3 -c "import yaml; yaml.safe_load(open('/opt/catfish/central/llm-gateway/config/models.yaml'))" && echo OK
docker compose restart gateway
```

### 场景 2 · 关掉 Gemini (数据不出海)

`vim models.yaml` · 从**所有** `chain: [...]` 里删 `catfish-public-gemini-flash` 和 `catfish-public-gemini-pro`. `.env` 里 `GEMINI_API_KEY=` 留空 (自动隐藏 catalog).

### 场景 3 · 完全离网 (只用达华内网)

`.env` 里 3 个公网 key **全留空**:
```env
DASHSCOPE_API_KEY=
DEEPSEEK_API_KEY=
GEMINI_API_KEY=
```

`vim models.yaml` · 从所有 private 模型的 fallback chain 里, 只留 private:
```yaml
fallback:
  chain: [catfish-private-vision]
  max_hops: 1
```

### 场景 4 · 改内网 qwen timeout (推理慢)

`vim models.yaml` · 找 catfish-private-main:
```yaml
upstream:
  timeout: 300   # 改成 600
```

## 7. 后续加员工 · 3 种方式 (v0.18 Phase 1)

**架构说明**: 员工登录密码存**PG.users 表** (bcrypt hash). `users.yaml` **只在**首次启动 seed 一次. 之后 PG 是权威.

### 方式 A · psql 直接 INSERT (最快 · 单个员工)

```bash
# 1. 生成新员工 hash
docker compose exec identity python -c \
  "from catfish_identity.users import hash_password; print(hash_password('EmployeePasswd'))"

# 2. psql insert
docker compose exec postgres psql -U catfish -d catfish -c "
INSERT INTO users (email, password_hash, name, department, tier, role, managed_departments)
VALUES ('zhang.san@dahua.com', '刚生成的hash', '张三', '研发', 'employee', 'employee', '[]'::jsonb);
"
```

### 方式 B · vim yaml + wipe + restart (批量首次 seed)

```bash
vim identity-server/config/users.yaml            # 追加多条 user
docker compose exec postgres psql -U catfish -d catfish -c "TRUNCATE users CASCADE;"
docker compose restart identity
```

### 方式 C · Companion Admin API (Phase 2 未实现)

Companion 里 admin 用户看到 "员工管理" 面板 · Phase 2 加.

### 重置员工密码 (员工忘密码)

```bash
# 1. 生成新 hash
docker compose exec identity python -c \
  "from catfish_identity.users import hash_password; print(hash_password('NewPassword'))"

# 2. psql UPDATE
docker compose exec postgres psql -U catfish -d catfish -c "
UPDATE users SET password_hash = '刚生成的hash', must_change_password = TRUE
WHERE email = 'zhang.san@dahua.com';
"
```

## 8. 常见 6 个坑排查

### 坑 1 · gateway 挂 · worker 循环 die

```bash
docker compose logs gateway | grep "Child process died"
```

**根因 3 种**:

**1. models.yaml 引用了 .env 里没配的 env** (最常见):
```bash
docker compose logs gateway 2>&1 | grep "env variable"
# 若报 "env variable ${INTERNAL_LLM_BASE_XXX} is not set"
# → vim .env 补上对应变量
```

**2. volume 权限不对**:
```bash
docker compose exec --user root gateway chown -R catfish:catfish /home/catfish
docker compose restart gateway
```

**3. PG 密码错** (改过 .env 密码但 pgdata 还是老密码):
```bash
# 测试期无数据可以 wipe
docker compose down -v    # -v 删 volume
docker compose up -d
```

### 坑 2 · identity users 加载 0 · 员工登录 401

```bash
docker compose logs identity | grep "users 加载"
# 若报 "PG users 加载: 0 个用户" → 没 seed
```

**Fix** · 参照 Step 6 · 建 users.yaml + Truncate + restart.

### 坑 3 · Companion 首启弹 CMD 框 (Windows) · 浏览器 URL 挂

**根因** · 老版 msi (CircleCI Build #12 之前).

**Fix** · 换 CircleCI Build #25 之后的 msi (含 rundll32 fix).

### 坑 4 · web unhealthy 但能访问 (healthcheck 路径问题)

已知无害 · 功能正常. 员工浏览器打开 `http://<IP>:5173` 能看到 catfish web 首页.

### 坑 5 · nginx 起不来 · 缺证书

**测试期 skip nginx** (Step 7 命令里没启 nginx 就行).

生产上域名 + Let's Encrypt 证书:
```bash
cp web/nginx.conf.example nginx.conf
vim nginx.conf                # 改 server_name 到达华域名
mkdir certs
# 拷贝 cert.pem + key.pem 到 certs/
docker compose up -d nginx
```

### 坑 6 · docker compose 报 "path xxx not found"

**根因** · cwd 不在 `central/` 目录. compose 里 relative path 找不到.

**Fix**:
```bash
pwd                              # 应该显示 /opt/catfish/central
cd /opt/catfish/central
docker compose ps                # 再跑
```

## 9. 参数速查 · .env / docker compose / psql

### 9.1 .env 全字段

| 变量名 | 用途 | Default | 必填 |
|---|---|---|---|
| `PG_USER` | postgres 用户名 | `catfish` | ⭕ |
| `PG_PASSWORD` | postgres 密码 | 无 | ✅ **必填** |
| `PG_DB` | postgres 数据库名 | `catfish` | ⭕ |
| `GATEWAY_WORKERS` | gateway uvicorn worker 数 | `4` | ⭕ |
| `IDENTITY_WORKERS` | identity uvicorn worker 数 | `2` | ⭕ |
| `INTERNAL_LLM_KEY` | 内网 qwen API key | 无 | ✅ **必填** |
| `INTERNAL_LLM_BASE_QWEN_MAIN` | 内网 qwen chat 端点 | `http://127.0.0.1:9998/v1` | ✅ **必填** |
| `INTERNAL_LLM_BASE_QWEN_VISION` | 内网 qwen vision 端点 | 同上 | ✅ **必填** |
| `INTERNAL_LLM_BASE_BGE_M3` | 内网 embedding 端点 | 同上 | ✅ **必填** |
| `CATFISH_OIDC_ISSUER` | OIDC issuer URL | `http://host.docker.internal:8998` | ⭕ (Linux 生产要改) |

### 9.2 docker compose 全命令

```bash
# 启全栈 (不含 nginx)
docker compose up -d postgres identity gateway skills-hub wiki-hub mcp-registry web

# 状态
docker compose ps

# log (实时 · 最近 100 行)
docker compose logs -f --tail 100 gateway
docker compose logs -f --tail 100 identity

# 重启单服务
docker compose restart gateway

# 停 · 保留数据
docker compose stop

# 启已有的 (不 pull)
docker compose start

# 停 + 删 container (保留 volume 数据)
docker compose down

# ⚠️ 停 + 删 container + 删 volume · 数据全清! 测试期可用, 生产禁
docker compose down -v

# 只 pull 新 image (若给了新版本 tar)
docker load -i /path/to/new-images-<架构>.tar
docker compose up -d --force-recreate
```

### 9.3 psql 常用命令

# 退出
\q
