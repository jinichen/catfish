# 稻生万物 · AI Agent 落地 P1 期实施方案

> **认证智能体 + 招商智能体**
> 国家数字经济与产业互联基金申报 · 技术附件
> 2026 年 7 月

---

## 摘要

P1 期 (0-12 月) 落地 2 个 AI Agent · 选型依据 **技术难度最低 + 业务价值明确 + 零硬件依赖**:

| Agent | 业务价值 | 技术难度 | 依赖 |
|---|---|---|---|
| **认证智能体** | 出口认证材料准备周期压缩 · 法规变更不再靠人盯 | 低 | 无硬件 · 纯文档 |
| **招商智能体** | 集群招商精准匹配 · 入驻服务提前预测 | 低 | 无硬件 · 企业库数据 |

两个 Agent 共用同一技术底座 · 共享知识库建设投入 · **P1 完成即形成可复用方法论** · 为 P2/P3 期打基础.

---

## 一、技术底座 (已有能力)

P1 期**不需要从零搭建 AI 平台** · 底座能力已具备:

| 能力 | 说明 |
|---|---|
| **agent runtime** | 自研本地 agent 运行时 · 员工桌面直接用 · 数据不出本机 |
| **业务工具集** | 70+ 工具 · 含文档检索 / 知识库 / 浏览器自动化 / 邮件 / 日历 / 后台任务 |
| **skill 闭环** | 教学 → 凝固 → 复用. 员工演示一次业务流程 · 系统自动凝固为可复用 skill |
| **知识库** | 本地 wiki (BM25 离线检索) · 支持个人 + 部门共享两层 |
| **多模型路由** | 内网模型 (数据不出内网) + 公网模型 (能力更强) 按场景自动选 · 带 fallback |
| **定时任务** | cron 调度 + 执行记录 + 失败告警 |
| **文风学习** | 扫历史文档提取写作特征 · 生成内容贴合组织既有文风 |
| **全链审计** | 每次 AI 调用 / 工具执行 / 数据访问全记录 · 可导出合规审计 |

**P1 期工作 = 在此底座上建知识库 + 凝固业务 skill** · 不是造平台.

## 二、认证智能体

### 2.1 业务痛点

稻壳/牡蛎壳复合材料出口需通过多个市场的认证体系:

| 市场 | 典型认证 |
|---|---|
| 欧盟 | DIN 环保认证 · TUV 认证 · REACH 合规 |
| 美国 | FDA 食品接触材料 · ASTM 标准 |
| 日本 | JIS 标准 · 食品卫生法 |
| 中国 | GB 标准 · 食品接触材料国标 |

现状问题:
1. **材料清单靠人记** — 每个认证要什么文件 · 老员工脑子里
2. **申报书从零写** — 每次重复劳动 · 格式不统一
3. **法规变更靠偶然发现** — 欧盟新增禁用物质 → 可能几个月后才知道 → 已出货产品面临召回风险
4. **多市场并行时混乱** — 同一产品报 3 个市场 · 材料交叉引用容易漏

### 2.2 Agent 能力设计

#### 能力 1 · 认证材料清单自动生成

```
员工: "这个配方要报欧盟 DIN 认证, 要准备什么?"
Agent:
  1. 检索认证知识库 → 拿 DIN 认证要求清单
  2. 检索产品档案 → 拿该配方已有的检测报告 / 成分表 / 工艺文件
  3. 比对 → 输出:
     ✓ 已有: 成分表 (2026-03 版) · 降解性测试报告 (2026-05)
     ✗ 缺: 重金属迁移测试 · 生产工艺声明 (需更新)
     ⚠ 过期: 微生物测试 (2024-11 · 已超 24 月有效期)
```

**实现路径**: 认证知识库 (wiki) + 产品档案库 (wiki) + LLM 比对

#### 能力 2 · 申报书草稿生成

```
员工: "帮我起草 DIN 认证申报书"
Agent:
  1. 读历史申报书 (稻生万物已有 4 大国际认证 → 有成功样本)
  2. 提取文风特征 (术语用法 / 段落结构 / 表述习惯)
  3. 填入当前产品数据
  4. 输出草稿 docx · 标注需人工确认的字段
```

**实现路径**: 文风学习工具 + 历史申报书样本 + 产品档案 + 文档生成

**红线**: Agent 只出草稿 · **技术参数与合规声明必须人工核对签字** · 不代替认证工程师判断

#### 能力 3 · 法规变更监测

```
定时任务 (每周一 09:00):
  1. 爬取目标法规站点 (欧盟 EUR-Lex / 美国 FDA / 日本厚生劳动省 等)
  2. 比对上次快照 → 识别变更条目
  3. LLM 判断: 变更是否影响稻壳/牡蛎壳复合材料?
  4. 若影响 → 推送通知 + 列出受影响的已认证产品 + 建议动作
```

**实现路径**: cron + 浏览器自动化 + 知识库快照比对 + LLM 相关性判断 + 通知

#### 能力 4 · 认证问答 (客户/入驻企业自助)

```
入驻企业: "我做食品包装, 用集群材料出口欧盟, 需要我自己再认证吗?"
Agent: 检索认证知识库 + 集群认证覆盖范围 → 答:
  "集群材料本身已有 DIN + TUV 认证 (证书号 XXX).
   你的成品仍需做 [食品接触材料迁移测试].
   集群共享服务可代办, 联系 [渠道]."
```

**实现路径**: 知识库 + 权限分层 (入驻企业只见公开范围 · 不见内部数据)

### 2.3 数据准备工作量

| 数据 | 来源 | 工作量 |
|---|---|---|
| 认证要求知识库 | 各认证机构公开文档 + 历史申报经验 | 4 个市场 × 2-3 认证 = 约 10 份要求文档结构化 |
| 产品档案库 | 现有检测报告 / 成分表 / 工艺文件 | 按配方数量 · 每配方 5-8 份文件归档 |
| 历史申报书样本 | 已有 4 大国际认证的申报材料 | 4-8 份 (已有 · 只需归集) |
| 法规源清单 | 各国官方法规站 URL | 约 10 个站点 |

**关键**: 数据都是**现有的** · 工作是**归集 + 结构化** · 不是新造.

### 2.4 里程碑与验收

| 阶段 | 产出 | 验收标准 |
|---|---|---|
| M1 (1-2 月) | 认证知识库建成 | 4 市场认证要求可检索 · 检索准确率人工抽检 ≥ 90% |
| M2 (2-3 月) | 材料清单生成能力 | 给定配方 + 目标市场 → 清单完整性人工核对 ≥ 90% |
| M3 (3-4 月) | 申报书草稿生成 | 草稿人工修改量 ≤ 30% (对比从零写) |
| M4 (4-5 月) | 法规监测上线 | 连续 4 周监测无漏报 (人工双轨验证) |
| M5 (5-6 月) | 认证问答开放入驻企业 | 权限隔离测试通过 · 无内部数据泄漏 |

## 三、招商智能体

### 3.1 业务痛点

产业集群成败关键在**入驻企业质量与匹配度**. 现状问题:

1. **招商靠人脉靠碰** — 不知道集群缺什么类型企业
2. **入驻企业需求摸不清** — 签了才发现服务能力不匹配
3. **合同/权益/评级散在各处** — Excel + 邮件 + 纸质
4. **产业链缺口看不见** — 上下游哪个环节薄弱说不出

### 3.2 Agent 能力设计

#### 能力 1 · 产业链缺口分析

```
员工: "现在集群产业链哪里薄弱?"
Agent:
  1. 读入驻企业档案 (业务类型 / 产能 / 产品)
  2. 对照集群完整产业链模型 (原料 → 加工 → 应用 → 服务)
  3. 输出:
     🔴 缺口: 表面处理环节无企业 (影响: 高端产品交期依赖外协)
     🟡 薄弱: 模具设计只 1 家 (风险: 单点依赖)
     🟢 饱和: 注塑成型 4 家 (可能内部竞争)
```

**实现路径**: 入驻企业档案库 (wiki) + 产业链模型 + LLM 缺口分析

#### 能力 2 · 目标企业匹配推荐

```
员工: "帮我找适合入驻的表面处理企业"
Agent:
  1. 拿缺口分析结果 → 明确需求画像
  2. 检索企业库 (公开工商数据 + 行业名录)
  3. 多维打分: 业务匹配度 / 规模适配 / 地理距离 / 资质完备
  4. 输出候选清单 + 每家的匹配理由 + 建议接触角度
```

**实现路径**: 企业库 + 需求画像 + LLM 匹配打分

**数据来源**: 公开工商数据 (企查查/天眼查等公开 API) + 行业协会名录 + 展会名录

#### 能力 3 · 入驻服务需求预测

```
新企业签约后:
Agent:
  1. 分析该企业类型 · 规模 · 业务特征
  2. 对照历史入驻企业的服务使用记录
  3. 预测: 该企业大概率需要 [仓储 200㎡ / 财税代理 / 出口认证代办]
  4. 提前准备 → 入驻即可用 · 不用等企业提需求
```

**实现路径**: 入驻企业服务使用记录 + LLM 相似性预测

#### 能力 4 · 合同/权益/评级一站管理

```
员工: "A 公司的入驻情况怎么样?"
Agent: 检索 → 输出:
  合同: 2026-03 签约 · 3 年期 · 2029-03 到期 (还有 32 月)
  权益: 已用 [仓储 150/200㎡] [财税代理] · 未用 [认证代办 1 次额度]
  评级: B+ (原料采购量达标 · 但共享服务欠费 2 期)
  待办: 合同 6 个月后进入续约窗口 · 建议提前沟通
```

**实现路径**: 合同/权益/评级数据结构化 + 检索 + 定时提醒

### 3.3 数据准备工作量

| 数据 | 来源 | 工作量 |
|---|---|---|
| 产业链模型 | 集群规划 + 行业调研 | 1 份结构化模型 (环节 / 上下游关系 / 关键指标) |
| 企业库 | 公开工商数据 + 行业名录 | 按目标区域 · 初期建目标环节企业库 (数百到数千家) |
| 入驻企业档案 | 签约资料 | 按入驻数量 · 每家 5-10 项结构化字段 |
| 服务使用记录 | 共享服务台账 | 从平台运营开始积累 (P1 期先建结构) |
| 合同/权益/评级 | 现有合同 + 台账 | 结构化归档 |

### 3.4 里程碑与验收

| 阶段 | 产出 | 验收标准 |
|---|---|---|
| M1 (1-2 月) | 产业链模型 + 入驻企业档案库 | 模型完整覆盖集群业务环节 · 档案字段齐全 |
| M2 (2-3 月) | 缺口分析能力 | 分析结果与人工判断一致性 ≥ 80% |
| M3 (3-4 月) | 企业库 + 匹配推荐 | 推荐候选人工评估可接触率 ≥ 30% |
| M4 (4-5 月) | 服务需求预测 | 预测准确率 (对比实际使用) ≥ 70% |
| M5 (5-6 月) | 合同/权益/评级管理上线 | 数据完整 · 到期提醒零漏报 |

## 四、共享基础工作 (两 Agent 复用)

| 工作项 | 说明 | 复用方 |
|---|---|---|
| 知识库框架 | wiki 结构设计 · 分类体系 · 权限模型 | 两者 |
| 文档归集流程 | 纸质/散落文件 → 数字化 → 结构化入库 | 两者 |
| skill 凝固方法论 | 业务流程如何演示 → 如何凝固 → 如何验收 | 两者 + P2/P3 |
| 权限分层 | 内部 / 入驻企业 / 外部 三级数据可见性 | 两者 + 集群平台 |
| 审计与合规 | AI 调用记录 · 数据访问日志 · 可导出报告 | 全集群 |
| 人员培训 | 业务人员如何用 · 如何教 Agent 新流程 | 全集群 |

**关键**: 这部分投入在 P1 期一次做好 · P2/P3 期新增 Agent 边际成本大幅降低.

## 五、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| **数据归集慢于预期** | 知识库空 → Agent 无法工作 | 分批上线 · 先做数据最全的市场 (欧盟) · 边用边补 |
| **LLM 生成内容有误** | 认证申报出错 → 合规风险 | Agent 只出草稿 · **技术参数与合规声明必须人工签字** · 系统强制人工确认节点 |
| **法规监测漏报** | 已认证产品面临风险 | P1 期人工双轨验证 4 周 · 达标后才单轨 · 保留人工季度全量复核 |
| **企业库数据过期** | 推荐无效企业 | 定期刷新 + 推荐时标注数据时间 |
| **业务人员不会用** | 建了不用 | 培训 + 从最痛的场景切入 (法规监测最省人力) · 用出价值再扩 |
| **权限泄漏** | 入驻企业看到内部数据 | 权限分层设计 + 上线前渗透测试 + 全链审计可追溯 |

## 附:与国家智能体管理能力成熟度标准的对齐

国内已有《人工智能 智能体 管理能力成熟度评估模型》标准工作 (福建省开源数字技术研究院等参与试点). P1 期设计有意对齐:

| 成熟度维度 | P1 期落地做法 |
|---|---|
| **可控性** | Agent 只出草稿 · 关键节点强制人工确认 |
| **可审计** | 每次 AI 调用 / 工具执行 / 数据访问全记录可导出 |
| **可解释** | 输出附来源引用 (哪份文档 / 哪条法规) |
| **数据合规** | 内网模型处理敏感数据 · 数据不出本机/内网 |
| **权限管控** | 三级数据可见性 · 入驻企业隔离 |
| **持续改进** | skill 版本管理 · 效果反馈闭环 |

具体条款对齐清单与新规划详本同步.
