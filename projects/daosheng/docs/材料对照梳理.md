## 一 · 从 v33 掉了什么

nlzx-v2 是从 33 页 docx 提炼的，不是从 v33 来的，所以 v33 里几块内容整块消失了。
有些该掉（视角不对），有些不该掉。

| v33 内容 | 现状 | 该不该补 |
|---|---|---|
| **p6 上下文工程三层**（行业 / 企业 / 实时） | 完全没有 | ★ **该补**。这是「为什么是护城河而不是配置工作」的唯一论证。现在 nlzx-v2 只说「把业务流程凝固为可调用能力」，没说清凭什么别人复制不了 |
| **p12 MES 等传统系统还建不建** | 完全没有 | ★★ **必补**。见第二节第 2 条，这是硬伤 |
| **p18 安全与合规体系**（等保定级、OT/IT 隔离、数据跨境、入驻企业数据边界） | 只在前置条件里留了「数据分级」一行 | ★★ **必补**。**等保对制造企业是准入门槛不是加分项**，涉工业控制系统通常需二级或三级，定级结果直接决定安全投入规模——而现在预算里没有这一项 |
| **p23 验收 KPI**（10 项指标 + 为什么不列良品率） | 只说「效果类指标待基线采集后定值」 | 该补。现在等于「怎么算验收」完全空着，而这是要写进合同的 |
| **p11 数据与知识层**（全域统一定义、多形态存储、数据服务与权限） | 只在岗位表里出现「数据工程师：统一语义模型」 | 可选。核心信息已散在别处，但「语义不统一则 Agent 回答不可信」这条判断没了 |

## 二 · 客户材料里有、我们没对齐的

### ★★★ 1. 「无人开机」——我们把客户写过的话降级了，没说明

客户 p24《数字化管理平台模型》原文列着：

> 配方管理专家系统 · 智能诊断 · 历史追溯维保系统 · **无人开机** · 远程诊断 · 加热诊断

我们 P5「不做什么」写的是：

> 不做无人干预的自动调参 …… 开机准备度检查与时机建议

**「无人开机」→「开机准备度检查与时机建议」是实质性收窄。**收窄本身是对的
（工艺窗口窄、误调代价不对称、安全联锁归 PLC），但**方案里从没点明这是在收窄
客户自己已经写过的东西**。客户拿两份材料一对照，看到的是被减配，而不是被讲清楚。

**处理：**在 P5 或参与方页明确写一句对照——客户材料中的「无人开机」在本方案里
拆成「开机准备度检查（我方）＋ 人工确认放行 ＋ PLC 侧执行（集成商）」，
并说明为什么不做成全无人。

### ★★★ 2. MES / ERP：我们假定它存在，却没说谁建

客户 p24 规划里有：**PLM 云 · 制造云 · MES 云 · 供应链云 · 金蝶云 ERP · BOS 平台**。
p25 还有一整套互联网管理业务蓝图（全渠道订单 / 配送 / 账务 / 会员、智能仓储、分销服务、城市合伙人）。

而我们的方案：

- P5 写「配方参数下发——批次级设定，非实时回路，**属 MES 标准职能**」
- P10 产能外包写「经工艺工程师确认后**经 MES / 配方系统下发**」

**两处都把 MES 当成既有前提，但全篇没有一句说 MES 是已有的、还是要建的、谁建、
什么时候到位。**这是交付边界上的一个洞：如果 MES 不存在，我们的「配方参数下发」
就没有落点。

v33 p12 本来把这件事讲清楚了（MES 仍需建设，定位从「人操作的系统」变成
「Agent 调用的工具与数据源」；ERP 沿用既有不重复建），**提炼时丢了**。

**处理：**补一页或一段，明确 MES / QMS / ERP 的建设归属与接口时点。

### ★★ 3. 医疗领域——认证覆盖面不够

客户 p16 产品应用含**医疗**：药瓶、药盖、一次性抗菌医疗耗材。

我们 P4「合规与客户」写的是：

> 覆盖欧盟 / 美国 / 日本 / 中国四个市场**十余项认证**

但这是按**食品接触材料**口径写的（FDA 食品接触、GB 食品接触国标、DIN、TUV、REACH）。
**医疗器械与药包材是另一套体系**（NMPA 注册、FDA 510(k)、欧盟 MDR、ISO 13485），
认证难度与周期都高一个量级。

**处理：**要么在能力范围里明确「本期不含医疗器械与药包材认证」，
要么把它列入阶段三扩展并单独估工作量。**现在的写法会被读成「都覆盖」。**

### ★★ 4. 投资额 vs 客户自己的盈利预测——必须摆上台面

客户 p27 盈利预测：

| 年份 | 目标 |
|---|---|
| 2026–2027 | 业务量 5 万吨/年，**纯利润不少于 5,000 万/年** |
| 2028 | 产能 10 万吨，纯利润不少于 1 亿/年 |
| 2029 | 纯利润不少于 2 亿/年 |
| 2030 | 产能销售 100 万吨以上，十亿级产业园，IPO |

客户 p26 资金计划的目标是「满足**年产值不少于 1 个亿**的产能硬件条件」。

**我们的项目总投资中值 7,020 万，超过客户 2026–2027 全年的净利润目标（5,000 万）。**

这不是说方案报高了——六台 GPU 是按 2.4T 级模型定的，账是清楚的。
但**这个对照必须由我们主动摆出来**，不能等客户自己发现。可能的走向：

- 数字化投入分摊到三年，与利润曲线对齐（阶段一重、后两年轻，现在正是这个形状）
- 可申报部分 2,735–4,687 万（约六成）能显著改变实际出资
- 若仍不匹配，回到「主力模型选型」那个前置条件——**两台方案总投资约 4,000 万量级**

### ~~★★ 5. 海蛎壳还算不算~~ —— 8/6 已定：**不提**

> 鸿波 8/6：「海蛎壳不提」。README「已废止的方向」里 v14 那条继续有效，
> 客户对外版 p5 / p7 的海蛎壳内容**不纳入本方案**。
> 原料在线检测口径维持稻壳单一原料（含水率 / 粒径 / 灰分），归因模型输入不扩。
>
> 以下为原始分析，留作背景。

客户对外版 p5、p7 有整页海蛎壳内容（片层纳米复合结构、生物相容性、氨基酸与微量元素）。

而 `README.md` 的「已废止的方向」写着：

> 牡蛎壳 / 双原料平权 | v14 废止 | 客户去掉牡蛎壳，选址论证主轴随之作废

**两边不一致。**这份 v2 对外版是客户在用的材料，如果海蛎壳仍在，
则原料在线检测（含水率 / 粒径）的口径要扩——海蛎壳的关键指标与稻壳不同
（碳酸钙含量、煅烧程度、粒径分布），归因模型的输入变量要多一套。

**这条我不能自己定，见第五节。**

### ★ 6. 品牌客户没点名

客户 p18 典型客户案例：**迪士尼 · 哈利波特 · 壳氏唯 · 宜家 · 乐高 · 爱玛客 · 劳斯莱斯**。

我们渠道中心「合作伙伴」写的是「下游：品牌客户、渠道商」——泛称。
而 README 列的痛点之一正是「客户对接的分寸」在少数人脑子里。

**这些品牌的审厂标准与对接经验，是「合规与客户智能体」最该沉淀的企业上下文**
（v33 p6 的「企业上下文」原话：「客户要求、审厂标准与认证档案」）。
现在完全没提。

### ★ 7. 「一中心两平台」没对齐

客户 p20 规划术语：产业园按「**一中心两平台**」规划。

我们的「能力中心 + 渠道中心」与它是什么关系？是同一套的不同叫法，
还是并列的两套？**方案里没有一句交代。**客户看的时候会问。

### ★ 8. 资金计划四块没映射

客户 p26 把资金分成：**固定设备 / 流动资金 / 知识产权 / 团队建设**。

我们的六个科目（硬件采购 / 运营人力 / 平台采购 / 开发外包 / 年服务费 / 其他）
与这四块怎么对应？做一张映射表，客户合并预算时就不用自己猜。

### ★ 9. 七大应用领域印证了产线口径 ✓

客户 p11–17：餐饮食品包装、日常用品、工业用品、农业用品、医疗、辅料。
**全部是成型制品。**

这印证了 8/6 确认的「稻生产线止于造粒 / 板材，成型归下游入驻企业」——
七大领域正是下游入驻企业要做的事，也解释了为什么园区赋能是必需的。
**这条不用改，但可以在 P10 产能外包里引用，让口径更有依据。**

## 三 · 最要紧的三条

1. **MES / ERP 的建设归属**（第二节 2）——方案两处依赖它，却没说谁建。交付边界的洞。
2. **等保定级**（第一节）——制造业准入门槛，涉工控通常二级或三级，**定级结果决定安全投入规模，而预算里现在没有这一项**。
3. **投资额与客户利润预期的对照**（第二节 4）——7,020 万中值 vs 5,000 万年利润目标。主动说，不要等被问。
