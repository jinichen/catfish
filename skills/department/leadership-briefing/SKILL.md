## 文档结构: blocks 模式

**4 段固定逻辑顺序** (概况 → 分项 → 问题 → 计划), 但**每段的 heading 文本由 LLM 根据汇报场景自由命名**.

### 4 段逻辑顺序 (顺序不可调, 标题文本灵活)

| 序 | 逻辑主题 | 必含内容 | 标题文本示例 (LLM 任选合适的) |
|---|---|---|---|
| 一 | **概况** | 总体情况、关键数字、覆盖范围 | "2026 年资质管理总体情况" / "本月工作概览" / "项目背景概述" / "上半年业绩总览" |
| 二 | **分项情况说明** | 按业务线 / 类别 / 部门拆分的具体进度 | "三大类资质建设进度" / "各条线推进明细" / "重点项目进展" / "分类目工作完成情况" |
| 三 | **存在问题** | 当前瓶颈、风险、未达预期事项 | "当前面临的主要问题" / "瓶颈与风险分析" / "需要关注的事项" / "未达预期分析" |
| 四 | **下一步计划** | 下阶段动作、时间节点、责任分工 | "下阶段重点工作" / "Q3 落地计划" / "后续推进安排" / "下月工作部署" |

**LLM 选 heading 时**:
- 看汇报场景定: 季度汇报用"一、上半年业绩总览", 单项目用"一、项目背景概述"
- **heading 必须含数字编号** "一、" "二、" "三、" "四、" (LLM 自己写完整, 例 `"heading": "一、2026 年资质管理总体情况"`)
- 不强制特定字眼如"概况" — 但**第一段必须是概况**, 第二段必须是分项, 第三段必须是问题, 第四段必须是下一步计划. 顺序不可调.

### ⭐ 内容质量铁律 (鸿波 4-30 反馈"内容太简单, 要有分析")

**正文 4 段以 `paragraph` 分析为主, 不要堆数据列举.** 每段必须包含:

1. **论点**: 一句话总结这段的核心判断 (例: "整体进度稳定推进, 但新增类资质明显滞后")
2. **数据支撑**: 1-2 个关键数字, 但**不要长清单** (长清单转附件)
3. **推论 / 影响 / 趋势**: 数据背后的解读 (为什么这样, 会怎样, 跟去年比如何)
4. **承上启下**: 跟下一段或附件的衔接 (例: "具体明细见附件 1")

错误示范 (鸿波 4-30 实测发现的问题):
```
❌ "Q1 资质投标 157 次, 涉及 32 种, 26 个部门."   ← 纯数据, 没分析
❌ kv_table[(新增, 9 项), (更新, 22 项), (政企, 11 项)]  ← 把数据塞表格放正文
```

正确示范:
```
✅ "Q1 资质投标累计 157 次, 较去年同期增长 23%, 反映业务竞标活跃度
    显著提升. 调用资质共 32 种 (覆盖率 41%), 资质组合应用程度提高,
    说明业务向高复杂度场景延伸. 部门分布显示政企条线占主导 (52 次,
    33%), 详细数据见附件 1."
```

### ⭐ 表格全部作为附件 (鸿波 4-30 反馈"表格放正文后面以附件展现")

**默认**: 所有表格化数据 (清单 / 频次统计 / 对比 / 明细) **全部走 attachments**, 正文用 paragraph 引用 "详见附件 N".

**例外**: 仅当某个**关键 KPI 总览表** (≤ 5 行) 领导一眼必看时, 才在正文用 `kv_table`. 例如:

```python
# § 一 概况末尾, 1 个 5 行的关键 KPI 总览
{"type": "kv_table", "rows": [
    ["资质总数", "39 项 (有效 38)"],
    ["年度计划", "67 项, 已完成 42 (62.7%)"],
    ["Q1 投标", "157 次, 32 种资质"],
    ["头部差距", "17 项 (待突破)"],
]}
```

**禁止**: 在正文嵌入 6 行以上的 `table` / 多列详细数据表 — 都转 attachments.

### Block 类型 (4 种)

#### `paragraph` — 普通段落 (⭐ 4 段正文首选)

```python
{"type": "paragraph", "text": "公司持证人员 5 人, 尚缺 1 人. 详见附件 1."}
```

- 自动首行缩进 2 字符
- 红字高亮根据 `important_phrases` 自动应用

#### `kv_table` — 项目-内容两列表 (公文方案标志)

```python
{"type": "kv_table", "rows": [
    ["用人部门", "已与人力部、集成能力中心沟通确认 ..."],
    ["公司归属", "先入职北福, 后转中电"],
    ["待遇标准", [   # 多行内容用 list 包
        "1. 月工资: ...",
        "2. 五险一金: ...",
    ]],
]}
```

- 左列固定窄 (3cm), 右列宽 (13cm)
- 内容支持单行 (str) 或多行 (list[str])
- **公文 § 三方案 必用这个**

#### `table` — 普通多列表 (问题清单 / 数据汇总)

```python
{"type": "table",
 "headers": ["序号", "问题", "影响", "紧迫度"],
 "rows": [
     [1, "数据更新滞后 3 个月", "已错失 2 个投标窗口", "高"],
     [2, "审核流程跨 4 部门", "单条 11 工作日", "中"],
 ]}
```

- 表头加粗
- 列宽自动均分
- 用于 § 二问题 / 数据汇总等场景

#### `ordered_list` — 数字层级列表 (下一步计划专用)

```python
{"type": "ordered_list", "items": [
    {"text": "启动一级建造师招聘工作:", "subs": [
        "(1) 需符合社会招聘条件 (学历本科及以上; 年龄低于 40 岁)",
        "(2) 招聘过程中重点关注相关专业背景及一级建造师执业资格;",
    ]},
    {"text": "人员到岗并完成资质人员配备后, 同步推进法人变更.", "subs": []},
    {"text": "后续管理:", "subs": ["集成能力中心负责入职人员的考勤与工时管理."]},
]}
```

- 顶级 `1.` `2.` `3.` 阿拉伯数字
- 子项 `(1)` `(2)` 中文括号
- 子项左缩进 2 字符
- **公文 § 五下一步 必用这个**

### 段内灵活混排

每段的 `blocks` 数组可以**任意组合**任意 block 类型:

```python
{"heading": "二、问题与影响", "blocks": [
    {"type": "paragraph", "text": "该缺口已对业务产生影响:"},
    {"type": "table",        # 多个问题用表格列出
     "headers": ["问题", "影响"],
     "rows": [["数据滞后", "错失投标"]]},
    {"type": "paragraph", "text": "若直接变更法人, 将 ..."},
]}
```

## 附件 (CSV 清单)

### 何时用附件

- 主文档正文里有**长清单 / 数据明细** (例: 145 类资质 / 50 名持证人员 / 30 项预算条目)
- 直接放正文会让文档**冗长难读**, 领导抓不到重点
- 解决: 正文写一句"目前 X 详见附件 N", 附件用 CSV 提供完整数据

### 附件结构

```python
attachments=[
  {
    "filename": "附件1-资质人员清单",   # 不带扩展名, skill 自动加 .csv
    "kind": "csv",
    "headers": ["序号", "姓名", "证书编号", "专业", "持证日期", "状态"],
    "rows": [
      [1, "张三", "粤01-123456", "机电工程", "2020-05-12", "在岗"],
      [2, "李四", "粤01-234567", "建筑工程", "2019-08-20", "在岗"],
      ...
    ],
  },
  {
    "filename": "附件2-补位方案预算明细",
    "kind": "csv",
    "headers": ["费用类别", "金额 (元/年)", "说明"],
    "rows": [
      ["员工工资", 32400, "税后 2000/月 × 12 + 月薪"],
      ["五险一金 (公司)", 11385, "由公司统一缴纳"],
      ["合计", 43785, ""],
    ],
  },
]
```

### 附件细节

- **命名**: `附件1-XXX.csv` / `附件2-YYY.csv`, 跟正文里 "详见附件 1" 编号对得上
- **位置**: 跟主 .docx **同目录**, 员工 Finder 一打开看全部
- **编码**: UTF-8 BOM, Excel/Numbers/记事本 / WPS 直接打开中文不乱码
- **数字**: rows 里数字直接传 int / float, 不加引号

## 输出路径规则

```python
# 员工指定路径 (推荐场景: "保存到 ~/Desktop/")
output_path="~/Desktop/补位汇报.docx"
# → 主文件在 ~/Desktop/补位汇报.docx
# → 附件在 ~/Desktop/附件1-资质人员清单.csv 等 (同目录)

# 没指定 → 默认到鲶鱼托管目录

# → 主文件在 ~/.catfish/output/2026-04-29/14:30:25_补位汇报/补位汇报.docx
# → 附件在同目录
```

**为啥不用 /tmp**: macOS 重启清空 + 系统 7 天后自动清理, 客户机演示完文件就没了, **demo 翻车风险大**. 员工想清理用 Companion 仪表盘里"清理 30 天前输出"按钮 (TODO).

## 错别字 + 合规自审

LLM 生成内容时**必须**自审:

1. **错别字高危**: 的/得/地 / 即/既 / 那/哪 / 已/以 / 帐/账 / 部署/布置
2. **称谓**: "公司" 不写 "公司方" / "我公司" 写 "本公司" / "领导" 不写 "上级"
3. **数字**: 千分位空格不用逗号, 金额大写"元 / 万元" 不混用
4. **不要出现**: emoji / 英文标点 (用 ， 。 ： 不用 ,.: ) / 半角空格混排
