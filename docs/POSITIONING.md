> 一页纸说清楚: 我们卖什么, 卖给谁, 凭什么客户选我们.
>
> 用法: 软著申报 / 投资人 pitch / 客户 demo / 招聘 / 内部对齐. **统一口径**, 凡是对外说"鲶鱼是什么", 都从这里取。

---

## 1 · 一句话定位 (Elevator Pitch)

> **鲶鱼是中国企业的"AI 同事": 装在每个员工电脑上, 替员工跑邮件 / 浏览器 / 内网系统, 同时帮员工练沟通和决策, 数据全部留在边缘, 公司只看用量不看内容。**

---

## 2 · 三句话深一层

| 维度 | 一句话 |
|---|---|
| **客户怎么用** | 员工开机 → 鲶鱼自起 → 自然语言聊"今天哪些邮件没回" / "周三汇报演练一下" / "在合规平台上找谁是管理员" → 鲶鱼跟员工**已登录**的飞书 / Outlook / Foxmail / 内网系统直接对话, 5 秒给结果 |
| **跟 ChatGPT 区别** | ChatGPT 是公网通用脑, 看不到员工本地数据, 出错就让员工自己复制粘贴; 鲶鱼跑在员工电脑里, 直接读公司账号下的文件 / 邮箱 / 内网, 替员工**真在系统里干活** |
| **跟"接 OpenAI 的国内套壳" 区别** | 那些是"中央存所有数据"模式, 公司合规过不了; 鲶鱼是边缘主权架构: 对话内容**永不上传**中央, 只有 metadata 上传给计费 / 用量统计 |

## 3 · 三大支柱 (产品形态)

```
┌──────────────────────────────────────────────────┐
│              鲶鱼 = 一个"AI 同事"                 │
│                                                   │
│  💼 浏览器副手     📨 邮件副手    🧠 自我进化     │
│  Browser Agent   Email Agent   Self-Evolution   │
│                                                   │
│  • 内网系统操作   • 读 Foxmail   • 学员工偏好    │
│  • 合规平台审查   • 起草回复     • 沉淀 skill    │
│  • 表单 / 报表   • 不自动发     • 跨员工共享    │
└──────────────────────────────────────────────────┘
        ↓                ↓               ↓
┌──────────────────────────────────────────────────┐
│  本地 Companion App + Hermes Agent + 工具桥        │
└──────────────────────────────────────────────────┘
        ↓
┌──────────────────────────────────────────────────┐
│  catfish-gateway (中央) — 鉴权, 计费, 模型路由    │
│  ⚠ 只看 metadata, 不看内容                        │
└──────────────────────────────────────────────────┘
```

**三大支柱选择逻辑**: 这三件事是中国职场员工**每天都做、做了又烦、ChatGPT 又解决不了的**:
- 浏览器: 内网系统没 API, 员工每天点鼠标点几百次
- 邮件: 公司邮箱不支持 IMAP, 员工每天 30+ 封要分诊 + 起草
- 自我进化: 普通 AI 助手永远在"零起点", 不学员工的偏好和上下文

## 4 · 客户画像

### 主目标客户

**100-500 人的中国成长型企业**, 满足以下任意 2 条:
- 用自建邮件 / 内网 OA / 合规平台 (对外 SaaS 接不进来)
- 数据合规要求高 (金融 / 医疗 / 政企 / 出海科技)
- 已经买过 ChatGPT 但员工"用不起来 / 用得分散"
- IT 团队不大 (10 人以内), 上不动复杂中央 AI 平台

### 不是我们的客户

- < 30 人创业公司 (用 ChatGPT 套壳够了)
- > 5000 人国企 (要的是中央集权 AI 平台, 不是边缘主权)
- 纯 to-C 场景 (我们是 to-B 工具, 不做消费应用)
- 客户 IT 强 + 数据无敏感 (他们自己接 OpenAI API 就行)

## 5 · 5 条 Hard Differentiation (硬差异)

跟 ChatGPT / Copilot / 文心一言 / 通用 RAG 平台对比, 我们独占的 5 件事:

| # | 我们 | 别人 |
|---|---|---|
| 1 | **数据 100% 本地**, 对话内容 0 上中央 | 公网模型必上传; 国内"私有化"通常也要中央存对话 |
| 2 | **直读员工本地客户端**: Foxmail SQLite / Outlook AppleScript / 已登录 Chrome CDP | 必须开 IMAP / SSO / API, 公司常常不开放 |
| 3 | **三大支柱 niche 锁死**: 浏览器 + 邮件 + 演练 / 复盘 | 通用 chatbot 做啥都泛 |
| 4 | **跨员工 skill 共享**: A 学的"飞书报销自动化" 可以推给 B (P2) | 无 |
| 5 | **演练 / 复盘真方法论**: SBI / NVC / 金字塔 / STAR, 不是空话 | 通用助手只会"加油" |

## 6 · 三个英雄场景 (Demo 必演)

每场景都有"真实痛点 → 旧办法痛苦 → 鲶鱼怎么 5 秒搞定"对比:

### 场景 1 · "今天有什么邮件没回?"
- **旧痛点**: 自建邮件没 IMAP, 只能开 Foxmail 一封封翻; 50 封看一遍 10 分钟
- **鲶鱼**: 一句话 → 鲶鱼读 Foxmail SQLite + .mail 文件 → markdown 表 5 秒列出未读 + 重要发件人优先
- **关键 demo 点**: 员工不需要任何配置, 直接拿 Foxmail 已登录态

### 场景 2 · "帮我演练周三的汇报"
- **旧痛点**: 找 mentor 一个月见一次; ChatGPT 演成"友善 yes-man" 没价值
- **鲶鱼**: 进 in-character 模式 → 真扮苛刻老板 / 投资人 → 多轮 push → 系统复盘 ✓3 + ✗3 + 方法论
- **关键 demo 点**: 复盘格式严格, 句式样板可执行, 不是"加油"

### 场景 3 · "在合规平台上看下今天新建用户"
- **旧痛点**: 内网系统没 API, 登录 → 翻到 admin → 查 → 导出, 5 分钟
- **鲶鱼**: 一句话 → 鲶鱼用员工的已登录 Chrome (CDP) → 走 catfish-browser-compliance skill → 直接出 markdown 报表
- **关键 demo 点**: 员工不用重新登录, 不用截图给鲶鱼, 全 DOM 自动操作

## 7 · Pricing 心智 (P1 锁定)

不在 one-pager 上写死价, 但定位心智:

- **不是按 token 计费**: 员工不该理解 token
- **不是按"AI 调用次数"**: 容易被理解为"按问问题次数"
- **是按"员工席位 / 月"**: 类似 Slack, 让公司财务一眼算清楚
- **可能加"附加包"**: 浏览器自动化 / 邮件高级 / 跨员工协同, 按场景加包卖

价格锚点 (推测): 50-150 元/员工/月, 跟飞书 Plus 一个量级.

## 8 · 我们不做什么 (反 scope creep)

- ❌ 不做通用 chatbot (那是 ChatGPT 战场)
- ❌ 不做中央数据湖 (那违反我们的边缘主权哲学)
- ❌ 不做 to-C (员工 / 个人版面我们不卖)
- ❌ 不做"自训模型" (我们是 AI 应用层, 模型用第三方)
- ❌ 不替代 IM / 协作工具 (Slack / 飞书不是我们 surface)
- ❌ 不做销售 SDR / Marketing AI (太多人卷了)

## 11 · 反对意见 (FAQ)

**"鲶鱼跟 Hermes / OpenClaw / OpenInterpreter 这些开源 agent 不是同一个东西吗?"**

不是. 它们是**底层 runtime / SDK** (Linux kernel 那一层); 鲶鱼是**基于 runtime 的产品 + 企业平台** (Ubuntu 那一层). 详细对比见 `docs/COMPETITIVE-DIFFERENTIATION.md`.

简版: 拿 Linux kernel 跟 Ubuntu 比同质化吗? 内核相同, 产品完全不同. 客户付钱买的不是内核.

5 条硬差异 (随便哪条都让 Hermes 直接出局):
1. **直读员工已登录的 Foxmail / Chrome / 内网 OA** — Hermes 没有, 要自己写代码接
2. **数据 100% 在员工电脑, 公司只看 metadata** — Hermes 没这种架构, 它只是单机
3. **演练方法论 (SBI / NVC / STAR / 金字塔)** — Hermes 没有, 它是通用 runtime
4. **跨员工 skill 共享 (Skills Hub, P2)** — Hermes 没有"组织层"概念
5. **企业鉴权 + Quota + Audit + IT 5 人能跑** — Hermes 完全没有

最关键的差: Hermes 服务**会装会配**的开发者 (5%), 鲶鱼服务**装不动 Hermes** 的销售/HR/客服 (95%).

**"为什么不直接用 ChatGPT?"**
ChatGPT 看不到员工本地的 Foxmail / Outlook / 内网系统. 员工要复制粘贴一上下午, 还可能漏数据 / 截图泄漏隐私. 鲶鱼直接接员工已登录的客户端, 5 秒读到本地数据.

**"为什么不直接接 OpenAI / Claude API 自己写一个?"**
那是去年的活. 写完 N 个员工要"手把手教训"它你们公司的 OA 长什么样, 飞书消息怎么解析. 鲶鱼把这套**通用基础设施**(身份注入 + 网关 + Companion + 三支柱 skill)打包好了, 客户从 day 1 就能用, 不用养 5 人的 AI 工程团队.

**"员工数据真不上传?"**
对话内容**端到端**在员工本机的 hermes 进程里, gateway 只看 OpenAI API 风格的 request 元信息 (token 数, 模型, 延迟, 错误码). 我们提供审计脚本 (`scripts/audit_logs.sh`) 让客户 IT 团队自己核验. 这是写进合同的承诺.

**"鲶鱼自己挂了员工怎么办?"**
鲶鱼是员工电脑上的进程. 客户公司的网关挂了, 员工的鲶鱼仍能跑本地能力 (本地搜索 / Foxmail 读邮件 / 演练). 中央 gateway 只是路由 LLM 请求, 不挂员工日常生产力.

**"开源还是闭源?"**
**核心开源, 应用闭源**:
- 开源 (Apache 2.0): hermes-agent fork, gateway, tool-bridge, identity/SOUL, browser-agent skill, email-agent
- 闭源 (商业): Companion App, 中央管理界面, MCP registry, Skills Hub, telemetry

详见 `docs/STRATEGY.md` Open Core 章.

## 12 · "招牌镜头" (用一张截图打广告时拍这个)

不是 Dashboard. 不是配置页. 是**这一组连续动作** (锁死跟 Hermes 等开源 CLI agent 的层差):

### 镜头 1 · 0 配置启动 (锁死安装门槛)

> 销售小王打开公司发的 Catfish 安装包, **双击, 0 配置 0 命令行**, SSO 登录,
> 进对话: "今天哪些客户还没回?"
>
> 5 秒后, 表格列出未读邮件 + 优先级 + 紧急程度

锁死: Hermes / OpenClaw 半小时配置门槛, 销售根本上不去手. 这一帧客户**自动会问** "Hermes 能这样吗?", 答案是"不能".

### 镜头 2 · 接本地客户端 (锁死中国本土场景)

> 同一对话: "帮我给王总起草一封, 客气点"
>
> 5 秒后: 草稿在 Foxmail Drafts 里待发, 鲶鱼读了员工历史邮件知道王总的称谓 / 邮件风格

锁死: ChatGPT 看不到 Foxmail, Hermes 接不到 Foxmail SQLite. 中国大量公司用 Foxmail / 自建邮件 / 飞书内网, 没有 IMAP, 没有 API. 鲶鱼直接接员工**已登录**的客户端.

### 镜头 3 · 演练真方法论 (锁死价值差异)

> 同一对话: "帮我演练下午的 demo"
>
> 进 in-character 模式 → 鲶鱼扮苛刻客户, 多轮 push → 员工卡壳 → 客户继续 push → 10 分钟后员工说"暂停, 复盘" → 鲶鱼给 ✓3 / ✗3 / 推荐 STAR 框架 / 下次试试主动 push

锁死: ChatGPT / Hermes 都是 yes-man, 没有方法论沉淀. 鲶鱼用真 SBI / NVC / STAR / 金字塔.

---

**这一组连续 3 个镜头**是**全产品最浓缩的卖点**:
- 0 配置 + 接本地 + 真方法论 = 鲶鱼
- 缺一不可, 缺一项就跟 Hermes / ChatGPT 同质化了

## 14 · 我们的"独特性" (1 句话)

> **鲶鱼不是 AI 助手, 鲶鱼是中国企业的 AI 同事 — 一个不会泄密、不耽误事、能学习、敢顶嘴的同事。**

—— 边缘 + niche + 协同 = 鲶鱼.

**对应到技术层差**: 鲶鱼**不是 AI 引擎** (Hermes / OpenClaw / OpenInterpreter 在那一层), 鲶鱼**是基于引擎的整车** — 销售 / HR / 客服直接开走, 不需要先学修车. 详见 `docs/COMPETITIVE-DIFFERENTIATION.md`.
