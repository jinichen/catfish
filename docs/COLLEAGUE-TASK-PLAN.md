# 请同事帮忙 · 派任务给多位同事 —— 计划

11/4 鸿波定。原来的「请同事的小鲶帮忙」(P50, 9/10) 只能找**一个人**、对方要在 **10 分钟**内点同意,
之后**发起人这台电脑一直开着、在局域网里直连对方的小鲶**派工等结果。关机、合盖、不在一个网段就断。
四类任务 (立即 / 定时 / 周期 / 多阶段) 都要「发出去就不用管, 到点对方自己做, 结果自己回来」,
所以改成**异步任务单**, 跟「一起填表」走同一个邮筒。

## 0. 统一模型

发起人写一张任务单 → 发给多位同事 → 每人各自决定接不接 → 接下后在**他自己的电脑上**由他的小鲶
(或他本人) 做 → 他核对后点「交回」→ 结果经中央转交, 只回到发起人电脑。

- 中央只转交 (不透明 payload, 不解析、不记日志、取走即清空), 跟填表同一套 (`room_link_mailbox`)。
- 对方同意时看到的只有: **要做什么、什么时候 (截止)、结果交给谁**。不列工具 (11/4 鸿波: 员工看不懂, 把关在执行时)。
- 执行时的把关照旧: 只读的不用批; 发邮件 / 发消息 / 删东西每次问对方本人; 结果对方点「交回」才发出。
- 这是「请」不是「命令」: 拒绝是正常结果, 界面上显示原因。

## 1. 第一步 (11/4 做完): 立即完成的任务 · 多人 · 截止 · 汇总

| 位置 | 内容 |
|---|---|
| 中央 `room_link_db.py` | 加 `TASK_KINDS`: task_invite / task_reply / task_remind / task_cancel, 期限规则同填表 (截止后 7 天, 夹在 [10 分钟, 30 天]) |
| tool-bridge `colleague_tasks.py` | 本机账本 `~/.catfish/collab_tasks/` + 收发 + 状态; `pim/ctask_*` 给界面; `forms_net.py` 投 / 取通用化 |
| 小鲶工具 | 合进 `catfish_form` 的 `task_*` action (网关工具数已到 49 上限, 不新增工具): 派出 / 催 / 取消要员工确认; 做同事派来的任务只能 `task_draft` 存结果草稿, **没有接下 / 交回 / 不接** |
| Companion | `commands/colleague_tasks.rs` 只放行 `pim/ctask_*`; 「协同」页左上换成 `TasksPanel` (同事请我做的 / 我请同事做的), 弹层 `TaskComposer` / `TaskWork` / `TaskProgress`; 20 秒取一次邮筒, 新任务 / 被催 / 取消 / 交回 / 不接发系统通知, 待处理 + 在做算红点 |

信封 (中央看不懂也不看):

```
task_invite  {v, task_id, task: {title, text, deadline}}      不含别的收件人, 不含别人的结果
task_reply   {v, task_id, status: accepted|done|declined, result?, reason?, at}
task_remind  {v, task_id, text?}
task_cancel  {v, task_id}
```

规则:

- 一次最多 20 人; 任务说明 ≤ 2000 字; 交回的结果 ≤ 15000 字 (邮筒单封 64KB)。附件这一步不做, 长材料用邮件。
- 截止可以只给日期 (当天 23:59 截止) 或带时分 (`2026-11-05T18:00`, 本机时间); 不给 = 不限时。
- 发起人看到的状态: 未发 / 等回应 / 在做 / 已完成 / 逾期完成 / 不接 / 超时未回 / 超时未交 / 已取消。
- 收件人: 待处理 / 在做 / 已交回 / 不接 / 已取消。交回后可以改了再交 (后交的覆盖); 回了不接还能再接下。
- 催只催还没交回的; 取消只通知还没交回的, 已交回的结果留着。
- 防冒名: 同编号别人发的任务单不覆盖; 不是这个任务收件人发来的回复不收; 催 / 取消只认原发起人。
- 「让小鲶做」走工作台一次性请求 (跟填表的「让小鲶先填」同一条路), 同事原话放在 `<<< >>>` 里当任务内容,
  提示词写明对外操作先问、结果只存草稿、不要自己发给对方。
- 老版 Companion (< 1.2.56) 取件不带 task_* kind, 任务单留在中央等它升级 (不会被取走丢掉); 发起人那边一直是「等回应」, 进度页提示对方升级。
- 老中央 (不认 task_*) 投 / 取都回 400: 界面说「中央端版本太旧, 请管理员升级」。
- 原来的在线直连 (P50) 发起入口去掉; 右栏「等我点头」照旧, 接老版本同事发来的在线请求和工具审批。

## 2. 第二步 (待做): 定时 / 周期

- 任务单带「什么时候做」: 某个时间 / 周期 (每天 / 每周几 / 每月几号) + **必须有结束条件** (结束日期或最多几期)。
- 对方同意后在**他电脑上**建定时任务 (hermes cron, 跟现有定时任务同一套), 绑定 task_id; 每期结果作为「第 N 期」交回。
- 到点对方电脑没开: 开机后补做, 结果标「晚了 X 小时」, 不悄悄跳过。
- 到点碰到要审批的一步: 不跳过、不自动放行, 停在对方「等我点头」里, 任务标「等对方确认」, 发起人看得到卡在哪; 过截止按超时结束。
- 周期任务每期都点放行太烦: 只读结果可以选「这个任务以后的回复自动放行」; 对外 / 删除类每次问。
- 双方都能停: 发起人改 / 停 (改了对方重新同意); 对方随时退出。

## 3. 第三步 (待做): 多阶段

- 跨人的工作流: 串行 (甲做完交给乙)、并行后合并 (发起人的小鲶合成)、审核关卡 (发起人点头才进下一段)。
- **发起人电脑来协调**, 中央不存任何阶段的内容; 上一段结果先回到发起人、放行后才交给下一个人。
- 某段失败 / 被拒只重做那一段。接 `catfish_workflow`: 加「交给同事」这种步骤。

## 4. 不做 (第一步)

- 附件、图片。
- 中央 web 上看任务内容 (那就等于内容落中央)。
- 「主管强制指派」: 主管派给下属也由对方本人同意。
- 端到端加密: 跟填表一样靠「不透明 + 取走即清空 + 不记日志」, 客户要求时再加。
