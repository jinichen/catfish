# 鲶鱼 Memory · 员工使用手册

> **谁该看**：用鲶鱼的员工，想搞清楚"小鲶到底记了我什么、记在哪、能不能改"。
> **谁不用看**：开发者 / IT 看 `docs/MEMORY-OWNERSHIP-ARCHITECTURE.md` 那份系统文档。

---

## 1 · 一图看懂 4 套 memory

鲶鱼记你的事，**散在 4 个地方**，写入触发跟控制手段完全不同，别混了：

| # | 名字 | 文件位置 | 谁写 | 写入频率 | 大小 | 怎么管 |
|---|---|---|---|---|---|---|
| 1 | **hermes USER memory** | `~/.hermes/memories/USER.md` | LLM 在对话里显式调 `memory_update` tool | 一周 1-2 条 | ~1-7 KB | `hm` 脚本 |
| 2 | **hermes MEMORY memory** | `~/.hermes/memories/MEMORY.md` | 同上 | 一周 1-2 条 | ~1-7 KB | `hm` 脚本 |
| 3 | **小鲶印象 / journal** | `~/.catfish/employee_journal.md` | catfish-memory plugin 后台自动总结 | **每 30 分钟一次**（上限频率）| 几十 KB（会涨）| 仪表盘"清空印象"按钮 / 手编 .md |
| 4 | **distilled facts** | `~/.catfish/distilled_facts.md` | 同上，蒸馏 journal | **每 24 小时一次** | < 8 KB | 删 journal 后 24h 内自动重蒸 / 手动触发 |

仪表盘上的 3 个卡片分别对应：
- "我的 hermes memory" tile = #1 + #2
- "小鲶对你的印象" tile = #3
- "小鲶对你的画像" tile = 另一套 evidence-based fact DB（这份手册不细讲，仪表盘有"锁定 / 删掉"按钮，所见即所得）

## 2 · hermes memory（#1 + #2）

### 2.1 写入原则

LLM 自己判断，**只有它觉得"这事儿值得长期记"才调 `memory_update` tool**。没有后台自动写入。

经验上 LLM 倾向于把这些事写进去：

| target | 写什么 | 例 |
|---|---|---|
| `user` | 关于"你这个人"的稳定事实 — 偏好、习惯、关系、身份 | "用户喜欢简洁直接的回答，不要废话"<br>"终端用 HOMEbrew 类型，进 catfish 前要跑 /skin default" |
| `memory` | 项目、技术、操作事实 — 跨 session 的重要技术决策 | "客户内网 LLM 在 10.10.40.x"<br>"DeepSeek V4 Flash 是 284B/13B active" |

**LLM 不写**：临时讨论、单次决定、AI 自己说的话、闲聊。

### 2.2 字符上限

每条 entry 有 char 上限（不是总容量上限）：

| 文件 | 单 entry 上限 | 改在哪 |
|---|---|---|
| USER.md | 1375 chars | `~/.hermes/config.yaml` `memory.user_char_limit` |
| MEMORY.md | 2200 chars | `~/.hermes/config.yaml` `memory.memory_char_limit` |

仪表盘上 `82% of 1375` 这种百分比指的是**最大那条 entry** 占上限的比例，不是总量满了。你可以有 100 条 entry，每条 ≤ cap 就行。

### 2.3 怎么查看 + 删除

用 `hermes-memory-cleanup.py` 脚本，加个 alias 用起来最顺手：

```bash
# 一次性配置
echo "alias hm='python3 ~/person_task/catfish/scripts/hermes-memory-cleanup.py'" >> ~/.zshrc
source ~/.zshrc

# 日常用
hm                       # 列 USER + MEMORY 所有 entry, 含 char 数 + cap%
hm list USER             # 只列 USER
hm show USER 3           # 看 USER 第 3 条完整内容（preview 截断时用）
hm delete USER 3         # 删第 3 条（二次确认 + 自动备份）
hm delete USER 3 --yes   # 跳确认（脚本里用）
```

每次 delete 自动备份到 `~/.hermes/memories/USER.md.bak.<时间戳>`，脚本会 print 恢复命令。

### 2.4 怎么阻止 LLM 写

聊天时直接告诉小鲶 "**这事别记 hermes memory**"，模型一般会避开 `memory_update`。

如果 LLM 还是写了不想要的 → 用 `hm delete` 删了即可。

### 2.5 改写哪条 entry

```bash
# 直接编辑文件，文件就是 markdown + § 分隔
code ~/.hermes/memories/USER.md
# 改完保存
```

格式很简单：

```
第一条 entry 的内容...

§
第二条 entry 的内容...

§
第三条 entry...
```

注意 `§` 必须独占一行，前后各一空行（hermes ENTRY_DELIMITER = `\n§\n`）。

## 3 · 小鲶印象 / employee_journal（#3）

### 3.1 写入原则

`catfish-memory` plugin 在每次对话后**自动**总结（30 分钟节流）。prompt 让 LLM 抽：

- ✅ 关键决策、偏好、你做出的事
- ✅ 你的立场 / 输出
- ❌ AI 答了啥（不复述）
- ❌ 闲聊 / 问候（返空，不写）
- ≤ 200 字 / 段

### 3.2 文件长这样

```markdown
## 2026-05-24 09:30 · session `…ab12cd`

### 主题：DeepSeek V4 部署调研

总结内容...

## 2026-05-24 11:00 · session `…7f8e90`

### 主题：...
```

每个 `##` 段是一次总结。

### 3.3 为啥它能涨到 60 KB+

每天可能写 5-10 段，每段几百字。一周累积就 30 KB+，一个月 100 KB+。

**但磁盘大不等于注入 prompt 大**：每轮对话 hermes 只把 journal **最近 5 KB** 注入 prompt，不会全部塞进去。

### 3.4 控制手段

**直接清空**（最暴力）：仪表盘 "小鲶对你的印象" tile → 右下角 "清空印象" 按钮。

**手动编辑**（推荐每周做一次）：

```bash
open -t ~/.catfish/employee_journal.md
# 删不想留的 ## 段, 保存
```

**降低写入频率**：

```bash
# 改成 1 小时一次（默认 30 分钟）
export CATFISH_PLUGIN_SUMMARIZE_MIN_INTERVAL_SECONDS=3600
# 加到 ~/.zshrc 永久生效
```

**完全暂停**（如果代码支持）：env `CATFISH_PLUGIN_DISABLE_SUMMARIZE=1`（这个开关如果当前还没实现，可以提需求加）。

## 4 · Distilled facts（#4）

### 4.1 写入原则

每 24 小时一次，把整份 journal 喂给 LLM 蒸馏出 4 类核心事实：

- 人物
- 项目
- 偏好
- 决策

总长 ≤ 300 字，纯结论，不复述。

### 4.2 文件长这样

```markdown
<!-- Generated by catfish-memory plugin at 2026-05-24 04:00:00 -->
<!-- on_session_end 触发, 来源 catfish-memory plugin -->

## 人物
- 鸿波: ffcs sysadmin, 主开发
- ...

## 项目
- DeepSeek V4 部署调研
- ...

## 偏好
- ...

## 决策
- ...
```

### 4.3 控制手段

**立刻重蒸**（你删了 journal 某段，想立刻同步蒸馏出干净版）：

```bash
rm ~/.catfish/memory_distill_state.json
# 下一次聊天会触发重蒸（因为没 state 等于"从没跑过"）
```

**手编**：直接 `open -t ~/.catfish/distilled_facts.md` 改就行，下次蒸馏会覆盖。所以如果想保留某条事实别让蒸馏覆盖，比较麻烦 — 建议改对应的 journal 段比改 distilled 直接，因为 distilled 是衍生物。

## 5 · 一表速查（贴在显示器旁边那种）

| 想干啥 | 命令 / 操作 |
|---|---|
| 看 hermes 记的所有事 | `hm` |
| 看某条完整内容 | `hm show USER 3` |
| 删某条 hermes entry | `hm delete USER 3` |
| 看 hermes 备份 | `ls ~/.hermes/memories/*.bak.*` |
| 恢复 hermes 误删 | `cp ~/.hermes/memories/USER.md.bak.<时间戳> ~/.hermes/memories/USER.md` |
| 看小鲶印象（journal） | 仪表盘 "小鲶对你的印象" tile  |
| 清空小鲶印象 | 仪表盘 → "清空印象" 按钮 |
| 手编印象 | `open -t ~/.catfish/employee_journal.md` |
| 看 distilled facts | `cat ~/.catfish/distilled_facts.md` |
| 立刻重蒸 distilled | `rm ~/.catfish/memory_distill_state.json` + 随便聊一句 |
| 改 hermes 单 entry 上限 | `~/.hermes/config.yaml` → `memory.user_char_limit` / `memory_char_limit` |
| 让 journal 总结慢点 | `export CATFISH_PLUGIN_SUMMARIZE_MIN_INTERVAL_SECONDS=3600` |
| 让 LLM 不要记某事 | 聊天里说 "这事别记 hermes memory" |

## 6 · FAQ

**Q：仪表盘 "82% of 1375" 是不是快满了？**
A：不是。1375 是**单条** entry 的字符上限。82% 指最大那条 entry 占了上限的 82%，跟其他 entry 无关，跟总容量更无关。可以有 100 条 entry 各自 < 1375 字符。

**Q：employee_journal.md 60 KB 大不大？**
A：磁盘上 60 KB 没事，但只有最近 5 KB 注入 LLM prompt。建议每周扫一眼删掉不想留的段，不是因为容量，是因为**让小鲶看到的"你的最近"更精准**。

**Q：hermes memory 跟小鲶印象有啥区别？**
A：hermes memory 是 LLM **主动**判断"这事值得记"才写，频率低、内容精；小鲶印象是 catfish-memory plugin **后台**每 30 分钟自动总结，频率高、可能记到你没特别想留的东西。

**Q：删了 hermes entry 会不会让小鲶"忘了"我？**
A：会，**那条 entry 描述的事**小鲶就不知道了。但小鲶印象（journal）和小鲶画像（fact DB）是另外两套独立的，那俩里有同样的事就还在记忆里。如果你想"彻底忘"某事，3 套都要清。

**Q：小鲶画像怎么管？**
A：仪表盘 "小鲶对你的画像" tile 每项右边有 "锁定 / 删掉" 按钮，直接 UI 操作。锁定 = 以后不再 propose 修改这条。

**Q：我能让小鲶完全不记任何东西吗（隐私模式）？**
A：4 套全关：
  1. hermes memory：在 `~/.hermes/config.yaml` 改 `memory.user_char_limit: 0` + `memory_char_limit: 0`（或者干脆停用 memory plugin）
  2. journal：`export CATFISH_PLUGIN_DISABLE_SUMMARIZE=1`（如果支持；不支持就把 plugin 软链删掉）
  3. distilled：journal 关了它自然空
  4. 画像：仪表盘清掉

但**做完后小鲶就跟陌生人一样**，跨 session 不再"懂你"。建议不要全关，只 prune 你在意的事就行。

**Q：multi-tenant 场景（一台 mac 多个员工切账号）？**
A：当前所有 memory 都跟 `$HOME` 走，不跟员工 email 走。换账号 = 换 HOME = 换 memory。一台 mac 多账号同时跑会互踩。这是已知限制，需要的话提需求。
