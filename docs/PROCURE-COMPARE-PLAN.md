# 采购比价

2026-11-19。鸿波：「现在经济不好，客户对投资很谨慎，对投资产出的要求高……现在几个场景很弱。」选定先做采购比价，因为它能直接算出钱。

## 做了什么

一句话：小鲶读各家报价 → 统一口径 → 对照历史成交价 → 出比价表，并算出这一单能省多少钱。

| 环节 | 谁做 | 说明 |
|---|---|---|
| 读报价 | 小鲶（模型） | 邮件正文、附件 Excel / Word / PDF；每家抽出供应商、单价、单位、是否含税、交货期、付款条件、运费、有效期、来源。原文没写的字段留空，不编。 |
| 统一口径、排名、算差额 | `procure.py`（确定性代码） | 都换成「含税、每目标单位」，另计的运费加进到厂价，再按到厂价排名。单位能换的有吨、千克、克；换不了的不参与排名，单独列出。 |
| 对照历史 | `procure.py` | 取近 180 天这个品名的成交记录：上次成交、均价、最低价。 |
| 出表 | `procure_xlsx.py` | `~/.catfish/outputs/<日期>/比价-<品名>-<时分>.xlsx`，含「比价」「历史成交」两张表。 |
| 历史价从哪来 | `procure_import.py` / `procure_deal` | 导入现成的采购台账（按常见叫法认列名，重复导入不会记两遍）；以后每次成交，员工确认后记一笔。 |

## 接到小鲶上

- 作为 `catfish_customer` 的 `procure_compare / procure_deal / procure_history / procure_import` 四个动作挂上去，**不另起一个工具**。
- 原因：网关同时能给模型看的工具最多 49 个，已经全部用满。另起工具就只能藏起来靠模型自己搜，而 Qwen 这类模型找不到被点名但藏起来的工具。
- 工具说明压到了 520 字的上限以内；工具定义的总量上限上调了 200 字，原因写在 `test_tool_schema_budget.py` 里。

## 规则

- **只算价格，不拍板。** 质量、交期、账期、运费在表里列出，由采购员权衡。
- **不联系供应商。** 可以起草邮件，由员工自己发。
- **记成交要员工确认**（`confirmed=true`），因为记进去的就是以后的历史价。

### 什么时候提醒

| 情况 | 提醒内容 |
|---|---|
| 没写含不含税 | 按含税算，请核实 |
| 不含税 | 按 13% 换成含税 |
| 有效期已过 | 要重新确认 |
| 运费写法看不出金额 | 没加进到厂价，请核实 |
| 最低价比其余报价的中位数低 15% 以上 | 核实规格、质量，以及是否含运费 |
| 最低价仍比上次成交价高 3% 以上 | 可以拿上次价格去压价 |

## 验证（11/19）

- **单元测试**：`tests/test_procure.py` 共 19 个，覆盖口径换算、运费、排名、历史对照、提醒、导台账、Excel 内容。
- **真实模型（catfish-auto，qwen3.8-flash）走网关跑通全流程**，用的是 `docs/demo/procure/` 里的示例文件：
  - **抽取正确**：三份不同写法的报价都抽对了——乙的 5.55 元/公斤自己换成了每吨，丙没写含税就留空，运费、付款条件、有效期都对。
  - **结果正确**：比价结果是乙的到厂价最低（6,331.5），200 吨比最高价省 23,700 元；三家都高于上次成交价（6,214）。
  - **讲解到位**：模型给员工的讲解能点出「乙要款到发货」「甲贵 48.5 元/吨，换来 30 天账期」「丙如果不含税实际约 7,288」，并主动提出起草确认邮件，没有替员工发出。

## 月度汇总 (`procure_monthly`, 11/19)

鸿波「做月度汇总，算出每月省了多少」。只算**有据可查**的钱：一笔成交（`procure_deal` 记的）要能对上它之前 30 天内同品名的一次比价，才算「按比价成交」。

| 口径 | 怎么算 | 怎么用 |
|---|---|---|
| 比报价均价省（**主口径**） | (那次比价各家到厂价的平均 − 成交价) × 数量 | 保守，给老板看这个 |
| 比最高报价省 | (最高到厂价 − 成交价) × 数量 | 上限，只作参考 |
| 比上次成交 | (比价时的上次成交价 − 成交价) × 数量 | 行情涨跌，不算比价的功劳，单列 |

- 没填数量的成交只计笔数，不计金额（不猜数量）。
- 比了价但没记成交的，单独列出来让员工补记；不补记就不算钱。
- 导入的台账不算（那是以前的历史价）。
- 出月报 Excel：`采购比价月报-<YYYY-MM>.xlsx`。

## 小鲶自己搭（工作流积木，11/19）

鸿波问「每次新的能力都要这里实现代码？用小鲶自己能实现吗？」。比价和月报也做成了工作流积木（`procure_compare` / `procure_monthly`），员工一句话，小鲶就能自己把它们和查邮件、读邮件、「交给小鲶判断」、建任务这些积木串成定时工作流。

- 真模型实测：「每周一把上周的硅锰合金报价邮件找出来比价、出表、建任务提醒我」——小鲶自己查积木目录、起草了 9 步的工作流并通过校验，还自己加了「上周没报价就改建补询价任务」的分支。
- 实测暴露了一个问题：「判断」那一步按中文字段名（供应商 / 单价 / 含税与否）交回报价，比价积木只认英文字段名，真跑起来会在比价那一步失败。已改成两种都认。这说明：小鲶自己搭的时候，积木要对它的「随手写法」宽容。
