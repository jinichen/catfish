# 知识库类型定义（属性 / 状态 / 类型上的行动）

2026-11-07 起。本体四块：**类型、属性、关系、行动**。原来鲶鱼只有类型（`entity_type` / `concept_type`）和关系（`related`），证书的编号、发证机构、有效期都写在正文一句话里，小鲶只能全文搜再读字；行动只能一页一页手工关联，执行时拿不到参数。

现有六类：资质证书（`cert`）、软件产品 / 软著（`software`）、项目（`project`）、人（`person`）、部门（`department`）、组织（`org`）。别的类型照同一套加。

## 定义在哪

- 内置：`edge/contracts/wiki_type_schema.json`，随安装包发（edge-runtime 里的 `contracts/`）。
- 本机补充：`~/.catfish/wiki-type-schema.json`（一般用类型定义页改，不用手写），格式相同，只写要加 / 要改的部分：
  - 同名类型：属性按 `key` 合并，行动按 `id` 合并，`status` 按字段合并，其它字段覆盖；`hidden_properties` / `hidden_actions` 列着的内置项隐藏；
  - 新类型：直接写进 `types`（key 用条目的 `entity_type` / `concept_type` 值，中文细分类型按受控词表归一后也认，例「资质」→ `cert`）。
- 读写全在 tool-bridge `wiki_types.py`；Companion（`commands/wiki_types.rs`）只转发，再给行动标上本机技能装没装。

## 在界面上改（类型定义页）

知识体系 → 关系整理 → 搜索框旁「类型定义」（旁边原来叫「类型」的按钮管关系类型，改叫「关系」）：

- 左边是各类型，右边改这一类：类型名、到期前多少天提醒、属性（名字 / 文本或日期 / 说明）、行动（名字 / 要做的事 / 可选技能）。
- 「要做的事」里可以写 `{属性名}`（例 `{有效期至}`），点「插入属性」也行，执行时换成这条知识的属性值；没填的换成「（未填）」。
- 内置的属性和行动能改名、改说明、隐藏 / 恢复，不能删；自己加的随便删。新建类型从知识库里已有的细分类型里选（列出条数），自建类型可以删，已写进知识的属性不删。
- 改的是本机补充文件 `~/.catfish/wiki-type-schema.json`（每次改前旧文件备份成 `.bak`），换机迁移会带走；内置定义不动。
- 后端 `wiki_type_defs.py`：`view()` 给合并后的定义（每项标内置 / 我加的 / 内置改过、是否隐藏），`apply({op, …})` 一次改一处并校验。

## 一个类型里有什么

| 字段 | 意思 |
|---|---|
| `label` | 界面上的名字（资质证书） |
| `properties` | 属性：`key`、`label`、`type`（`text` / `date`）、可选 `hint`、`pattern`、`keywords`、`aliases`、`max_len`（文本默认 60 字，超了不当值） |
| `status` | 自动算的状态：`from` 哪个日期属性、`warn_days` 提前多少天算「即将到期」；可选 `done_when`（某属性是这些值时算「已结束」，不再按日期算，例 项目阶段=已结束） |
| `relations` | 这一类常用的关系（目前是说明，还不拦截） |
| `actions` | 这一类都有的行动：`id`、`label`、`description`、可选 `skill_path`、`instruction`（`{属性key}` 或 `{属性名}` 会换成属性值） |

### 属性存在哪

扁平字段写进条目文件头，例 `cert_no: "CCRC-2019-ISV-SD-210"`。改属性只动这几行，正文一个字节都不动（`wiki_types.set_props_file` 直接写文件，不走会重排文件头的 `update_wiki_file`）。

### 从正文抽属性（「整理属性」）

知识体系 → 关系整理 → 搜索框旁「属性」：

1. 先按每个属性的 `pattern`（正则，第 1 组是值）抽，秒出、不花 token。
2. 句式抽不到、但正文出现 `keywords` 或属性名本身（「有效期」「发证机构」…）的条目，可以点「让小鲶读正文补」：每 8 条一批请模型摘值。模型给的值必须原样出现在正文里（日期允许换写法），否则丢掉。
3. 都过一道过滤：正文说「待核 / 疑似误录 / 未录入 / 占位」的不当值；日期必须是真日期（「无限期」不算）；`aliases` 把同一个值的不同写法归一（等级「无等级」→「无」）。
4. 只给建议：表里每个值都能改，勾上的才写；写之前每个文件整份备份到 `~/.catfish/wiki/.props-backups/<时间>/`。

11/07 在鸿波机器 80 条证书上实测：固定句式给出 69 条的建议（有效期 62、编号 56、发证机构 57…），小鲶再补认证范围等十来项，一次全量二十秒左右。

### 类型上的行动

知识页属性卡片下面列出这一类都有的行动，点「交给小鲶」：切到工作台开新对话，属性和「要做的事」（`instruction`，属性已填进去）一起带过去。要技能的（`skill_path`）本机没装就灰掉；不要技能的（例「到期提醒」用 `catfish_create_reminder`）总是可用。登录、提交、发送这类对外操作小鲶照常先问。

证书现有两个：

- **官网核查**：技能 `personal/renzheng-gongshi-website-verify`（鸿波本机自己的技能，别的员工机上没有会灰掉），核对编号、状态、有效期、等级、认证范围，不一致的先给员工看，同意后用 `catfish_wiki_update` 的 `props` 改属性。
- **到期提醒**：有效期至前 180 天提醒准备续期；有复审日期的也提前 180 天提醒；建之前先让员工确认。

### 软件产品（software）

就是软件著作权登记：登记号、版本、登记日期、著作权人（归属单位）、产品方向、维护人。细分类型写「软件产品」「软件」「软著」的都归成 `software`（受控词表 11/07 加的）。鸿波机器 61 条（52 条「软件产品」+ 9 条 `software`）按固定句式全部抽到登记号，登记日期 40、版本 36。

行动：**版权登记核对**（到中国版权保护中心按登记号查，核对名称 / 版本 / 日期 / 著作权人）、**整理投标用产品说明**（软著信息 + 用过的项目和客户，每条注明出处）。都不要技能，小鲶用自带工具做。

### 项目（project）

客户、负责人、承建部门、合同金额、阶段、开始日期、截止日期。状态叫「进度」：截止前 30 天算「临近截止」，阶段是「已结束 / 运维」算「已结束」。

现有 67 条项目知识的正文里很少写这些（实测只有 6 条抽到东西），属性主要靠以后边用边补：在证书页一样的属性卡片上直接改，或者「进展汇总」发现新信息后由小鲶问过员工再写。

行动：**进展汇总**（邮件、会议纪要、知识库里的最新进展，分当前阶段 / 最近动态 / 待办和风险）、**截止提醒**（截止前 30 天）。

### 人（person）/ 部门（department）/ 组织（org）

- **人**：部门、职务、邮箱、电话、负责事项、个人证书。行动：往来汇总（最近和他有关的邮件、会议、知识库）、起草邮件（只存草稿）。正文多是零散一句，邮箱靠「邮箱：xxx」句式，其余靠小鲶读，实测 50 条里十来条能补到部门 / 邮箱。
- **部门**：全称、所属体系、层级、上级部门、下辖、负责人、职责。按组织架构的句式（「福富生产运营体系一级部。全称…。下辖…」）抽，实测 65 条里 35 条拿到体系和层级、22 条拿到下辖。行动：部门概况（上下级 + 负责的项目 / 软著 / 人员，用 catfish_wiki_query 跨类型查）、近期动态。
- **组织**：跟我们的关系（本公司 / 上级单位 / 兄弟单位 / 客户 / 合作伙伴 / 供应商 / 发证机构 / 竞争对手）、全称、统一社会信用代码、成立时间、注册资本、地址、官网、联系人。正文很少写，实测 50 条只有几条能补。行动：往来汇总、公开信息核对（官网 / 国家企业信用信息公示系统）。

知识里有些条目类型标错了（例「中电福富人员与邮箱对照」标成了人、「王某某」这类示例人名），整理属性时不勾就行。

单页手工关联的行动（`action_refs`，见 `CATFISH-WIKI-ACTIONS.md`）保留，当个别条目的补充。

## 小鲶怎么用

- `catfish_wiki_read`：有类型定义的条目返参多一个 `type_info`（属性、状态、这一类能做的事）。
- `catfish_wiki_query`：按类型 + 属性查，例 `{type: "cert", where: [{field: "valid_until", before: "2027-06-30"}], sort: "valid_until"}`、`{type: "cert", status: "即将到期"}`、`{type: "cert", where: [{field: "valid_until", empty: true}]}`（找没填的）。
- `catfish_wiki_update` 只给 `rel_path` + `props`：只改属性，不用整篇覆写。

## 11/08 整改: 小鲶真能找到、写进去有人把关、本体填实

鸿波 11/08 让我把「小鲶基于本体的知识库还有什么要优化」仔细看一遍 (659 条实体 / 概念, 134 份原件, 实测 + 读代码), 一次改完三批:

**检索 (小鲶在对话里用的那条路)**
- 分词 bug: 「证书编号ZTY2026…，」编号后面紧跟中文标点被粘进词里, 搜编号永远对不上 (262/659 条正文有这种写法); tool-bridge 与网关同一份修掉。
- `catfish_wiki_search` 重写成跟界面同一套: BM25 (标题 / 别名 / 标签 / 属性值 / 关系对象名 / 全文) + 向量 (问题的向量借 Companion
  的 embed_socket 算, 跟 Companion 建好的分块向量算余弦, 门槛同 Rust) + RRF 融合 + 顺着 related 扩一跳 (出边入边都从 frontmatter 算)。
  已过期 / 已结束、待确认的默认不列 (summary 说有几条, `include_expired` / `include_pending`); 上传的原件 (wiki/raw/sources) 也进索引,
  默认不列 (`include_sources`)。结果每条带类型、已填属性、状态、关系数、最相关的一段。`wiki_search.py`。
- `catfish_wiki_query` 先全部排好序再截 limit (原来是字母序前 15 条再排); 没填的排最后; 装机部门页也算; 废弃 / 驳回的不算。
- 部门共享页 (wiki-shared/dept/…) 能读; 装机、发布、搜索、读取同一个根目录 (CATFISH_HOME)。

**写入把关 (`wiki_guard.py` / `wiki_write_tools.py`)**
- 任何写入 (整页覆写、改属性、记忆口径挪进来) 先备份到 `wiki/.history/<页>/<时间>.md` (每页留 20 份, `catfish_wiki_history` 可查), `updated` 换成今天。
- `catfish_wiki_update` 带 `base_mtime` (从 read 拿): 这一页在读过之后被别人改过就不覆写, 把现在的内容交回去合并。
- 建页先查相似名 (去掉公司后缀 / 标点 / 大小写 / 全角后一样: 「云堤」vs「云堤公司」) → 拦下并指向那一条; 确认不同才 `allow_similar=true`。
- 关系按类型定义校验: 两头都有类型定义的, rel 必须在定义里 (src 的 `to` 或 dst 的 `from`); 词表外 / 自定义 / 「关联」不管。
  内置定义按鸿波机器上 425 条已有关系补齐过 (software 隶属 org、person 维护 cert …), 剩下拦的 12 条都是真写错的 (证书隶属项目、公司遵循项目)。
  引用了不存在的页 → 写进去但点名说缺哪一页; 待确认原因换成人话。
- 发布到部门扫到敏感内容: 只认界面上点的确认 (Companion 走 tools/dispatch 带 `_from_ui`, MCP 那条路剥掉这个键);
  小鲶自己带 `acknowledge_warnings` 不算, 对话里出「我看过了, 确认发布到部门」按钮 (`ChatWikiPublish.tsx`)。
- 记忆整理挪进知识库: 名字撞上的只能是概念页才追加 (口径不糊进公司页); 记忆那步失败就把知识库那页退回去。
- wiki-hub 信任 `X-Catfish-User-*` 头: 核过了 —— 端口只绑 127.0.0.1, 网关反代把客户端自带的身份头全部丢掉, 不是漏洞, 没改。

**本体填实**
- 新建条目按类型定义直接填属性: `catfish_wiki_create` 的 `props` + 正文按固定句式抽到的 (证书编号 / 有效期 …) 自动写进文件头。
- 「整理属性」让小鲶读正文时, 连上传的原件里提到它的段落一起看 (`wiki_sources.snippets_about`: 花名册 / 组织架构 / 项目台账 / 周报),
  摘出来的值照样必须原样出现在给它看的文字里。
- 词表外的 55 种细分类型能归的归进来 (`contracts/wiki_type_vocab.json` aliases: 软件平台 → software, 事业部 → department, 政府机构 → org …),
  读的时候归一, 不改条目文件。新加「文件资料」类型 `doc` (文号 / 发文单位 / 发布日期 / 类别 / 适用范围, 行动「要点摘要」):
  资料要点 / 政策文件 / 制度文件 / 汇报材料 / 法规 … 都归它。
- 金标问题集 `scripts/wiki_gold_eval.py`: `--init` 从现有知识库各类型抽几条生成起手的 `~/.catfish/wiki_gold.json`, 跑的是小鲶那条搜索路,
  打印命中率和没命中的; `--json` 存进 `~/.catfish/wiki_health/` 做趋势, `--min-rate` 发版前把关。结构体检 `wiki_health.py --json` 也存同一目录。
