# 对话里做通 → 固化成技能（11/19 真走一遍）

鸿波：「在工作台里把 Excel、Word、聊天记录拖进小鲶对话里，告诉他做什么任务……验证可以了，固化成技能，不要再去折腾这么复杂。」

结论：**这条路是通的，具体场景不用我们写代码。** 平台只补底座。

## 怎么测的

- **入口**：用员工本机真实的小鲶（`hermes chat -q`，同一套工具、技能和配置）。
- **场景**：应收账款账龄 + 催款清单。没有为它写过任何代码；数据是虚构的示例明细（11 月、12 月各一份）。
- **对答案**：我另外写了一段程序独立算出正确结果，逐项对照小鲶的输出。

| 步骤 | 结果 |
|---|---|
| 1. 拖文件、一句话说要求 | 小鲶写代码算、出 3 张表的 Excel。总余额 2,878,500、逾期 2,577,500、五档金额全对 |
| 2. 「数都对，固化成技能」 | 第一次失败：模型把 1.5 万字的程序重打进工具参数，一轮 2–5 分钟，最后参数名写错，只存下空壳。第二次成功：先把程序写成文件、用 11 月数据自测、自造畸形数据测出一个真 bug（已收 > 发票时勾稽对不平），改好后再装，用时约 6 分钟 |
| 3. 下个月新对话：「12 月明细来了，出账龄」 | 自动用上技能，跑存好的程序，86 秒出结果，数全对（3,046,500 / 2,319,000），还主动做了环比 |
| 4. 加需求「按客户汇总开票和已收」→ 固化 | 并进已有技能，约 4.5 分钟，旧功能回归测过 |
| 5. 全新场景「采购台账按供应商汇总」→ 固化 | 新建技能，约 7 分钟，自造了十几种畸形表测过 |

## 断的地方和处理

1. **`catfish_propose_skill` → `catfish_install_proposal` 装出来的技能是空壳**：程序只有步骤注释，一跑就报「未实现」。
   - 已修（`skill_from_code.py`）：hermes 插件钩子把会话号带给提议，提议时从会话里取最后跑通、存了文件的那段代码，原样存进技能。输入文件的绝对路径和截至日期识别成参数，产出目录换成运行当天的目录。
   - 运行时只换参数、在子进程里跑同一段代码，并且先过 execute_code 那套安全检查。
2. **模型重打程序又慢又容易丢**：这是模型自己做法的问题。它多数时候会「先写文件再装」，这样是成功的。
   - 试过把 skill_manage 的「新建」拦下、改走 catfish 那条，没拦到：它是写好文件再运行文件，运行的代码里看不到「存文件」那一行。
   - 结论是不跟模型较劲，这个拦截已经撤掉。
3. **固化本身要 4–7 分钟**：因为模型会自测边界情况。只在固化时花一次，以后每月 1–2 分钟。暂时接受。

## 不是问题的

- **桌面端看不看得到**：小鲶用 hermes 自带方式装的技能，桌面端技能页能看到（读的是 `~/.hermes/skills`）。
- **删除被拦**：「删除被拦（定时 / 无人值守不执行删除）」只出现在测试用的非交互命令行里，员工在桌面端对话时会当面确认。

## 测试留下的东西（在员工真实环境里）

- 两个技能：`ar-aging-collection-report`、`purchase-ledger-supplier-summary`。按虚构数据做的，但写法通用，可以当演示用。
- 6 个产出文件，在 `~/.catfish/outputs/2026-11-19` 和 `2026-12-19` 两个目录里。
- 小鲶在 `MEMORY.md` 里记了一条这次测试的事；日志（只追加）里也有记录。
