## 1. "跟 ChatGPT / 通义千问 / Claude 比, 你们什么不同?"

**核心一句**: 它们是聊天工具, 鲶鱼是工作流副手 + 企业基础设施. 不是同物种.

**展开**:
> ChatGPT / 通义这种是**通用聊天**工具. 员工提问它答, 一来一回. 但你们公司员工 80% 时间不是在"聊天" — 在切系统、找数据、套模板、写汇报. 鲶鱼是给这些**端到端工作流**做自动化的.
>
> 第二个不同: **数据流**. ChatGPT 类的对话内容全上传厂商服务器. 鲶鱼对话**全程在员工本机**, 中央 gateway 只看 metadata (token 数 / 模型 / 时长), 看不到内容.
>
> 第三: **跨厂商 LLM**. ChatGPT 锁定 OpenAI, 通义锁定阿里. 鲶鱼是 LLM 中台, qwen / gemini / claude / 你们自己私有模型任意切换. 主力慢了自动 fallback, 你们 LLM 出问题不影响业务.

## 2. "数据安全怎么保证?"

**核心一句**: 三层架构 + 凭据完全本地 + 中央可审 metadata. 设计阶段就是合规, 不是后补的.

**展开**:
> 我们有 3 层数据保护:
>
> **第一层: 边缘**. Companion + tool-bridge 在员工本机. 对话内容、工具调用历史、memory 全都在 `~/.catfish/` 和 `~/.hermes/`, 永远不出员工电脑. 你们 IT 可以扫盘验证.
>
> **第二层: 凭据隔离**. 员工密码、API key、token 走 secret_ref 机制, 存 macOS Keychain (跨平台 Win Credential Manager / Linux Secret Service). 调用工具时**真值在 tool-bridge 落地一刻才解析**, 永远不进 LLM 上下文. 我们 prompt 里还有 regex 检测, 员工不小心写明文密码会自动 audit 标记 + 提醒改 ref.
>
> **第三层: 中央审计**. gateway 写 JSONL audit 文件, 字段是 user / model / token 数 / TTFT / status / security_concern, **没有对话内容字段** — 这是代码层面写死的, 客户 IT 可以审计代码确认.
>
> 离线 / VPN 断网时鲶鱼进入"只读模式" — 能看历史不能调 LLM, 防员工离职后 token 还能用.

**演示时引用**: Slide 6 (架构图标记本地 vs 中央边界) + Slide 10 (AuditCard 看 metadata 没内容) + Slide 16 (数据流对比表)

## 4. "跨厂商 LLM 接入难度?"

**核心一句**: 1 周接一个新厂商. gateway 是 LiteLLM 标准协议, 改 yaml 配置即可.

**展开**:
> gateway 用 LiteLLM 库做底层 SDK, 它支持 100+ 厂商 (OpenAI / Anthropic / Google / 阿里 / 智谱 / 百川 / 月之暗面 / 你们私有 OpenAI-compatible 等).
>
> 接新厂商 3 步:
> 1. `models.yaml` 加一段配置 (issuer / api_key_env / 模型名)
> 2. `.env` 配 API key
> 3. fallback 链里加进去做容灾
>
> 我们现在就支持 6 个: 你们私有 qwen 主力 + qwen-vision + qwen-flash 公网 + gemini-pro + gemini-flash. 你们要加文心 / 通义其他模型 / 自己 fine-tune 的, **我们 1 周内接好**.

## 5. "成本 / 商业条款?"

**核心一句**: 私有化部署, 一次性 license + 年度维护. 不抽 API token 流水.

**展开**:
> 跟 SaaS 不一样, 我们**不按员工用得多收费**:
>
> - **私有化部署** (你们自己机房 + 你们自己 LLM)
> - **一次性 license** (按部署规模, 50-200 人 SMB X 万, 1000+ 集团单独谈)
> - **年度维护** (升级 / bug 修复 / 新功能, 大约 license 的 15-20%)
> - **不抽 API 流水**: 员工调 LLM 多少都不收 token 费, 你们用自己 LLM (内网 qwen / 集团采购的厂商额度), 钱付给厂商不付给我们
> - **客户 IT 自审**: 中央 audit / 配置 / 身份系统全部代码可审, 没有黑盒
>
> 这是个**装得久越值钱**的商业模式. 你们部门 50 人用 1 年 vs 5 年, 我们成本一样, 但你们 ROI 5 倍. 我们靠**续约 + 推广到其他部门**赚钱, 不靠卡员工 token.

**演示时引用**: Slide 20 (商业模式) + 比较 SaaS 模式 (Slide 16 的"抽流水" 行)

## 6. "跟星辰 / TeleAI 内部产品什么不同?"

**核心一句**: 星辰是中国电信内部桌面 Agent, 鲶鱼是企业级三层架构 + 跨厂商. 角度不一样.

**展开**:
> 星辰是 TeleAI 团队做的产品, 模式上是 Anthropic Agent SDK + 桌面客户端 (类似 Claude Code 的桌面版). 它是**单层 Agent**, 用户 → 主控 LLM → 工具.
>
> 鲶鱼是**三层架构**:
> - Companion (边缘客户端)
> - tool-bridge (工具隔离 + 凭据安全)
> - **central gateway** (LLM 路由 + 审计 + fallback) — **这是星辰没有的**
> - identity 层 (SOUL / USER / MEMORY 完全本地)
>
> 区别在哪:
> - 星辰锁 GLM-5 一个模型, 鲶鱼跨厂商任意切
> - 星辰是单租户单层, 鲶鱼有中央 gateway 多用户多模型路由
> - 星辰的 skill 是通用 (deep-research / news), 鲶鱼是业务流程 (报销 / 资质 / 汇报)
> - 星辰我们没看到跨员工协作设计, 鲶鱼 Phase 3 ship Catfish Federation
>
> **我们不打算跟星辰竞争 TeleAI 内部市场**. 我们目标是星辰够不到的: 外部企业 / 央国企部门 / 其他需要私有化的客户.

**演示时引用**: Slide 14-15 (锁层差架构对比) + 必要时翻 docs/COMPARE-1PAGER.md

## 8. "Win 跨平台支持?"

**核心一句**: Mac 现在 ship, Win Q3 2026 (Phase 2). 因为我们专心打透 Mac 一个平台先.

**展开**:
> 我们决策上**Phase 1 只打 Mac**, 原因:
> - 一个平台打透比两个平台都半成品强
> - macOS Keychain / Tauri / Playwright 这套技术栈 Win 都有对应实现, 不是技术难
> - 主要工作量在测试 + Win 特有问题 (Credential Manager API / Edge 自动化 / 路径分隔符)
>
> **Phase 2 (Q3 2026)** 完整支持 Win:
> - Tauri 跨平台 (代码大部分共用)
> - Credential Manager 替 Keychain
> - Edge / Chrome 都支持
> - Win-specific install 脚本
>
> 如果你们部门**100% Mac** (开发 / 设计 / 高管常见), 我们立即开干. 如果**80% Win**, 建议等 Q3 再 PoC 不浪费时间.

## 9. "员工不愿意用 / 学习成本高怎么办?"

**核心一句**: 鲶鱼是"沿着员工现有工作流加层", 不是"逼员工换工作方式".

**展开**:
> 我们设计哲学是"**让员工继续用熟悉的系统**, 鲶鱼在背后帮你"——
>
> - 员工还是用原来的 EIS / OA / 飞书 — 鲶鱼**不替代**它们
> - 员工还是用浏览器 — 鲶鱼**不要**员工装新软件 (除了 Companion)
> - 员工跟鲶鱼对话用大白话, 不学 prompt engineering
> - skill 是从员工**实际操作**里**自动学习** (做 ≥ 3 次同样流程鲶鱼建议沉淀)
>
> 培训成本: 半小时 — 给 1 个 demo + 5 分钟自己摸索. 我们驻场培训 1 天就够.
>
> 员工"不愿意用" 90% 是**没看到价值**. 你们让 1 个员工用 1 周, 它把"周报、汇报、报销"3 件事自动化了, 这个员工就是种子用户, 同事看完自己来要装.

## 10. "AI 答错怎么办? LLM 幻觉问题?"

**核心一句**: 我们设计**审计 + 容错** 而不是追求"100% 准确". 关键决策永远员工 review.

**展开**:
> LLM 幻觉是**物理限制**, 不是 prompt 调优能根除的. 我们的策略:
>
> 1. **关键决策员工 review**: 鲶鱼写邮件草稿 → **员工本人**按发送. 鲶鱼起草报销 → **员工本人**点提交. 鲶鱼建议数据导出 → 给员工 CSV 让员工查
> 2. **数据统计强制 execute_code**: 我们 gateway 自动检测员工"统计 / 多少 / 合计"等关键词, 强制注入"必须用 Python 代码算"提醒, 不让 LLM 自己数 (那必错)
> 3. **审计可追溯**: 任何 LLM 调用都进 audit log, 你们 IT 能查"哪个员工哪次调用错在哪"
> 4. **fallback 链**: 主力 LLM 答错 / 超时, 自动切公网模型重试. 容错不是事故掩盖, 是设计目标
>
> 我们承诺: **关键写入 / 发送 / 决策类操作, 鲶鱼不替员工拍板**. 这是产品红线.

**演示时引用**: Slide 8 (邮件 demo, 强调员工本人按发送) + Slide 10 (audit 仪表盘可追溯)

## 12. "如果你们公司挂了 / 你不做了, 我们怎么办?"

**核心一句**: 鲶鱼大部分是**开源 / 可审代码**, 客户能继续维护. 我们死了你们不死.

**展开**:
> 这个问题很好, 客户都该问 (尤其国央企做长期采购).
>
> 我们的设计原则: **客户不能被锁死在我们身上**.
>
> - **catfish-identity 自建 OIDC**: ~600 行 Python 客户 IT 可审 + 可改
> - **gateway / tool-bridge / Companion**: 标准 fastapi + Tauri Rust + React, 没用任何专有协议. 客户工程师拿到代码能继续开发
> - **核心组件 Phase 2 开源**: catfish-identity / SOUL.md 框架 / 部分 skill 库我们计划 Phase 2 开源 (具体范围合同里写)
> - **数据格式标准**: audit 是 JSONL, memory 是 markdown, skill 是 SKILL.md frontmatter, 全是开放格式. 我们死了客户能拿 grep 自己处理
> - **LLM 不是我们的**: 你们用自己 LLM, 我们死了你们 LLM 还在
>
> 真正的"绑死"是**SaaS 服务挂了你的数据全没**. 我们私有化部署, 数据全在你们机房, 你们随时能 fork.

**演示时引用**: 没专门 slide, 但客户问到这个问题说明感兴趣 — 你认真展开讲

## 总原则

- **诚实 > 营销**. 客户 IT 比你想象的懂技术, 吹牛被识破信任全没
- **具体 > 抽象**. 别说"我们很安全", 说"我们有 3 层数据保护, 这是代码"
- **承认局限 > 假装全能**. "Phase 2 才有" 比 "有但不太好用" 强 100 倍
- **demo 现场 > PPT 美**. 真实用 1 次 > 漂亮 PPT 10 张
