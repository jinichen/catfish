## 🎯 日常刚需型（高优 · 员工天天用）

### 1. 鲶鱼晨报（Daily Brief）
> 每天早 9 点自动推送"今天需要关注的 3 件事"。扫昨晚邮件 + Jira 更新 + 代码 PR，用员工自己的语气摘要。

- **好玩在哪**：不是新闻简报，是"**你自己的工作摘要**" — agent 懂你的项目
- **难度**：中（需 email agent + Jira/GitLab 连接器 + cron + 通知）
- **估时**：1–2 周
- **前置**：Email Agent + 1 个 MCP 连接器（Jira 或 GitLab）
- **Week**：P1 后期

### 2. 对话式回顾周报
> 周五下午鲶鱼主动问你"这周做了啥？遇到什么坑？"。你随口说，它整理成正式周报发给上级。

- **好玩在哪**：把**最讨厌的事**（写周报）变成**最省力的事**（聊聊天）
- **难度**：低（单 skill，靠 memory 拉数据）
- **估时**：3–5 天
- **前置**：Memory 体检通过 + Skill 系统稳定
- **Week**：P1 早期

### 3. 会议纪要机器人
> 开会时在 Companion 里点"开始记录"，语音转写 + 会后自动生成纪要（谁说了什么、共识、待办、action item）。

- **好玩在哪**：解放**所有会议记录员** — 刚需 + 高频 + 价值可量化
- **难度**：中高（需实时语音转写 + 发言人识别）
- **估时**：2–3 周
- **前置**：Companion App v1 + 接入公司 STT / Whisper
- **Week**：P2 早期

### 4. 哄客户草稿生成器
> 员工收到客户投诉邮件，选中邮件内容，Companion 给出**三种回复风格**（专业冷静 / 共情安抚 / 义正辞严）。

- **好玩在哪**：销售/客服**每天都在为措辞纠结**，真痛点
- **难度**：低（单 skill + Companion 浮窗多选项）
- **估时**：3–5 天
- **前置**：Companion App v1 + Email Agent
- **Week**：P1 后期

### 5. 选中即翻译
> 任何地方选一段文字，按 `Cmd+Shift+T`，Companion 浮窗直接出翻译。**不是逐字**，是**员工母语的自然表达**。

- **好玩在哪**：Google 翻译几十年了还是直译，鲶鱼能"翻译得像你会说的话"
- **难度**：低
- **估时**：1–2 天
- **前置**：Companion App v1
- **Week**：Companion 上线同期

## 🔧 工作流自动化型（中优 · 特定场景爆发）

### 6. 内部系统懒人代理
> "帮我报销昨天打车去客户公司的 150 块" → agent 自动打开 OA，填表，上传滴滴发票（从支付宝扒），提交给主管审批。

- **好玩在哪**：员工对 OA 的恨意 = 这是最大泄洪口
- **难度**：高（每个 OA 系统都要特殊处理）
- **估时**：每个流程 1–2 周
- **前置**：Browser Agent 成熟 + 公司 OA MCP 连接器
- **Week**：P2 中期

### 7. 代码改完自动更新相关文档
> 研发 commit 后，cron 检测到，读 diff + 相关文档，提醒："你改了 X，README 里描述的 Y 过期了，我帮你改好草稿了，去 Drafts 看下"。

- **好玩在哪**：**文档滞后**是技术债大头，agent 当守卫
- **难度**：中（需 git hook + 文档定位 + diff 理解）
- **估时**：1 周
- **前置**：GitLab MCP 连接器 + 仓库上下文理解
- **Week**：P2

### 8. 鲶鱼的"学习清单"
> 员工每次问的问题被 memory 记下来。月底鲶鱼主动说："你这个月问了 8 次 SQL 语法，推荐 2 小时速成教程"。

- **好玩在哪**：从"帮你解答"升级到"**发现你的成长机会**"
- **难度**：中（需 session search + 主题分类 + 推荐算法）
- **估时**：1 周
- **前置**：Memory 稳定 + FTS5 搜索工作
- **Week**：P1 后期

### 9. "今天不想跟人说话"模式
> 一键启用："所有人 @ 我都先过鲶鱼，鲶鱼能回答的自动回，需要我的标记优先级"。

- **好玩在哪**：专注工作时的"**手动挡过滤器**"
- **难度**：中（需 IM 适配器，飞书/企业微信）
- **估时**：1–2 周/平台
- **前置**：企业 IM 适配器上线
- **Week**：P3（IM 入口上线后）

## 💬 人机关系型（高价值 · 长期复利）

### 10. agent 的命名权给员工
> 每个员工的 agent 可以起名字（"小雷"、"老李"、"阿呆"），选 personality，改头像。

- **好玩在哪**：心理所有权 = 员工愿意**教它事情** — 这是自进化的燃料
- **难度**：低（personality 系统已有）
- **估时**：1 天（加 personalization UI）
- **前置**：无
- **Week**：任何时候，做了立刻有效

### 11. 鲶鱼周末不干活
> 周末、节假日、晚上 10 点后，鲶鱼自动说"老板下班了，明天再帮你"。

- **好玩在哪**：最反直觉的功能，但**最有文化价值**。企业默许 agent 是员工工会
- **难度**：极低（一个 cron + 一个 prompt 开关）
- **估时**：半天
- **前置**：无
- **Week**：任何时候
- **注意**：需要公司文化真的支持。**不是所有公司能接受**

### 12. 鲶鱼能主动"闲聊"
> 周五下午员工闲下来，鲶鱼主动发："你上周那个报销审批了没？" — **没 cron、没人触发**，agent 自己判断

- **好玩在哪**：从**被动响应**到**主动陪伴**
- **难度**：中（需要"何时应该说话"的判断逻辑 — 不能打扰专注）
- **估时**：1–2 周
- **前置**：Memory 稳定 + 员工"专注/空闲"状态推断
- **Week**：P1 晚期

## 🎪 纯娱乐/毒舌型（团建向）

### 13. 鲶鱼吐槽你的 PPT
> 上传 PPT，鲶鱼点评："这张字太多了"、"这配色让我眼睛疼"、"你真的懂你在讲什么吗" — **毒舌模式**

- **好玩在哪**：员工乐意用 = 自然扩散
- **难度**：低（PPTX parser + 专门的 critical personality）
- **估时**：3–5 天
- **前置**：Companion App 或 CLI
- **Week**：P2（"有趣"分量的功能）

### 14. "领导来了"快捷键
> 员工按某个键，屏幕瞬间切换成"认真写代码"的假象

- **好玩在哪**：纯搞笑，但会成为员工之间的梗
- **难度**：低
- **估时**：1 天
- **前置**：Companion App
- **Week**：任何时候（彩蛋功能）

### 15. 社交健康检查
> 鲶鱼扫 Slack 聊天记录（员工授权），告诉你："最近一个月里 @ 你的 23 条里，17 条是找你要东西，6 条是表扬，0 条是闲聊"

- **好玩在哪**：提醒人际健康 — 可能是**意想不到的洞察**
- **难度**：中（需要情感分析 + 意图分类）
- **估时**：1–2 周
- **前置**：Slack/IM 适配器 + 员工明确授权
- **Week**：P3
- **注意**：**边界要非常谨慎**，稍有不慎就像监视

## 🌐 组织协作型（P3+ · 长期愿景）

### 16. 两个鲶鱼对话（Agent-to-Agent）
> 员工 A 的 agent × 员工 B 的 agent，跨人协作时 agent 先"碰头"
> A 问 B："你老板对 XX 项目怎么看？"
> B 根据公开偏好回答

- **好玩在哪**：组织沟通被压缩成几秒
- **难度**：高（需 agent 间通信协议 + 隐私边界设计）
- **估时**：1–2 个月
- **前置**：所有员工都有自己的 agent + 隐私控制成熟
- **Week**：P3 远期
- **注意**：**隐私边界要极谨慎**。A 的 agent 不能说出 A 没明确授权的事

- **难度**：中（IM 本地缓存解析）

## 🧬 外部参考：Evolver / EvoMap（2026-04-23 记录）

**项目**：[github.com/EvoMap/evolver](https://github.com/EvoMap/evolver)
**一句话**：基于 GEP（Genome Evolution Protocol）的 agent 自进化引擎

### 可以借鉴的三个概念

- **GEP 协议化的进化资产** — skill 不是自由文本，是结构化的 Gene/Capsule + events.jsonl 审计日志。对我们 Skills Hub 的治理和软著合规很有用。
- **策略预设** — balanced / innovate / harden / repair-only 四种模式。可以做成鲶鱼的"今天模式"一键切换（探索 / 稳健 / 修复）。
- **Validator 角色** — 每个 agent 默认参与网络验证。我们的 Skills Hub 审核可以做成"员工的鲶鱼晚上空闲帮别人验证"，分布式、自动化。

### 不要学的三件事

- 中心化 Hub（evomap.ai 云端网络）— 违反员工主权
- Node.js 技术栈 — 我们是 Python
- "Mad dog mode" — 气质不合

### 一个法律预警

Evolver README 声明 **Hermes 的自进化设计涉嫌抄袭自 Evolver**。
我们用 Hermes 作 agent runtime 存在间接依赖。
**应对方案**：架构上已经解耦（网关、策略、Companion 都独立），
若未来 Hermes 真出问题，可切换 runtime（Evolver / 自研），其他部分不受影响。
**目前无需行动，保持关注。**

## 🎨 Companion UI 形态（2026-04-24 确认）

**三层 UI 形态，一套 Companion App 后端**：

### 1. 浮窗模式（快捷键召唤）★ 主入口
- 全局快捷键 `Cmd+Shift+Space`（Mac）/ `Ctrl+Shift+A`（Win）
- 从屏幕边缘滑出，半透明/毛玻璃
- 输入 → 回答 → Esc 关闭，不打断当前工作
- 自动带上下文（选中文本、前台应用、剪贴板）
- 适合：翻译、总结、写邮件、查东西

### 2. 主窗口模式（Dock / 任务栏图标点击）
- 完整聊天 UI：左侧历史会话、右侧对话区
- 支持文件拖入、图片粘贴、多模态
- 会话切换、搜索、导出
- 适合：长流程、深度任务、回顾

### 3. 菜单栏/托盘常驻
- 右上角（Mac）/ 右下角（Win）图标
- 状态指示（在线 / 后台任务运行 / 有新通知）
- 右键快捷：新对话 / 历史 / 设置 / 退出

**绝对不要的形态**：
- 黑底终端 CLI（给员工用 = 劝退）
- 网页版（还要开浏览器，打断感强）
- 飞书/企微 bot（聊天 UI 非差异化，P3 再说）

### 技术路径
- **Tauri** 主选（Rust + Web 前端）
- 浮窗与主窗口共用同一个 Tauri 进程
- 后端走 localhost HTTP 调用 Hermes runtime
- 全局快捷键：Tauri 的 global-shortcut plugin

**实施时机**：Week 3 Companion App v1（含浮窗），v2 加主窗口（Week 4-5）

### 22. 网关 Fallback 链
> 主模型挂了（502/429/timeout）时，网关自动切到备用模型。员工无感。

- 好玩在哪：**员工看不到"模型挂了"这件事**，鲶鱼"永远在线"
- 难度：中（error type 识别 + 冷却逻辑 + 测试）
- 估时：1–1.5 天
- 前置：网关日志稳定、真实环境有偶发故障可复现
- Week：**Week 2 后期 / P1 早期**（不是 P0）
- 为什么不着急：内网 Qwen 比 Gemini preview 稳得多，目前没成为真实痛点

**配置形态**：
```yaml
fallback_chain:
  catfish-private-main:
    on_error: [502, 429, 504, timeout]
    fallback_to:
      - catfish-public-gemini-flash
    cooldown_seconds: 30
```

### 23. 三层统一搜索（Unified Search）
> 员工说"搜一下 X"，鲶鱼自动判断搜公网 / 搜公司内 / 搜本地。

**三层分工**：
- 公网：Google / Bing / Brave Search（Hermes 已部分支持）
- 公司内：Confluence、Jira、GitLab、BI — 通过 MCP 连接器
- 本地：员工自己的文档、历史会话（FTS5）

- 好玩在哪：ChatGPT 不能搜"你公司的东西"，这是鲶鱼**真正的差异化**
- 难度：低（单层）/ 中（多层路由）/ 高（智能路由）
- 估时：
  - 公网（复用 Hermes 现有）：1–2 天
  - 内部 MCP 每个连接器：3–5 天
  - 智能路由层：1–2 周
- 前置：Browser Agent 稳定 + 至少 1 个 MCP 连接器
- Week：Week 2–3 开始（公网那层）→ P1（内部连接器）→ P2（智能路由）

**典型场景**：
```
员工："上次那个客户报的 bug 是谁修的"
→ 鲶鱼识别到"bug"和"客户"，搜 Jira
→ 找到 ticket #1234，展示修复人 + 修复时间

员工："我们产品三季度销售数据"
→ 鲶鱼搜 BI / Confluence
→ 返回报表链接 + 摘要

员工："Python 3.14 有什么新特性"
→ 鲶鱼判断是外部信息，搜公网
→ 返回官方文档摘要
```

### 24. Hermes 自定义 skill namespace
> 现在 Hermes 0.10 只识别预定义的一级 namespace（productivity / apple / github / mcp / ...），自建 `~/.hermes/skills/catfish/` 这种新 namespace 不会被加载，要把 catfish 自己的 skill 都塞进 productivity 下面才能用。这跟"鲶鱼是企业平台"的定位别扭：以后会有 catfish-local-search、catfish-internal-jira、catfish-meeting-summary、catfish-skill-hub 一堆，混在 productivity 里既乱又削弱品牌识别度。

**调研问题**：
- Hermes 加载 skill 的逻辑在哪？是硬编码 namespace 列表还是动态扫描？
- 有没有"插件式注册新 namespace"的机制？或者 manifest 文件？
- 实在不行，能不能 fork 一个 hermes-catfish-fork 把 namespace 列表加上 catfish？

**期望效果**：banner 出现独立一行：
```
catfish: local-search, internal-jira, meeting-summary, skill-hub, ...
```

- 难度：未知（要看 Hermes 内部）
- 估时：调研 0.5 天 + 实施可能 0.5~3 天
- 前置：catfish 平台 skill 数 ≥ 3（现在只有 1 个，还不急）
- Week：等到我们有 3 个以上 catfish skill 时再做
