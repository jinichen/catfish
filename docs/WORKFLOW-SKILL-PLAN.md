# 工作流 skill —— 设计 (待审)

10/17 起草, 同日按鸿波意见改: **目标不是做某一条工作流, 而是让员工自己用鲶鱼已有的能力搭工作流**。
文中的 EIS / 下载 / 通报只是举例。

一句话: 员工把一件反复做的事描述出来 (或者做一遍给小鲶看), 小鲶从「积木」里挑出步骤、接好数据,
员工确认后存成一个工作流 skill; 以后一句话 (或定时) 整条跑完, 中间该停下给员工看的地方会停。

这是「原子 skill → 工作流 skill → 专家」三层里的中间层 (10/17 讨论, 对标 WorkBuddy 专家包)。
专家 (人设 + 多个工作流 + 选路 + 验收, 打包进资源市场) 是下一步, 不在本文。

## 1. 现状 (10/17 读代码核实)

已经有、直接复用:

| 能力 | 位置 | 说明 |
|---|---|---|
| 教学录 trace | `trace_recorder.py` `RECORDED_TOOLS` | 浏览器 7 个动作 + `catfish_run_skill` (5/12 起 skill 能调 skill) |
| 凝固成脚本 | `skill_freeze.py` / `skill_freeze_template.py` | 纯模板, 不让 LLM 写代码; 嵌套 run_skill 失败即停 |
| 按值认出数据流 (只认一种) | `_is_captcha_fill` | 后面 fill 的值 = 前面验证码识别结果 → 凝固成实时调用 |
| 跑 skill | `run_skill` | 显式 `ok: false` 判失败; 结果里的路径收进 `files`; 审计只记参数名 |
| 静态校验 | `skill_verify.py` | 不过就不入库 |
| 员工确认才入库 | `catfish_propose_skill` | 草稿 → 员工点同意 → 写入 |
| 鲶鱼原生能力 | 89 个 catfish 工具 | 邮件 / 知识库 / 文件检索 / 任务提醒日程 / 草稿 / 一起填表 / 微信记录 / 客户档案 …… |
| 定时 | 定时任务 (hermes cron + picker 联动) | 工作流可以挂进去定时跑 |
| 对外动作的审批 | 审批卡片 / 微信 1、2 / P59 删除类每次问 / 定时任务里不执行删除 | `confirm` 步骤沿用 |

缺的 —— 要让员工自己搭工作流, 现在差这些:

1. **只能串「教过的 skill」**: 鲶鱼自己会的事 (查邮件、建任务、发填表、写草稿) 不能直接当一步用,
   员工得先把它们各教一遍。
2. **步骤之间传不了数据**: 嵌套 skill 的参数凝固时原样焊死 (`{skill_params!r}`), 上一步结果扔掉 ——
   下载到的文件到不了下一步, 下一步永远用教学那天的值。
3. **没有「要判断 / 要总结」的一步**: 固定步骤之间常常夹一步「看一下内容、挑出要的、写一段话」, 现在只能整件事
   交给过程型 skill (SKILL.md 让小鲶照着做), 没法跟固定步骤拼在一起。
4. **跑完不等于做成**: 只看 skill 自己报没报失败, 没有「做完查一下结果」。
5. **浏览器下载拿不到文件**: 没有「点下载 + 等落盘 + 返回路径」的工具, 网页上下文件的原子 skill 做不出来。
6. 中间一步失败只能从头跑; 工作流里有「发出去」的步骤时没有在那一步前停下的机制。

## 2. 积木: 一步可以是什么

工作流 = 一串步骤。每一步是下面三种积木之一, 员工 (或小鲶替他) 从积木目录里挑:

| 积木 | 是什么 | 例子 | 确定性 |
|---|---|---|---|
| **技能** `skill:` | 员工 / 部门已有的凝固 skill (`script.py`) | 登录某系统、在某网页上下载、在 OA 里填单 | 每次一样 |
| **能力** `action:` | 鲶鱼原生工具里**挑出来、适合放进工作流**的那些 (§2.1) | 搜邮件、读附件、建任务 / 提醒 / 日程、写邮件草稿、发填表、发布到知识库 | 每次一样 |
| **小鲶** `xiaonian:` | 交给小鲶做一步需要判断的事, **必须说清要交回哪些字段** | 「从这些邮件里挑出跟资质有关的, 交回: 标题列表、一段 200 字摘要」 | 会有出入, 所以有限制 (§2.2) |

### 2.1 能力积木目录

不是 89 个工具全放进来。每个进目录的能力要标两件事: **输出有哪些字段** (后面的步骤才能引用) 和
**副作用级别** (决定要不要停下确认):

| 级别 | 跑的时候 | 首批候选 |
|---|---|---|
| 只读 | 直接跑 | email_search / email_read / email_attachment、wiki_search / wiki_read、search_files / search_docs / search_attachments、list_tasks / list_reminders / list_calendars、wechat_search / wechat_history、today_summary、list_my_outputs |
| 本机写入 | 直接跑 (只动员工自己电脑上的东西) | create_task / create_reminder / create_calendar_event、email_create_draft / draft_email_reply (只存草稿不发)、wiki_create / wiki_update、form create / export |
| 对外 | **停下给员工看, 同意才做** | form send / remind / close、wiki_publish、(以后接进来的「发消息」类能力) |
| 不进目录 | — | 教学 / 凝固 / 装删 skill、记忆和画像的改动、forget、原始浏览器动作 (属于原子 skill)、终端 / 执行代码 |

目录是一份声明文件 (tool-bridge 里), 新能力上线时顺手决定进不进、算哪一级。

### 2.2 小鲶积木的限制

- 必须写明**交回的字段** (名字 + 类型), 运行器校验, 缺了 / 类型不对就算这一步失败, 不往下传半截。
- 这一步里小鲶**只能用只读能力** (查、读、搜), 不能发、不能写、不能调别的 skill —— 判断归判断, 动手的事留给后面的固定步骤。
- 结果在运行记录里原样留着, 员工随时能看「小鲶这一步是怎么判断的」。

## 3. 工作流长什么样

新 kind: `workflow`。跟别的 skill 一样放 `~/.catfish/skills/<ns>/<name>/`:

```
SKILL.md        # name / description / triggers —— 小鲶靠它知道什么时候用 (跟所有 skill 一样)
workflow.yaml   # 步骤: 用哪块积木、参数从哪来、做完查什么、哪一步要确认 —— 不是代码
```

`workflow.yaml` 示意 (举例: 每周一把上周的资质相关邮件附件整理好, 给负责人建个任务):

```yaml
kind: workflow
version: 1.0.0
params:                                   # 每次跑可以改的; 小鲶 / 定时任务给, 不给用默认
  keyword: {type: text, default: 资质}
  days:    {type: number, default: 7}
steps:
  - id: mails
    action: email_search
    params: {query: "${params.keyword}", days: "${params.days}"}
    expect: {count_min: 1}               # 一封都没有 → 停, 告诉员工「这周没有」
  - id: pick
    xiaonian: 从这些邮件里挑出真正跟资质申请有关的, 说明理由
    input: ${steps.mails.items}
    returns: {ids: list, summary: text}
  - id: files
    action: email_attachment
    for_ids: ${steps.pick.ids}            # 见 §8: 这一版只支持「对一个列表各做一次」这一种重复
  - id: todo
    action: create_task
    params:
      title: "整理资质附件 (${params.days} 天内 ${steps.files.count} 份)"
      note:  ${steps.pick.summary}
      attachments: ${steps.files.paths}
```

另外两个举例, 说明积木能怎么拼 (都只是例子):

- **网页系统 + 发出去**: `skill: 某系统登录` → `skill: 某页面下载附件` → `xiaonian: 核对附件内容, 交回 是否合格 / 问题` →
  `action: form send` (发给相关同事确认, **对外, 停下给员工看**)。
- **月度收集**: `action: form create` (用上个月的模板) → `action: form send` (**对外**) —— 挂定时任务每月 1 号跑,
  发送那步默认等员工点头。

为什么是声明式 yaml, 不是再生成 `script.py`:

- 员工看得懂、改得动 (Companion 里画成一列步骤卡片, §4.3)。
- 不让 LLM 写代码的原则不破: 只能引用积木和 `${...}` 取值, 没有表达式, 写不出任意逻辑。
- 能静态校验: 积木存在、版本匹配、`${steps.X.字段}` 只引用前面步骤**声明过的输出**、类型对得上。
- 能断点续跑、能在对外步骤前暂停 —— 运行器知道走到哪、每步结果是什么。
- 调用方式不变: `catfish_run_skill` 遇到 `workflow.yaml` 交给工作流运行器。

## 4. 员工怎么自己搭

三条路, 产物都是同一份 `workflow.yaml`, 都要员工确认才入库, 入库前都能**试跑一次**。

### 4.1 跟小鲶说 (主路)

员工用大白话描述:「每周一帮我把上周带"资质"的邮件附件理一下, 给我建个任务」。小鲶:

1. 拆成步骤, 每步从积木目录 + 员工已有的 skill 里挑; 用 `catfish_propose_skill` (kind=workflow) 出草稿。
2. 草稿给员工看: 一列步骤卡片 (哪步是固定的、哪步是小鲶判断、哪步会停下等确认)、哪些是可改参数。
3. **有一步没有积木能做** (例如要在某个内部网页上点点点) → 小鲶明说「这一步我还不会, 你教我一遍」,
   转进教学流程教一个原子 skill, 教完回到草稿接上。员工的工作流能力会随着教的原子 skill 越来越多。
4. 员工点「试跑」→ 真跑一遍, 对外步骤照样停下; 看结果满意再点「保存」。

### 4.2 做一遍给小鲶看 (教学)

照现在的教学流程, 员工一步一步让小鲶做 (调 skill、调能力、让小鲶判断一下)。凝固时:

- trace 里**没有原始浏览器动作**的 → 生成 `workflow.yaml`; 有浏览器动作的照旧凝固成 `script.py` (现有行为)。
- 数据流照验证码那一招**按值对上**推断, 不让 LLM 猜: 后一步某个入参的值 = 前面某步输出里的某个字段值 →
  写成 `${steps.X.字段}`; 找不到来源、像是员工当场给的值 (关键词、日期) → 提成工作流参数, 当天的值作默认
  (像日期的默认「今天」)。
- 拿不准的列出来问员工 (「标题是每次固定, 还是每次换?」), 不自己定。
- 顺带修掉现在 `script.py` 里嵌套 skill 参数焊死、结果扔掉的问题 (同一套推断)。

### 4.3 在 Companion 里改

技能页里工作流显示成一列步骤卡片:

- 加一步: 从积木目录挑 (按「查 / 写 / 发 / 我的 skill / 让小鲶判断」分组)。
- 填参数: 每个参数可以填固定值、选工作流参数、或者**从下拉里选前面某一步的某个输出** (下拉只列前面步骤
  声明过的输出, 选不到不存在的东西)。
- 勾「这步要我确认」(对外的能力默认勾上且去不掉; 别的可以自己加)。
- 存之前过静态校验, 不过就标红那一步。

不做拖拽连线的流程图: 这一版只有顺序步骤, 一列卡片就够, 员工也更容易看懂。

## 5. 怎么跑

运行器在 tool-bridge (新 `skill_workflow.py`)。

1. **开跑前检查**: 积木都在 (缺的部门 skill 提示去资源市场装)、版本匹配、必填参数齐、`${...}` 都能解析。
   有一个不行就一步都不跑。
2. **每一步**: 调积木 → 记结果 → 查 `expect`。`expect` 只有几种简单判断, 不写表达式:

   | 写法 | 意思 |
   |---|---|
   | `ok: true` | 结果里 `ok` 显式为真 |
   | `count_min: N` | 列表至少 N 项 (邮件、文件、搜索结果) |
   | `files_min: N` | 至少 N 个文件, 而且**真的在磁盘上** |
   | `text_contains: "…"` | 结果的文字里有这段 |
   | `page_contains: "…"` | 当前浏览器页面里有这段 (浏览器类 skill 之后用) |

   失败 → 停, 说清: 第几步、哪块积木、为什么、前面做了什么 (已经下载到哪、已经建了什么)。
3. **对外步骤前停下**: 把**将要发什么** (参数解析后的值: 发给谁、内容、附件) 给员工看, 同意才继续。
   对话 / 微信里出审批卡片 / 回 1、2。**定时任务里默认不发**: 停在这一步, 结果写明「这步没发, 等你确认」。
   删除类不管怎么设都每次问 (P59 同一条红线)。
4. **断点续跑**: 每次运行记 `~/.catfish/workflow_runs/<run_id>.json` (只在本机)。失败或停在确认步骤 →
   员工说「继续」/ 点「从这一步重跑」, 前面成功的结果直接用。会过期的东西 (登录态) 由原子 skill 自己的预检发现。
5. **审计**: 工作流名 / 版本、每步积木名 / 成败 / 耗时、参数**名**; 不记参数值、不记邮件 / 文件内容。

## 6. 先补的原子能力

- **浏览器下载** `catfish_browser_download(selector | coordinates, timeout)`: 点下载 → 等文件落到
  `~/.catfish/downloads/<日期>/` → 返回 `{path, filename, size}`; 进 `RECORDED_TOOLS` 和凝固模板。
  没有它, 「在网页上下文件」这类最常见的原子 skill 做不出来。
- **能力积木的输出声明**: 进目录的能力各写一份输出字段 (多数工具现在就返回 dict, 主要是把字段名定下来、写测试钉住)。

## 7. 跟现有东西的关系

- **已有 skill 不用重做**: 凝固的 `script.py` 都能当技能积木; 过程型 skill (`eis-zizhi-shenpi` 这类, 小鲶边看边判断)
  照旧, 需要大段判断的流程还是它合适。
- **分发**: 跟别的 skill 一样走 personal / department 和 skills hub。部门发出去的工作流引用到的部门 skill 要在部门里;
  员工自己的 skill 被引用时, 发布前提示「这一步用的是你个人的 skill, 同事没有」。
- **专家 (下一步)**: 专家包 = 人设 + 若干工作流 / skill + 选路规则 + 收尾检查。本文的积木目录、`expect`、对外确认
  是专家的底座。

## 8. 不做 (这一版)

- 条件分支 (「如果……就……否则……」): 要判断用小鲶积木交回结果, 分支逻辑留给专家那一层。
- 任意循环; 只支持一种: `for_ids` —— 对前一步交回的列表**每项做一次同一块积木** (多个附件各下载一次)。
- 并行步骤、步骤之间的时间等待 (「等 3 天再催」用定时任务)。
- 拖拽连线的流程图编辑器。
- 跨员工 (某一步在同事电脑上跑) —— 要同事参与的用「一起填表」或「请同事帮忙」那两套。

## 9.1 实现备注 (10/17 落地时的取舍)

- **10/17 定的**: 定时任务里的对外步骤默认不发、等确认, 员工可以对某个工作流单独开「对外步骤不用每次确认」
  (只在界面上开, 小鲶不能替他开; 员工自己勾的「这步要我确认」不受影响); 首批能力加了「推送到我的微信」;
  小鲶积木放进第一版。
- **确认只能在界面上点**: 没用 hermes 的审批引擎 (它要会话上下文, 从插件里调太脆, 升级就坏), 走跟「一起填表」提交同一个思路 ——
  模型的工具里根本没有确认动作, 停下的运行在每个页面顶上出确认卡 (WorkflowConfirmBanner), 只有 `pim/workflow_confirm` 能放行。
  所以定时任务跑到对外步骤天然就停住等人, 不用另外判断「有没有人在」。
- **小鲶积木比设计稿再收紧**: 这一步**不给任何工具**, 只看 `input` 交进来的数据, 按 `returns` 交回; 说明文字里也能写 `${...}`。
- **重复只做了 `for_each`** (列表每项做一次同一步, 最多 50 项), 引用里用 `${item}`。
- 运行记录在 `~/.catfish/workflow_runs/`, 草稿在 `workflow_drafts/`, 员工设置在 `workflow_prefs.json` —— 都只在本机。
- **教学凝固**: 没有网页操作 → 工作流草稿; 网页 + 会改东西的能力混着 → 拒绝并说明; 网页教学里顺手查的只读能力跳过。
  script.py 那条路里嵌套 skill 的参数也按值认数据流 (`_dig(_outs[n], 路径)`), 其余字符串提成参数, 默认教学那天的值;
  凝固出的脚本现在会返回 `files` / `path` (下载到的文件)。
- `catfish_browser_download` 用一次性 Chromium 走 CDP 实测过 (下载、重名加序号、点了没下载给人话)。
- 核心工具上限 46 → 47 (`catfish_workflow` 直达)。tool-bridge 的分派表挪到 `native_submodules.py` (catfish_tools.py 贴着 800 行)。
- 顺带: tool-bridge 测试加了 conftest, 默认把 CATFISH_HOME / 任务库 / 登录凭据都指到临时目录 —— 写这个功能时测试两次写进了真
  `~/.catfish` (已清掉), memory_dedupe 两条测试一直拿真凭据打真模型、时过时不过, 现在都不会了。

## 10. 验收
