## V0 · 核心一句话 (任何场景都能用)

**10 秒**:

> 鲶鱼让员工**个人能力持续成长**, 把员工愿意分享的部分**沉淀成企业资产**. 数据全在员工电脑, 跳槽带走; 员工显式贡献的 skill 才进部门 Hub. 双层飞轮.

**关键词**: 成长 / 沉淀 / 员工拥有 / 自愿贡献 / 双层飞轮.

**用法**: 不知道客户角色, 或客户问"鲶鱼到底是干嘛的", 先用这一句, 看反应再展开 V1-V5.

## V1 · 给 CTO / 技术决策者

**30 秒**:

> 鲶鱼是企业级**LLM 中台 + 员工副手 + 组织能力沉淀器**. 三层架构: Companion 在员工本机, tool-bridge 隔离工具调用, 中央 gateway 做 LLM 路由 + 审计 + 容灾.
>
> 跟 ChatGPT 不一样的核心是: 数据**全本地** (对话不出员工电脑, 跨 session 记忆也在本地 journal), LLM **跨厂商任意切** (你们自己 qwen / 公网 gemini / 容灾 fallback), 中央**只看 metadata** (token / latency / 安全事件), 看不到内容.
>
> Phase 1 现在 ship 已经包含**跨 session 记忆 + 教学冻结**: 员工教鲶鱼一次, 鲶鱼凝固成 skill, 员工显式分享给同事进部门 Hub. 部门 skill 库**一年长 50-100 个工作流模板**, 这是组织 know-how 数字化沉淀, SaaS 干不了.
>
> 12 个月内 ship Phase 3 Catfish Federation 跨员工 agent 协作, 护城河更深.
>
> 私有化部署, 你们 IT 全审代码.

**触发场景**: 客户 CTO 问"你们技术架构什么样" / "怎么保证企业级"

## V2 · 给部门领导 / 业务负责人

**30 秒**:

> 你们部门员工 8 小时, 4 小时在切系统 / 找数据 / 套模板 / 写汇报. 这 4 小时鲶鱼能帮他们干掉. **更深的 ROI 是: 员工干完一次, 部门 skill 库就多一个流程模板**.
>
> 演示场景: 员工说"抓 EIS 资质 145 条, 套部门模板生成本月汇报", 鲶鱼**全程自动**做完, 4 段公文结构 + 错别字自审, 员工只 review 改两个字按发送. 第二天员工说"昨天那个汇报怎么改", 鲶鱼**记得**.
>
> 然后是关键的一步: 员工觉得这个流程好用, 点一下"📤 分享到部门 Hub", 经安全扫描 + 你审一下, 这个 skill 进部门库, **别的同事直接装就能跑**. 100 个员工各贡献一个流程, 1 年部门 skill 库长 100 个工作模板. 老员工流失, know-how 不流失.
>
> 不是替代员工, 是**两件事一起做**: (1) 把员工**从重复劳动里解放** (2) 让员工**贡献的好流程沉淀成部门资产**.
>
> 50 人部门一年装下来, 每人省 10 小时 / 周 = 部门一年省 25000 小时 + 部门 skill 库长出 50-100 个工作模板.
>
> 私有化部署, 你们数据不出公司. 员工**显式分享**的才进 Hub, 没分享的还在员工本机. 一次性 license, 不抽 token 流水.

**触发场景**: 部门领导问"它能给我员工带来什么" / "对我的 KPI 有什么用"

## V3 · 给员工 / 实际使用者

**30 秒**:

> 你早上 9 点开电脑要登 4 个系统对吧? 报销跨 3 个表填 12 个字段对吧? 周报凑字数翻一周邮件半小时对吧?
>
> 鲶鱼帮你干掉这些. 你跟它说"帮我登 EIS 抓今天数据, 套部门模板写汇报", 它**自动**做完, 你审一下按发送. 它**还记得你昨天做了什么** — 你说"昨天那个改一下", 它直接接得上, 不需要你重新解释.
>
> 关键 3 条:
>
> 1. **它跟你跳槽走** — 鲶鱼是你的, 不是公司的. 你换工作了, `~/.catfish/` cp 到新电脑, 鲶鱼继续懂你. 6 个月跟你磨合的画像 / 风格 / 工作记忆不丢
> 2. **你教它的东西, 你决定要不要分享** — 觉得这流程同事用了也好, 点"📤 分享到部门 Hub" 才走出去 (而且经过安全扫描). 不分享就一直在你电脑上
> 3. **不偷你密码** (走 Keychain), **不传你对话给厂商** (全本地), **不替你做决定** (草稿 / 发送 / 提交都你本人按)
>
> 装上 30 分钟学一下, 一周后你不会想关掉它. 真的.

**触发场景**: 给员工演示 / 入职培训 / 推广

## V4 · 给 CISO / 数据安全负责人

**30 秒**:

> 鲶鱼**不是后补合规**, 设计阶段就是合规.
>
> 三层数据保护:
> 1. **边缘**: 对话内容 + memory + 工具历史 + **跨 session 记忆 (employee_journal.md)** 全在员工本机 `~/.catfish/`, 永远不出员工电脑. 你们 IT 可以直接 grep journal 文件审计鲶鱼记了什么
> 2. **凭据**: secret_ref + macOS Keychain, 密码**永远不进 LLM 上下文**, 我们 prompt regex 检测员工不小心发明文密码会自动 audit 标记
> 3. **审计**: 中央 gateway 写 JSONL audit, 字段是 user / model / token 数 / TTFT, **没有对话内容字段** — 代码层面写死的, 你们 IT 可以审计代码
>
> 离线模式 + token 短 TTL + 强制 SSO. 客户 IT 拿到全套 audit 工具, ~600 行 SSO 代码可读可审.
>
> 你们 CISO 部门提的合规要求, 我们能正面回答, 不是"我们正在规划".

**触发场景**: CISO 问"数据安全怎么保证" / "员工密码怎么处理" / "审计能追溯吗"

## V5 · 给财务 / 预算决策者

**30 秒**:

> 鲶鱼是**资本支出 (一次性) + 维护费**, 不是 SaaS 月费 / 按 token 付.
>
> 50 人部门: 一次性 X 万 license + 年度 15-20% 维护. 5 年总成本约 X*1.8 万.
>
> 不收的: API token 流水 (员工怎么用都不收钱, 你们用自己 LLM) / 中央云费 (你们机房) / 升级费 (年度维护包含).
>
> ROI 两层算:
>
> 1. **短期省时间**: 50 人部门, 每人每周省 10 小时, 一年部门省 25000 小时, 按内部时薪折算约 X*30 万/年
> 2. **长期沉淀**: 1 年部门 skill 库长 50-100 个工作模板. 等于把老员工 know-how 数字化存档. 老员工流失, 流程不流失. 这是**组织能力资产**, 跟人才战略对齐, 高 5-10 倍议价空间
>
> 投资回收期: 2-4 个月 (短期 ROI). 长期 ROI 看部门 skill 库厚度, 不收敛.
>
> 关键: 我们靠**装得久 + 推广到其他部门 + 部门 know-how 沉淀沉得越深越离不开**赚钱, 不靠卡员工 token. 商业模式跟 SaaS 反着来 — 你们用得越多, ROI 越高, 我们续约越稳.

**触发场景**: 财务问"成本结构" / "ROI 怎么算" / "为什么不用 SaaS"

## FAQ · 客户对"成长 + 沉淀"广告词追问的标准回答 (5/21 加)

> 5/21 charter 把广告词调整为 "员工成长加速器 + 组织能力沉淀器". 这 3 个追问最容易撞到, 标准回答背熟. 跟 `docs/CATFISH-POSITIONING-2026-05-19.md` "产品初衷 5 条护栏" 保持一致, 别回答得跟初衷冲突.

### Q1 · 你们说"提升企业能力", 具体怎么实现?

> **员工自愿分享**, 不是从员工本机抽数据.
>
> 流程: 员工教鲶鱼一次 → 鲶鱼凝固成 skill → 员工**自己决定**要不要点"📤 发布到团队 Hub" → 经 3 道安全扫描 (凭据 / PII / 内网信息) + manager 审核 → 才入部门 skill 库, 别的同事可装.
>
> 100 个员工各贡献一个流程, 1 年部门 skill 库长出 100 个工作模板. **能力从员工自愿贡献来, 不是从员工电脑偷数据**.

### Q2 · "员工拥有" 跟 "企业能力沉淀" 不冲突吗?

> 不冲突, **两层资产分开**:
>
> | 层 | 谁拥有 | 跳槽时 |
> |---|---|---|
> | **个人画像** (~/.catfish/ 里的 memory / journal / chat / 风格指纹) | 员工 | 跟员工走 |
> | **部门 skill 库** (员工显式 publish 进 Hub 的 skill) | 公司部门 | 留下 |
>
> 员工拥有的是**自己的 AI 副手 + 自己的工作记忆**. 企业沉淀的是**员工愿意贡献的部分**. 边界清晰, 工程上是两个目录, 不混. 详见 `docs/CATFISH-HERMES-BOUNDARY.md` "Skill 路径" 段.

### Q3 · 鲶鱼会被公司用来监控员工吗?

> 不能, 而且**架构上做不到**:
>
> 1. **数据零出端** — 员工 chat 内容 / journal / memory / uploads 全在员工 mac (`~/.catfish/`), 永远不进中央. 中央 gateway 写的 audit JSONL **代码层面没有"对话内容"字段**, 客户 IT 可审代码确认
> 2. **公司能看的只有 metadata** — 谁用了多少 token / 几次调用 / 哪个模型 / 哪类工具. 看不到内容
> 3. **chat 是工作产出, 公司有审计权天然存在** — 跟邮件 / 飞书消息同源, 鲶鱼不挡也不该挡, 但 catfish 本身**不主动**做监控功能
>
> 想看具体边界 → `docs/PRIVACY-PRINCIPLES.md` + `README-FOR-CUSTOMERS.md` 数据隐私 3 道边界段.

## 30 秒计时练习

每个版本对着镜头 / 录音练 5 遍, 计时**必须 ≤ 30 秒**. 30 秒内说不完 = 没准备好, 客户会没耐心听.

理想节奏: **3-4 句话**, 每句 8-10 秒, 一句一个 take-home message.

V1 给 CTO 的拆解 (4-30 升级版):
- 句 1 (8s): 鲶鱼是 LLM 中台 + 员工副手, 三层架构
- 句 2 (8s): 数据全本地 (含跨 session 记忆), LLM 跨厂商, metadata 可审
- 句 3 (8s): Phase 1 已有跨 session 记忆 (真副手非聊天机)
- 句 4 (6s): Phase 3 Federation 是护城河, 私有化全审

每句精炼到这个程度, 30 秒不超.
