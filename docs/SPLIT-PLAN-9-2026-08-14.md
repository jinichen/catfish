# 9 个文件的拆分方案 (2026-08-14 夜)

## 为什么是这 9 个

`scripts/check_file_sizes.sh` 报 34 个必拆。按**真正影响拆分风险**的两个轴分：

| 类型 | 个数 | 有测试 | 编译器兜得住 |
|---|---:|---:|---|
| `.py` | 13 | 7 | 否 |
| `.rs` | 9 | 8 | 是 |
| `.tsx` | 5 | 0 | 是 |
| `.ts` | 4 | 1 | 是 |
| `.js`/`.sh` | 3 | 0 | 否 |

这 9 个是**类型检查 + 测试双保险**的那一批。文件大小不是主轴 —— 8/14 拆
`embedding.rs`(890 行) 之所以安全，靠的是自然边界 + `cargo check` 立刻兜底 +
拆完有测试能跑，跟"小"没关系。

对照：`app.py` 3779 行是最该拆的，也是最危险的（无类型检查、无测试文件、
全员主链路）。它不该顺手拆，**拆之前先补测试**。

---

## 通用规矩

1. **一次一个文件**，拆完立刻 `cargo check` / `npm run build`，绿了才动下一个。
2. **纯搬迁，不改逻辑**。搬迁和改逻辑混在一起，review 时分不出哪个动作引入了问题。
3. 搬完**跑一遍该模块的测试**（Rust 内联测试会跟着代码走，注意别落下）。
4. 提交信息里写清**切在哪条边界、为什么是这条**。

> 8/14 记的一笔：某天 4 个 bug 里 3 个来自重构。所以宁可慢。

## lib.rs 的具体拆法 (8/15 量好，等有编译器的机器上做)

**为什么没当场做**：Linux 沙箱里 `cargo check` 起不来 —— Tauri 要 GTK
系统库 (`gdk-3.0`)，而容器里没有 sudo 装不了。

Rust 这刀最容易断的恰恰是 `move` 闭包捕获、生命周期、`?` 的错误类型，
**只有 borrow checker 抓得住**。语法检查能过但编译不过，给的是假信心 ——
这正是当天反复在防的那类失效。所以只出方案，不动手。

### 已量好的事实

```
30-97    7 个 Shortcut 定义 (let)
98-120   builder + log plugin
122-247  #[cfg(desktop)] { global_shortcut Builder.with_handler(move |..| {...}) }
250-631  .setup(move |app| {...})              382 行
632-1048 .invoke_handler(generate_handler![])  417 行 ← 不动
1049-77  .build().run(...)
```

- 7 个 shortcut 被**两处**用：handler 闭包里比较 (`shortcut == &toggle_shortcut`)，
  setup 里注册 (`app.global_shortcut().register(toggle_shortcut)`)。
- `Shortcut` = `global_hotkey::HotKey`，crate 源码里是
  `#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]` —— **是 Copy**。
  所以一个 `#[derive(Clone, Copy)] struct Shortcuts { .. }` 能同时喂两个 move 闭包。
  (这是这个方案里最大的未知，已经查证。)
- `.setup` 闭包体里除了 7 个 shortcut，**不引用 run() 里任何别的局部**。
  `?` 只出现 1 处，`return` 2 处都在更内层的嵌套闭包里。

### 方案

```
src/startup/shortcuts.rs
    #[derive(Clone, Copy)] pub struct Shortcuts { toggle, focus, pet, tl, tr, bl, br }
    pub fn define() -> Shortcuts                     // 原 30-97
    pub fn handle(app, sc, event, s: &Shortcuts)     // 原 130-247 的闭包体
    pub fn register_all(app, s: &Shortcuts)          // 原 setup 里注册那段

src/startup/setup.rs
    pub fn setup(app: &mut tauri::App, s: Shortcuts)
        -> Result<(), Box<dyn std::error::Error>>    // 原 250-631
```

lib.rs 里剩：builder 链 + `invoke_handler!` 名单 + run，约 505 行。

### 做的时候要盯的五件事 (都只有编译器说了算)

1. `Shortcut: Copy` 已确认，但 `Shortcuts` 结构体要显式 derive
2. `setup` 的 `app` 是 `&mut tauri::App`，不是 `AppHandle`
3. `?` 的错误类型要跟闭包原来的 `Box<dyn Error>` 对齐
4. `#[cfg(desktop)]` 跨模块后要在新文件里重新标
5. 闭包捕获从"7 个值"变成"1 个结构体"，捕获模式会变 —— 编译器会说话

跑完 `cargo check` 还要真起一次 app：召唤浮窗 (Cmd+Shift+Space) /
专注模式 (Cmd+Shift+F) / 桌宠 (Cmd+Shift+P) / 四个角 (Option+Shift+1..4)
各按一次。快捷键注册失败是**只 warn 不报错**的，编译过不代表按得动。
