# 销售跟进 (客户档案 + 跟进雷达) —— 阶段 1 计划

10/12 定。用户: **我们自己卖鲶鱼的销售团队**; 客户沟通主要在**个人微信 + 邮件**。
不接 ERP, 只在现有能力上搭。目标是一件事: **跟进不掉线** —— 该回的回了、答应的做了、
久没联系的客户有人提醒。

| 早安顾问 | `briefing_advisor.ts`, 现有数据源 = 邮件 50 封 / 日历 / 提醒 | 加客户档案 + 微信两个源, 出跟进卡片 |

## 2. 客户档案 (实体页)

新类型 `customer` (别名「客户」「客户公司」), 一个客户一页:

```markdown
---
type: entity
entity_type: customer
title: <客户公司名>
stage: 线索 | 需求确认 | 已报价 | 商务谈判 | 成交 | 输单 | 暂停
owner: <销售姓名>
contacts: [{name: <联系人>, role: <职务>, wechat: <微信备注名>, email: <邮箱>}]
last_contact: 2026-10-12          # 最近一次双向沟通 (不是我单方面发)
next_action: 周三前发正式报价       # 一句话
next_action_due: 2026-10-15
deal_size: 12万/年                  # 可空, 估算
created: ... / updated: ...
---

## 时间线
- 2026-10-12 · 微信 · 对方问「私有化部署要几台服务器」(未答) [来源]
- 2026-10-10 · 邮件 · 我方发产品介绍 PDF [来源]
- 2026-10-08 · 会议 · 演示, 对方关心数据不出本机 [纪要]
```

- **谁建**: 销售说「把 X 公司建成客户」, 或小鲶在邮件/微信里发现新的潜在客户时**提议**新建 (员工确认才建, 不自动建)。
- **谁更新**: 小鲶处理客户相关的邮件 / 导入微信 / 会议纪要后, 往时间线**追加**一行 + 更新 `last_contact`;
  `stage` / `next_action` 由小鲶**建议**, 员工点确认才改 (阶段是业务判断, 不让模型自己定)。
- **怎么认是哪个客户**: 邮件按发件人域名 / 地址匹配 `contacts.email`; 微信按导出时的群名 / 对方备注名匹配 `contacts.wechat`; 匹配不上的列为「待归属」, 不猜。

### 2.1 销售模板 (不随商品写死)

不同商品的销售阶段和节奏不同 (软件: 线索→报价→谈判; 包装: 询价→打样→报价→试单…)。阶段名、各阶段
多少天没动静算冷、哪个阶段算「已报价」、客户问了多少个工作日没回提醒、报价后几天没回音提醒 —— 全在
「销售模板」里 (`~/.catfish/sales_template.json`, 设置 →「🤝 销售跟进」可改)。没配就用鲶鱼默认模板
(下面 §3 的天数)。小鲶建客户 / 改阶段只认模板里的阶段名。

## 3. 跟进雷达 (早安顾问的新数据源)

每天早上 (和员工手动点刷新时) 扫一遍, 出四类卡片, 每张卡带**依据** (原话 + 来源) 和**一键动作**:

| 规则 | 判据 | 卡片动作 |
|---|---|---|
| ① 客户在等我回 | 客户最后一条消息是问题 / 请求, 之后我方没回复, 超过 1 个工作日 | 起草回复 (按文风) · 标为已处理 |
| ② 我答应的事 | 我方消息里有承诺句 (「明天发」「周三前给」「我确认后回您」), 到期未见对应动作 | 生成提醒 (推到微信) · 起草 |
| ③ 客户冷了 | `last_contact` 超过 N 天 (按阶段: 线索 14 天 / 需求确认与已报价 7 天 / 谈判 3 天) | 起草问候 / 推进消息 · 改阶段为暂停 |
| ④ 报价没回音 | 阶段 = 已报价, 报价后 5 天无客户回复 | 起草跟进 · 提醒 |

- 判据由模型读原话判断 (承诺句、问题句), 但**卡片必须引用原话**, 员工一眼能核对; 判不准的宁可不出。
- 关掉的卡片走现有「关闭账本」, 不会第二天又冒出来。
- 天数阈值做成设置, 不写死。

## 4. 微信这条腿的限制 (要先说清楚)

1. **只能事后读**: 数据来自员工「合并转发」导出的 ZIP, 没有实时同步。雷达在微信上的新鲜度 = 最近一次导入。
   - 建议的工作习惯: 跟客户聊完或每天下班前, 把客户聊天合并转发一次拖进小鲶。
   - 待验证: 销售能否把客户聊天**直接合并转发给微信里的小鲶机器人** (iLink 是否把合并转发消息完整交给 hermes)。可行的话就不用拖 ZIP。
2. **小鲶不在个人微信里替销售发消息**: 个人微信自动化有封号风险。小鲶只起草, 销售复制发送。
3. 邮件这条腿是实时的 (现有邮件读取), 不受上面限制。

## 5. 数据边界

- 客户档案、时间线、雷达结果**全部在销售本机** (`~/.catfish/`), 中央端不存。
- 起草和判据走模型时, 只有相关片段经网关 (网关不落盘), 跟现在聊天一致。
- 阶段 3 才有「主管看全组漏斗」: 由销售**主动发布**结构化摘要 (阶段 / 金额 / 下一步, 不含聊天原文) 到部门 wiki-hub, 沿用现有「员工主动 push」例外。

## 6.1 实现备注 (10/12 落地时的取舍)

- **一个工具**: `catfish_customer` (action = upsert / log / done / get / list / radar / template)。核心工具每个都占
  gateway tool cap, 合成一个只占一格 (DEFAULT_MAX_TOOLS 44→45), 同步进 hermes `_PROMOTE` + gateway `ALWAYS_ON`。
- **雷达是确定性规则**: "是不是问题 / 承诺"由模型在 log 时判 (kind 字段), 雷达只按时间线和模板算,
  同样的档案永远出同样的卡; 卡片 uid 稳定, 关卡复用早安关闭账本。
- **待归属**: 第一版不单独存「待归属」列表 —— 认不出客户时工具直接报错 + 给候选, 由小鲶问员工; 不会记错客户。
- 早安「客户跟进」是独立一条 (`CustomerFollowupStrip`), 没有客户档案时不显示, 不改原有早安两栏布局。
- 「客户冷了」: 没有 `last_contact` (建档后客户一次没来过消息) 的, 从建档日 `created` 算, 否则这种客户永远不会被提醒。

## 7. 验收

1. 建 3 个虚构客户, 导入一段虚构微信 + 几封虚构邮件 → 时间线自动出现对应条目, 来源可点。
2. 构造四类情形各一 → 早安出四张卡, 每张引用原话; 关掉后第二天不再出现。
3. 「我答应的事」生成的提醒到点推到微信 (Windows)。
4. 改阶段必须经员工确认; 匹配不上的消息进「待归属」, 不被塞进错的客户。

## 10. 阶段 2: 报价 + 销售周报 (10/12 定: Excel 价格表, Excel 报价单)

仍然**一个工具** `catfish_customer`, 加 action, 不多占 tool cap。

### 10.1 价格表

- 来源: 销售团队现有的 Excel 价格表 (商品 / 规格 / 单位 / 标价 / 最低价 / 备注), 在设置「🤝 销售跟进」里**导入**,
  存成 `~/.catfish/sales/pricebook.json` (原 Excel 也留一份)。列名靠表头识别 + 员工确认映射, 不要求固定格式。
- 不同商品的团队各导各的, 跟销售模板一样不写死。
- action=`price`: 按商品名 / 规格查价, 给小鲶答「X 多少钱」用。

### 10.2 出报价单

- action=`quote`: 客户 + 明细 (商品 / 数量 / 单价 / 折扣) + 有效期 + 备注 → 生成报价单文件。
  - 单价默认取价格表标价; **低于最低价**只出提议 (needs_confirmation), 员工确认才生成。
  - 模板: 默认内置一份干净的 .xlsx 报价单; 团队有自己的公司模板 (.xlsx / .docx, 里面放 `{{客户}}` `{{明细}}` `{{合计}}` 这类占位) 可在设置里换。
  - 文件: `~/.catfish/outputs/<日期>/报价-<客户>-v<N>.xlsx`, 版本号按该客户已有报价自动 +1。
- 生成后自动往客户时间线记一条 `我方 · 报价 · v<N> 合计 ¥X [文件]`, 雷达的「报价没回音」直接接上。
  **只生成, 不替销售发出**; 发出去后员工说一声, 才把阶段改成「已报价」(仍走确认)。

### 10.3 销售周报

- action=`weekly`: 只读客户档案, 确定性统计本周 (周一到今天):
  - 漏斗: 各阶段客户数 + 预计金额合计; 本周新建客户; 本周阶段变化 (谁从哪到哪)
  - 本周发出的报价 (客户 / 版本 / 金额); 成交 / 输单
  - 跟进健康度: 到期未兑现的承诺、冷掉的客户、等回复的客户 (直接复用雷达)
  - 下周要推的: 各客户 next_action + 截止
- 输出 .xlsx (漏斗页 + 明细页) + 聊天里一段摘要; 员工说「写销售周报」触发。
- 需要的前置改动: **改阶段时往时间线记一条** `我方 · 信息 · 阶段 A → B`, 周报才知道本周谁变了阶段 (阶段 1 没记)。

### 10.4 不做

- 不接 ERP / 库存 / 订单状态; 不做审批流 (折扣超权限只是提醒员工找主管, 不拦流程)。
- 报价单不发邮件、不发微信, 只出文件 + 起草附言。

### 10.5 实现备注 (10/12)

- 代码: `sales_pricebook.py` (价格表导入 / 报价单设置 / 公司模板) · `sales_quote.py` (action=quote / quotes, 人民币大写) ·
  `sales_weekly.py` (action=weekly)。全部挂在 `catfish_customer` 下, 不加新工具。
- 存放: `~/.catfish/sales/` 下 `pricebook.json` + `pricebook_source.xlsx` · `quote_settings.json` · `quote_template.xlsx` (可选) ·
  `quotes.json` (报价台账, 版本号和周报从这里数)。生成的文件在 `~/.catfish/outputs/<日期>/`。
- **「系统」时间线行**: 改阶段 (`阶段 A → B`)、生成报价单 (`生成报价单 vN 合计 ¥X (未发出)`) 由工具自己记, channel=系统;
  模型 log 不能用这个 channel; 雷达判「客户在等回复」时跳过这类行 (改阶段不等于回过客户)。
- 生成 ≠ 发出: 生成只记系统行; 员工说已发给客户后小鲶 log kind=报价, 「报价没回音」从那条算。
- 公司模板: 有 `{{商品}}` 的那一行是明细行, 按条数往下复制 (合并单元格跟着挪); 合计用 `{{合计}}` 占位, 不用 SUM 公式。
- 部门 skill `weekly-report` 加了「销售周报不走本 skill」(1.0.1), 需要在 skills-hub 重新发布才生效。

## 11. 阶段 3: 主管视图 (10/12)

- **销售侧** (Companion 设置「🤝 销售跟进 → 发布给主管」, `sales_publish.py`): 员工先看 preview, 点了才把结构化摘要发到
  自己部门 wiki-hub (一条 filename=`catfish/sales-summary.md` 的 wiki, 摘要在 frontmatter `sales_summary:` 一行 JSON)。
  字段: 阶段 / 预计金额 / 最近联系日 / 下一步 + 截止 / 跟进提醒类型 / 报价次数和最近金额 / 全人漏斗。
  **不含**时间线原话、聊天内容、联系人电话邮箱。重发覆盖同一条; 可撤回。
- **wiki-hub** (`sales.py`): 这类条目对同部门普通同事隐藏 (列表不出、按 id 打开 403), 只给本人 / 管该部门的 manager / admin;
  `GET /wiki/sales/dept/{部门}` 返回每人最新一份 + 全组按阶段合计。manager 身份来自 gateway 注入的
  `X-Catfish-User-Managed-Depts` (identity 的 managed_departments)。
- **gateway**: `GET /v1/wiki/sales/dept/{部门}` 先查 `can_manage_department`, 再转 hub; 顺手修了一个洞 ——
  客户端自带的 `x-catfish-user-*` 头 (大小写不同) 以前会原样透传给 hub, 现在一律丢弃。
- **中央 web**: 管理台部门页 (`/admin/departments/:dept`) 明细加「销售漏斗」分段: 客户数 / 金额合计 / 要跟进数,
  各阶段 chips, 全组客户表 (有提醒的排前面)。没人发布时提示销售去哪发。
- **整页分享客户页被拦**: 知识库里客户页的「分享到部门」会被 wiki_publish 拒绝 (时间线是客户原话), 引导走「发布给主管」。
- 没做: 自动定时发布 (要员工每次点, 符合「员工主动 push」); 主管在 Companion 里看 (主管视图在中央 web)。
