# 同事群聊 —— 分步方案

11/5 起草, 同日鸿波定 (§5)。参照 Hermes Agent v0.22.x 的 Desktop Group Chat (多机器人房间、@提及、Lead 路由、共享笔记、
定时任务发到群), 但我们做的是**真人同事 + 各自的小鲶**的群, 不是一群 AI 互相聊 (专家包设计 10/17 已定: 不做 agent 团队互相传话)。

一句话: **群聊是「说事」的地方, 派任务 (`docs/COLLEAGUE-TASK-PLAN.md`) 是「办事」的机制; 群里一句话 → 一张有人负责、
有期限、能收回结果的任务卡, 卡片和进度回到群里。** 群聊建在派任务的邮筒上, 不替代它。

## 0. 统一模型 (守数据边界)

- **中央只转交, 不存群消息**。仍走同事邮筒 `room_link_mailbox`, 照 `CENTRAL-EDGE-DATA-BOUNDARY.md` 的四条:
  payload 不透明、取走即清空、到期清空、只留元数据 30 天、每一封都是员工自己点了才发。
- **一条消息 = 给每个成员各投一封** (跟任务单发给多人一样)。群的聊天记录**只存在每个成员自己电脑上**
  (`~/.catfish/collab_rooms/<room_id>/`), 中央和 web 端都看不到。
- 成员离线: 消息在邮筒里等, 最长 7 天 (超过 7 天没开机的人会缺那段, 界面提示「有一段时间没收到」)。
- 群主说了算: 成员名单、群名、公告只认群主发的; 不是当前成员发来的消息不收 (防冒名, 同派任务的规则)。
- 小鲶在群里**只替自己的主人干活**, 在主人电脑上、用主人的权限; 发到群里的内容主人点了才发 (同审批设计: 发消息每次问)。

新增中央邮筒种类 `ROOM_KINDS` (期限 7 天, 夹在 [10 分钟, 30 天], 单封 ≤ 64KB):

```
room_invite   {v, room_id, name, owner, members[], purpose?}          拉人进群 (对方点「加入」才进)
room_join     {v, room_id, status: joined|declined}                   回群主
room_msg      {v, room_id, msg_id, at, text, mentions[], reply_to?, card?}
room_member   {v, room_id, ver, members[], name?, purpose?, op}       群主改名单 / 改名 / 公告; op: update|disband
room_leave    {v, room_id}                                            自己退群
```

## 1. 第一步: 能用的群聊 (预计 1 个版本)

| 位置 | 内容 |
|---|---|
| 中央 `room_link_db.py` | 加 `ROOM_KINDS`; 老中央不认 → 界面说「中央端版本太旧, 请管理员升级」(同派任务) |
| tool-bridge `colleague_rooms.py` | 本机群账本 + 收发 + 去重 (`msg_id`) + 名单版本号; `pim/croom_*` 给界面 |
| Companion | 「协同」页加「群聊」: 左边群列表 (未读红点), 中间聊天, 右边成员; 建群 / 拉人 (复用 `RecipientPicker`) / 改名 / 退群 / 解散; @某人; 回复某条 |
| 取件频率 | 打开群聊时每 3 秒取一次, 平时 20 秒 (同派任务); 新消息 / @我 发系统通知 |

规则: 一个群最多 50 人; 一条消息 ≤ 4000 字; 这一步不传附件 (长材料用邮件); 后加入的人看不到加入前的记录。

## 2. 第二步: 群里派任务 (派任务和群聊打通, 预计 1 个版本)

- 群里输入框旁加「派任务」, 或直接说「@小鲶 让张三、李四周五前把本周拜访记录交上来」→ 小鲶起草一张任务单,
  收件人从群成员里挑好、截止填好 → 发起人确认 → 走**原来的派任务** (立即 / 定时 / 周期 / 多阶段都能用)。
- 任务卡发到群里 (`room_msg.card = {task_id, title, deadline, assignees}`), 大家都看得到要做什么、给谁做。
- 进度回群: 收件人点「接下」「交回」「不接」时, 除了照旧回给发起人, 同一次点击再往群里发一条只有状态的消息
  (「张三已交回」), 结果正文**仍然只回发起人**。
- 发起人看完结果, 可以点「把汇总发到群里」(自己点了才发)。

**已做 (11/5, Companion 1.2.64):**
- 群里输入框旁「派任务 / 多阶段」; 收件人只能从群里**已加入**的人里勾 (没加入的看不到任务卡)。立即 / 定时 / 周期 / 多阶段都能用。
- 「@小鲶 让张三、李四周五前把拜访记录交上来」→ 不发到群里, 直接打开派任务弹层, 收件人 / 截止 / 内容已填好, 发起人改了再发。
  起草按规则认 (群成员名字带不带 @ 都算; 今天 / 明天 / 后天 / 周X / 下周X / X月X日 / 年-月-日 / 上午下午几点), 不调模型, 认不出的留空。
- 任务卡 (`room_msg.card`) 只认派任务的人自己发的; 收件人算被 @。卡上实时显示每人状态 (还没回 / 在做 / 已交回 / 不接)。
- 状态回群 (`room_msg.status`): 只在收件人**在界面上点**「接下 / 交回 / 不接 / 退出 / 交回某一期」时发, 跟那次点击一起;
  周期任务「每期直接交回」的自动交回**不**往群里发 (自动发群只留给第三步那个经过同意的特例)。只认任务卡上的人报的状态。
- 发起人卡上「看进度和结果」「把汇总发到群里」—— 汇总填进输入框, 自己删改了再点发送。

## 3. 第三步: 小鲶在群里帮忙 (预计 1 个版本)

- 「@小鲶 总结一下今天的讨论 / 整理成待办 / 帮我起草回复」: 自己的小鲶读本机的群记录, 出草稿, 主人点了才发到群里。
- 群公告 / 共享笔记: 群主编辑, 作为 `room_member.purpose` 发给所有人。
- 定时 / 周期任务的结果发到群: 建任务时勾选「每次结果发到群里」(发起人建任务时同意一次), 之后每次结果到了
  由发起人电脑自动转发到群。**这是「每一封都是自己点了才发」的特例** (11/5 鸿波定), 只限这一种: 发起人建任务时明确勾选,
  能随时在任务里关掉; 发出的每一封照样记「数据外发记录」。

## 4. 以后再说

## 5. 已定 (11/5 鸿波)

1. 一个群最多 50 人、单条 ≤ 4000 字、离线最多补 7 天 —— 按建议。
2. 后加入的人看不到加入前的记录 —— 按建议。
3. 定时 / 周期任务的结果自动发到群里 —— **支持, 作为「自己点了才发」的特例** (见 §3)。

## 开发机上一个人怎么测 (11/5)

`scripts/dev_fake_colleague.py` 在本机扮演另一位同事: 用本机身份服务器的密钥现签 1 小时凭证, 只连 127.0.0.1 的中央,
同事的数据放 `~/.catfish-dev-colleagues/<邮箱>/`, 不碰真实 `~/.catfish`。走的是跟真同事一样的邮筒。

```bash
edge/tool-bridge/venv/bin/python scripts/dev_fake_colleague.py chenhongco@xxx rooms     # 收邀请、列群
edge/tool-bridge/venv/bin/python scripts/dev_fake_colleague.py chenhongco@xxx join      # 点加入
edge/tool-bridge/venv/bin/python scripts/dev_fake_colleague.py chenhongco@xxx say "收到 @chenhongbo"
edge/tool-bridge/venv/bin/python scripts/dev_fake_colleague.py chenhongco@xxx watch     # 一直收
```

派任务也能扮演 (一次性任务 / 多阶段里的单段; 定时 / 周期的要在真电脑上建 hermes 定时任务, 工具不扮演):
`tasks` · `task-show` · `task-accept` · `task-done "结果"` · `task-decline "原因"` · `task-assign "要做什么" 邮箱 [--deadline 日期] [--room 群名]`。
接下 / 交回 / 不接走界面按钮同一条路, 群里派的任务群里会出现状态。
