# 同事群聊 —— 分步方案

11/5 起草, 同日鸿波定 (§5)。参照 Hermes Agent v0.22.x 的 Desktop Group Chat (多机器人房间、@提及、Lead 路由、共享笔记、
定时任务发到群), 但我们做的是**真人同事 + 各自的小鲶**的群, 不是一群 AI 互相聊 (专家包设计 10/17 已定: 不做 agent 团队互相传话)。

一句话: **群聊是「说事」的地方, 派任务 (`docs/COLLEAGUE-TASK-PLAN.md`) 是「办事」的机制; 群里一句话 → 一张有人负责、
有期限、能收回结果的任务卡, 卡片和进度回到群里。** 群聊建在派任务的邮筒上, 不替代它。

## 0. 统一模型 (守数据边界)

- **中央只转交, 不存群消息**。仍走同事邮筒 `room_link_mailbox`, 照 `CENTRAL-EDGE-DATA-BOUNDARY.md` 的四条:
  payload 不透明、取走即清空、到期清空、只留元数据 30 天、每一封都是员工自己点了才发。
- **一条消息 = 给每个成员各投一封** (跟任务单发给多人一样)。群的聊天记录**只存在每个成员自己电脑上**
  (`~/.catfish/collab_rooms/<room_id>/`), 中央不留记录、web 端看不到。
  ⚠ 11/6 核对: 「payload 不透明」只是中央程序不解析 —— 投递到取走之间 (最长 7 天) 内容是**明文**存在中央库里,
  能直接登库的人看得到; 传输加不加密看员工填的中央地址 (https / http:8999)。端到端加密见 §4.1。
- 成员离线: 消息在邮筒里等, 最长 7 天 (超过 7 天没开机的人会缺那段, 界面提示「有一段时间没收到」)。
- 群主说了算: 成员名单、群名、公告只认群主发的; 不是当前成员发来的消息不收 (防冒名, 同派任务的规则)。
- 小鲶在群里**只替自己的主人干活**, 在主人电脑上、用主人的权限; 发到群里的内容主人点了才发 (同审批设计: 发消息每次问)。

新增中央邮筒种类 `ROOM_KINDS` (期限 7 天, 夹在 [10 分钟, 30 天], 单封 ≤ 64KB):

```
room_invite   {v, room_id, name, owner, members[], purpose?}          拉人进群 (对方点「加入」才进)
room_join     {v, room_id, status: joined|declined}                   回群主
room_msg      {v, room_id, msg_id, at, text, mentions[], reply_to?, card?}
room_member   {v, room_id, ver, members[], name?, purpose?, op}       群主改名单 / 改名 / 公告; op: update|disband
room_leave    {v, room_id}                                            自己退群
```

## 1. 第一步: 能用的群聊 (预计 1 个版本)

| 位置 | 内容 |
|---|---|
| 中央 `room_link_db.py` | 加 `ROOM_KINDS`; 老中央不认 → 界面说「中央端版本太旧, 请管理员升级」(同派任务) |
| tool-bridge `colleague_rooms.py` | 本机群账本 + 收发 + 去重 (`msg_id`) + 名单版本号; `pim/croom_*` 给界面 |
| Companion | 「协同」页加「群聊」: 左边群列表 (未读红点), 中间聊天, 右边成员; 建群 / 拉人 (复用 `RecipientPicker`) / 改名 / 退群 / 解散; @某人; 回复某条 |
| 取件频率 | 打开群聊时每 3 秒取一次, 平时 20 秒 (同派任务); 新消息 / @我 发系统通知 |

规则: 一个群最多 50 人; 一条消息 ≤ 4000 字; 这一步不传附件 (长材料用邮件); 后加入的人看不到加入前的记录。

## 2. 第二步: 群里派任务 (派任务和群聊打通, 预计 1 个版本)

- (原设想, 已改成下面「已做」的做法) 群里输入框旁加「派任务」, 或直接说「@小鲶 让张三、李四周五前把本周拜访记录交上来」→ 小鲶起草一张任务单,
  收件人从群成员里挑好、截止填好 → 发起人确认 → 走**原来的派任务** (立即 / 定时 / 周期 / 多阶段都能用)。
- 任务卡发到群里 (`room_msg.card = {task_id, title, deadline, assignees}`), 大家都看得到要做什么、给谁做。
- 进度回群: 收件人点「接下」「交回」「不接」时, 除了照旧回给发起人, 同一次点击再往群里发一条只有状态的消息
  (「张三已交回」), 结果正文**仍然只回发起人**。
- 发起人看完结果, 可以点「把汇总发到群里」(自己点了才发)。

**已做 (11/5, Companion 1.2.65): 在聊天里直接派, 不弹窗、不用卡片** (鸿波: 卡片和弹窗多一层, 定时 / 周期 / 多阶段也应该在聊天里一句话说)。
- 照常打字 @ 人。@ 到群里**已加入**的人时, 输入框下面实时显示认出来的:「点「派给@的人」= 派给 张三、李四 · 截止 11/6 18:00」;
  点「派给@的人」(或 Ctrl/⌘+Enter) 才派, 普通「发送」还是普通聊天 (@ 只是提醒)。认不出 / 不完整的 (周期没说结束、定的时间过了、
  某一段没 @ 人) 直接在那行说「派不了: …」, 改那句话就行。按规则认, 不调模型, 不猜:
  - 截止: 今天 / 明天 / 后天 / 周X / 下周X / X月X日 / 年-月-日, 加「上午 / 下午 / 几点 / 几点半」; 只写日子 = 当天 18:00
  - 定时做一次: 写了「定时」, 或「X点做 / 跑 / 发 / 执行」; 「X点前」仍是截止
  - 周期: 每天 / 每个工作日 / 每周X (可多天) / 每月X号 + 时间 (默认 9:00), 结束要说「做N次」或「到年底 / 到月底 / 到X月X日」
  - 多阶段: 「先让@张三 …, 再让@李四 …(, 最后…)」, 每段 @ 的人就是那段的人, 每段可以各写截止
- 群里显示的就是发起人那句话 (`room_msg.card` 带任务编号、派给谁、截止 / 周期), 收件人算被 @; 下面一行每人状态
  (还没回 / 在做 / 已交回 / 不接); 被派到的人在这条消息上点「接下」「交回」「不接」(一次性任务的接下直接生效, 交回 / 不接 / 定时周期的打开原来的处理窗口)。
  多阶段后面几段开始时群里出现「进入第 k 段: …」。只认派任务的人自己发的。
- 状态回群 (`room_msg.status`): 只在收件人**在界面上点**「接下 / 交回 / 不接 / 退出 / 交回某一期」时发, 跟那次点击一起;
  周期任务「每期直接交回」的自动交回**不**往群里发 (自动发群只留给第三步那个经过同意的特例)。只认这条任务上的人报的状态。**结果正文只回发起人。**
- **接下就让小鲶开工** (11/5, 1.2.67; 一次性任务, 群里和「协同事项」里都是): 点「接下」= 1 分钟后小鲶在后台做 (跟定时任务同一个 hermes 入口,
  无人值守: 发邮件 / 发消息 / 派任务 / 删东西一律不做, 写进结果末尾「要你确认的步骤」), 结果只存草稿; 做好了通知「小鲶做好了, 等你核对」,
  群里我这一栏显示「待核对 (小鲶做好了)」, 本人看了点「交回」才发。30 分钟没出来且 hermes 里也没这个任务了 → 通知一次「没做出来」。
  不想后台做: 任务窗口里还有「接下, 在对话里看着小鲶做」(对外动作照常弹确认) 和「接下, 我自己做」。
- 重复接下、交回后「改了再交」不再往群里发第二遍状态。
- **交回文件** (11/5, 1.2.69; 群里派的、「协同事项」里派的都一样): 邮筒单封 64KB、中央不存内容, 文件不走邮筒 ——
  小鲶做好文件后用 `catfish_email_create_draft` (新加 `attachments`) 起草一封发给发起人的邮件带上附件, 只建草稿;
  任务结果写文件要点 + 「文件在发给你的邮件里」, 并记下 `mail_draft_id` / `files`。任务窗口显示「📎 文件在发给 xx 的邮件草稿里」
  + 「打开邮件草稿」, 员工去草稿箱核对、点发送, 再回来点交回。附件只认主目录下、不在隐藏目录里的普通文件
  (小鲶的产出目录 `~/.catfish/outputs` 除外), 最多 10 个、合计 20MB。
- 发起人在自己那条上点「看结果」「汇总发到群里」—— 汇总填进输入框, 自己删改了再点发送。

## 3. 第三步: 小鲶在群里帮忙 (预计 1 个版本)

- 「@小鲶 总结一下今天的讨论 / 整理成待办 / 帮我起草回复」: 自己的小鲶读本机的群记录, 出草稿, 主人点了才发到群里。
- 群公告 / 共享笔记: 群主编辑, 作为 `room_member.purpose` 发给所有人。
- 定时 / 周期任务的结果发到群: 建任务时勾选「每次结果发到群里」(发起人建任务时同意一次), 之后每次结果到了
  由发起人电脑自动转发到群。**这是「每一封都是自己点了才发」的特例** (11/5 鸿波定), 只限这一种: 发起人建任务时明确勾选,
  能随时在任务里关掉; 发出的每一封照样记「数据外发记录」。

**已做 (11/5, Companion 1.2.70):**
- 输入框旁「🐟 小鲶」: 总结最近的讨论 / 整理成待办 (「@谁 做什么 (截止)」, 填进输入框后可以直接「派给@的人」) / 起草回复
  (选了「回复」某条就回那条; 输入框里写的字当要求, 如「委婉拒绝」)。去掉的是「@小鲶 派任务」那种说法 (派任务直接 @ 人), 不是小鲶帮忙。
  小鲶读**本机**最近 200 条群记录, 用员工自己的登录身份调大模型 (JSON-RPC `room/assist`, Companion `colleague_room_assist` 注入令牌和网关,
  跟会议纪要同一条路), 别人的话包在分隔符里只当材料; 只出草稿填进输入框, 员工改好自己点发送。外发记录用途「群聊 · 小鲶总结 / 起草」。
- 群公告: 第一步就有 (群主「改群名 / 公告」, `room_member.purpose`)。
- 定时 / 周期结果自动发群 (**唯一的特例**): 在群里派定时 / 周期任务时, 输入框下面多一个「每次结果自动发到群里」勾选; 任务进群时
  后面标「结果自动发群」, 收件人接之前在任务窗口看到黄字提醒。之后同事每交回一期, 发起人电脑收到时自动转进群
  (`room_msg.auto`, 一个人的一期只转一次, 改了再交不再刷; 只认这张任务卡的发起人、而且卡上写了自动发群的)。
  发起人随时在任务进度里关掉 (`pim/ctask_room_auto_post`)。每一封都进「数据外发记录」, 用途「群聊 · 定时任务结果自动转发」;
  邮筒本身的投递原来在外发记录里显示成「网页请求」, 现在叫「同事协作 · 邮筒」。

## 4. 安全与长期记录 (11/6 方案, 待做)

### 4.0 现状 (11/6 按代码核对)

| 在哪 | 现在 | 问题 |
|---|---|---|
| 中央邮筒 `room_link_mailbox.payload` | 明文 JSON (`forms_net.post` 里 `json.dumps(envelope)`), 取走即清空, 没人取最长 7 天 | 投递到取走之间, 登库的人看得到 |
| 传输 | 跟着员工填的中央地址: `https://…` 加密; `http://IP:8999` 局域网明文 | 部署常见 http:8999 |
| 每人电脑 `~/.catfish/collab_rooms/<群>/messages.jsonl` | 明文、永久保留; 只有群结束后能手动「删除本机记录」; 每次打开整份读一遍、显示最近 300 条 | 电脑丢失 / 备份泄露可读; 聊久了越来越慢 |
| 小鲶 | 只在员工点「🐟 小鲶 总结 / 整理待办」时读本机记录, 用完不存; 不进长期记忆 / 知识库 | (保持) |
| 换电脑 | 迁移清单里 `collab_rooms` 是 Required, 整份带走 | (保持, 加密后连密钥一起迁) |

**界面说法要改** (下个版本先改, 不等加密): 群聊页 / 建群窗口里「中央只转交、看不到内容」不准确 ——
改成「中央只转交、取走即清空, 不保存记录」; 端到端加密做完后再换回「中央看不到内容」。

### 4.1 端到端加密 (邮筒内容, 填表 / 派任务 / 群聊共用)

照手机中转站的做法 (NaCl), 中央库里只剩密文, 管理员也看不到:

- **每台电脑一对密钥** (X25519): Companion 第一次启动生成, 私钥只在本机 (系统钥匙串: macOS 钥匙串 / Windows DPAPI),
  公钥登记到中央。一个人多台电脑 = 多把公钥, 发给他时每台各加密一份。
- **中央公钥目录**: 新表 + 两个接口 (登记我的公钥 / 按邮箱查同事公钥)。目录只存公钥, 不涉内容。
- **发送 / 接收**: `forms_net.post / take` 下面统一一层 —— 发前按收件人每台设备加密 (`crypto_box`, 带发件人身份, 防冒名),
  取到后解密; 信封 `{v: 2, ct, nonce, sender_pk}`。过渡期仍认 `v1` 明文 (老版本同事发来的)。
- **防中央换钥**: 同事公钥第一次见到就记下 (TOFU), 之后变了界面提示「张三换了电脑 / 密钥变了」, 指纹可在成员栏核对。
- **换电脑**: 迁移工具连私钥一起迁 (走现有换机迁移, Secret 级); 没迁的新电脑 = 新密钥, 旧电脑没取走的那几封读不了, 界面说明。
- **对方还没有公钥** (没升级 / 升级后没开过): ⚠ **待定 (鸿波)** —— 建议「拦住不发, 提示对方升级」;
  另一种是过渡期允许明文并在界面标「这条未加密」。

预计: 开发约 1 天 + 端到端测半天 (「扮演同事」工具改成带密钥) + 打包; 动中央 → 中央版本 / 中央包 / 测试服务器都要升。

### 4.2 本机记录保留期限 (✅ 11/6 定: 默认 180 天)

- 每条按消息时间算, **超过 180 天自动从本机删掉** (每次取邮筒时顺手清, 不另起定时)。
- 公司可在中央统一设 (如 90 天 / 1 年) —— 中央只下发「保留几天」一个数, 不碰内容; 群主可给自己的群设得更短, 不能比公司的长。
- 群里派出的任务不受影响: 任务单和交回的结果在「协同事项」里另有记录 (按派任务那边的规则)。
- 群结束 (退群 / 被移出 / 解散) 后, 本机这个群进入同样的倒计时, 期满整群删掉; 「删除本机记录」照旧能马上删。

### 4.3 本机加密保存

- `messages.jsonl` / `room.json` 加密存盘, 密钥放系统钥匙串 (跟 4.1 的私钥同一处保管)。
  电脑丢了、被拷走、备份泄露都读不出来。换电脑走迁移工具 (连密钥)。

### 4.4 聊久了不卡 + 群内搜索

- 按月分文件存 (`messages-2026-11.jsonl` …), 打开群只读最近几百条, 往上翻再加载更早的。
- 群里加搜索框 (搜本机记录, 按人 / 关键词)。

### 4.5 边界与局限 (要跟客户说清楚)

- **送出去的收不回**: 退群 / 被移出 / 离职的人, 本机仍留着已收到的部分 (按 4.2 到期删)。离职交接配合公司 IT 清理那台电脑。
- 小鲶只在员工点了才读群记录, 不自动进长期记忆 —— 里面多半是别人说的话; 觉得某次总结有用, 自己点「存进知识库」。
- 系统通知中心里会留通知原文 (系统行为), 群里有敏感内容时可在设置里关「新消息通知」。

### 4.6 合规归档 (客户提出才做, 默认关)

国企 / 金融类客户可能要求留档备查, 跟「中央不留内容」冲突, 所以只能是可选项: 公司开启后每条群消息额外加密抄送一份到
公司归档库 (只有合规岗的密钥能解), 群里所有人都看得到「本群消息会归档」的提示。

### 4.7 做的顺序

1. 下个版本: 改界面说法 (§4.0)。
2. 同一个版本: 端到端加密 (§4.1) + 保留期限 180 天 (§4.2) + 分月存 / 搜索 (§4.4) —— 都在动同一块存储。
3. 接着: 本机加密保存 (§4.3)。
4. 客户提出再做: 合规归档 (§4.6)。

## 开发机上一个人怎么测 (11/5)

`scripts/dev_fake_colleague.py` 在本机扮演另一位同事: 用本机身份服务器的密钥现签 1 小时凭证, 只连 127.0.0.1 的中央,
同事的数据放 `~/.catfish-dev-colleagues/<邮箱>/`, 不碰真实 `~/.catfish`。走的是跟真同事一样的邮筒。

```bash
edge/tool-bridge/venv/bin/python scripts/dev_fake_colleague.py chenhongco@xxx rooms     # 收邀请、列群
edge/tool-bridge/venv/bin/python scripts/dev_fake_colleague.py chenhongco@xxx join      # 点加入
edge/tool-bridge/venv/bin/python scripts/dev_fake_colleague.py chenhongco@xxx say "收到 @chenhongbo"
```
