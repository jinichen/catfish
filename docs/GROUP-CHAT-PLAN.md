# 同事群聊 —— 分步方案

11/5 起草, 同日鸿波定 (§5)。参照 Hermes Agent v0.22.x 的 Desktop Group Chat (多机器人房间、@提及、Lead 路由、共享笔记、
定时任务发到群), 但我们做的是**真人同事 + 各自的小鲶**的群, 不是一群 AI 互相聊 (专家包设计 10/17 已定: 不做 agent 团队互相传话)。

一句话: **群聊是「说事」的地方, 派任务 (`docs/COLLEAGUE-TASK-PLAN.md`) 是「办事」的机制; 群里一句话 → 一张有人负责、
有期限、能收回结果的任务卡, 卡片和进度回到群里。** 群聊建在派任务的邮筒上, 不替代它。

## 0. 统一模型 (守数据边界)

- **中央只转交, 不存群消息**。仍走同事邮筒 `room_link_mailbox`, 照 `CENTRAL-EDGE-DATA-BOUNDARY.md` 的四条:
  payload 不透明、取走即清空、到期清空、只留元数据 30 天、每一封都是员工自己点了才发。
- **一条消息 = 给每个成员各投一封** (跟任务单发给多人一样)。群的聊天记录**只存在每个成员自己电脑上**
  (`~/.catfish/collab_rooms/<room_id>/`), 中央不留记录、web 端看不到。
  ⚠ 11/6 核对: 「payload 不透明」只是中央程序不解析 —— 投递到取走之间 (最长 7 天) 内容是**明文**存在中央库里,
  能直接登库的人看得到; 传输加不加密看员工填的中央地址 (https / http:8999)。端到端加密见 §4.1。
- 成员离线: 消息在邮筒里等, 最长 7 天 (超过 7 天没开机的人会缺那段, 界面提示「有一段时间没收到」)。
- 群主说了算: 成员名单、群名、公告只认群主发的; 不是当前成员发来的消息不收 (防冒名, 同派任务的规则)。
- 小鲶在群里**只替自己的主人干活**, 在主人电脑上、用主人的权限; 发到群里的内容主人点了才发 (同审批设计: 发消息每次问)。

新增中央邮筒种类 `ROOM_KINDS` (期限 7 天, 夹在 [10 分钟, 30 天], 单封 ≤ 64KB):

```
room_invite   {v, room_id, name, owner, members[], purpose?}          拉人进群 (对方点「加入」才进)
room_join     {v, room_id, status: joined|declined}                   回群主
room_msg      {v, room_id, msg_id, at, text, mentions[], reply_to?, card?}
room_member   {v, room_id, ver, members[], name?, purpose?, op}       群主改名单 / 改名 / 公告; op: update|disband
room_leave    {v, room_id}                                            自己退群
```

## 1. 第一步: 能用的群聊 (预计 1 个版本)

| 位置 | 内容 |
|---|---|
| 中央 `room_link_db.py` | 加 `ROOM_KINDS`; 老中央不认 → 界面说「中央端版本太旧, 请管理员升级」(同派任务) |
| tool-bridge `colleague_rooms.py` | 本机群账本 + 收发 + 去重 (`msg_id`) + 名单版本号; `pim/croom_*` 给界面 |
| Companion | 「协同」页加「群聊」: 左边群列表 (未读红点), 中间聊天, 右边成员; 建群 / 拉人 (复用 `RecipientPicker`) / 改名 / 退群 / 解散; @某人; 回复某条 |
| 取件频率 | 打开群聊时每 3 秒取一次, 平时 20 秒 (同派任务); 新消息 / @我 发系统通知 |

规则: 一个群最多 50 人; 一条消息 ≤ 4000 字; 这一步不传附件 (长材料用邮件); 后加入的人看不到加入前的记录。

## 2. 第二步: 群里派任务 (派任务和群聊打通, 预计 1 个版本)

- (原设想, 已改成下面「已做」的做法) 群里输入框旁加「派任务」, 或直接说「@小鲶 让张三、李四周五前把本周拜访记录交上来」→ 小鲶起草一张任务单,
  收件人从群成员里挑好、截止填好 → 发起人确认 → 走**原来的派任务** (立即 / 定时 / 周期 / 多阶段都能用)。
- 任务卡发到群里 (`room_msg.card = {task_id, title, deadline, assignees}`), 大家都看得到要做什么、给谁做。
- 进度回群: 收件人点「接下」「交回」「不接」时, 除了照旧回给发起人, 同一次点击再往群里发一条只有状态的消息
  (「张三已交回」), 结果正文**仍然只回发起人**。
- 发起人看完结果, 可以点「把汇总发到群里」(自己点了才发)。

**已做 (11/5, Companion 1.2.65): 在聊天里直接派, 不弹窗、不用卡片** (鸿波: 卡片和弹窗多一层, 定时 / 周期 / 多阶段也应该在聊天里一句话说)。
- 照常打字 @ 人。@ 到群里**已加入**的人时, 输入框下面实时显示认出来的:「点「派给@的人」= 派给 张三、李四 · 截止 11/6 18:00」;
  点「派给@的人」(或 Ctrl/⌘+Enter) 才派, 普通「发送」还是普通聊天 (@ 只是提醒)。认不出 / 不完整的 (周期没说结束、定的时间过了、
  某一段没 @ 人) 直接在那行说「派不了: …」, 改那句话就行。按规则认, 不调模型, 不猜:
  - 截止: 今天 / 明天 / 后天 / 周X / 下周X / X月X日 / 年-月-日, 加「上午 / 下午 / 几点 / 几点半」; 只写日子 = 当天 18:00
  - 定时做一次: 写了「定时」, 或「X点做 / 跑 / 发 / 执行」; 「X点前」仍是截止
  - 周期: 每天 / 每个工作日 / 每周X (可多天) / 每月X号 + 时间 (默认 9:00), 结束要说「做N次」或「到年底 / 到月底 / 到X月X日」
  - 多阶段: 「先让@张三 …, 再让@李四 …(, 最后…)」, 每段 @ 的人就是那段的人, 每段可以各写截止
- 群里显示的就是发起人那句话 (`room_msg.card` 带任务编号、派给谁、截止 / 周期), 收件人算被 @; 下面一行每人状态
  (还没回 / 在做 / 已交回 / 不接); 被派到的人在这条消息上点「接下」「交回」「不接」(一次性任务的接下直接生效, 交回 / 不接 / 定时周期的打开原来的处理窗口)。
  多阶段后面几段开始时群里出现「进入第 k 段: …」。只认派任务的人自己发的。
- 状态回群 (`room_msg.status`): 只在收件人**在界面上点**「接下 / 交回 / 不接 / 退出 / 交回某一期」时发, 跟那次点击一起;
  周期任务「每期直接交回」的自动交回**不**往群里发 (自动发群只留给第三步那个经过同意的特例)。只认这条任务上的人报的状态。**结果正文只回发起人。**
- **接下就让小鲶开工** (11/5, 1.2.67; 一次性任务, 群里和「协同事项」里都是): 点「接下」= 1 分钟后小鲶在后台做 (跟定时任务同一个 hermes 入口,
  无人值守: 发邮件 / 发消息 / 派任务 / 删东西一律不做, 写进结果末尾「要你确认的步骤」), 结果只存草稿; 做好了通知「小鲶做好了, 等你核对」,
  群里我这一栏显示「待核对 (小鲶做好了)」, 本人看了点「交回」才发。30 分钟没出来且 hermes 里也没这个任务了 → 通知一次「没做出来」。
  不想后台做: 任务窗口里还有「接下, 在对话里看着小鲶做」(对外动作照常弹确认) 和「接下, 我自己做」。
- 重复接下、交回后「改了再交」不再往群里发第二遍状态。
- **交回文件** (11/5, 1.2.69; 群里派的、「协同事项」里派的都一样): 邮筒单封 64KB、中央不存内容, 文件不走邮筒 ——
  小鲶做好文件后用 `catfish_email_create_draft` (新加 `attachments`) 起草一封发给发起人的邮件带上附件, 只建草稿;
  任务结果写文件要点 + 「文件在发给你的邮件里」, 并记下 `mail_draft_id` / `files`。任务窗口显示「📎 文件在发给 xx 的邮件草稿里」
  + 「打开邮件草稿」, 员工去草稿箱核对、点发送, 再回来点交回。附件只认主目录下、不在隐藏目录里的普通文件
  (小鲶的产出目录 `~/.catfish/outputs` 除外), 最多 10 个、合计 20MB。
- 发起人在自己那条上点「看结果」「汇总发到群里」—— 汇总填进输入框, 自己删改了再点发送。

## 3. 第三步: 小鲶在群里帮忙 (预计 1 个版本)

- 「@小鲶 总结一下今天的讨论 / 整理成待办 / 帮我起草回复」: 自己的小鲶读本机的群记录, 出草稿, 主人点了才发到群里。
- 群公告 / 共享笔记: 群主编辑, 作为 `room_member.purpose` 发给所有人。
- 定时 / 周期任务的结果发到群: 建任务时勾选「每次结果发到群里」(发起人建任务时同意一次), 之后每次结果到了
  由发起人电脑自动转发到群。**这是「每一封都是自己点了才发」的特例** (11/5 鸿波定), 只限这一种: 发起人建任务时明确勾选,
  能随时在任务里关掉; 发出的每一封照样记「数据外发记录」。

**已做 (11/5, Companion 1.2.70):**
- 输入框旁「🐟 小鲶」: 总结最近的讨论 / 整理成待办 (「@谁 做什么 (截止)」, 填进输入框后可以直接「派给@的人」) / 起草回复
  (选了「回复」某条就回那条; 输入框里写的字当要求, 如「委婉拒绝」)。去掉的是「@小鲶 派任务」那种说法 (派任务直接 @ 人), 不是小鲶帮忙。
  小鲶读**本机**最近 200 条群记录, 用员工自己的登录身份调大模型 (JSON-RPC `room/assist`, Companion `colleague_room_assist` 注入令牌和网关,
  跟会议纪要同一条路), 别人的话包在分隔符里只当材料; 只出草稿填进输入框, 员工改好自己点发送。外发记录用途「群聊 · 小鲶总结 / 起草」。
- 群公告: 第一步就有 (群主「改群名 / 公告」, `room_member.purpose`)。
- 定时 / 周期结果自动发群 (**唯一的特例**): 在群里派定时 / 周期任务时, 输入框下面多一个「每次结果自动发到群里」勾选; 任务进群时
  后面标「结果自动发群」, 收件人接之前在任务窗口看到黄字提醒。之后同事每交回一期, 发起人电脑收到时自动转进群
  (`room_msg.auto`, 一个人的一期只转一次, 改了再交不再刷; 只认这张任务卡的发起人、而且卡上写了自动发群的)。
  发起人随时在任务进度里关掉 (`pim/ctask_room_auto_post`)。每一封都进「数据外发记录」, 用途「群聊 · 定时任务结果自动转发」;
  邮筒本身的投递原来在外发记录里显示成「网页请求」, 现在叫「同事协作 · 邮筒」。

## 4. 安全与长期记录 (11/6 方案; 4.1–4.4 已做, 含本机整库加密; Companion 1.2.77 / 中央 019·020)

### 4.0 现状 (11/6 按代码核对)

| 在哪 | 现在 | 问题 |
|---|---|---|
| 中央邮筒 `room_link_mailbox.payload` | 明文 JSON (`forms_net.post` 里 `json.dumps(envelope)`), 取走即清空, 没人取最长 7 天 | 投递到取走之间, 登库的人看得到 |
| 传输 | 跟着员工填的中央地址: `https://…` 加密; `http://IP:8999` 局域网明文 | 部署常见 http:8999 |
| 每人电脑 `~/.catfish/collab_rooms/<群>/messages.jsonl` | 明文、永久保留; 只有群结束后能手动「删除本机记录」; 每次打开整份读一遍、显示最近 300 条 | 电脑丢失 / 备份泄露可读; 聊久了越来越慢 |
| 小鲶 | 只在员工点「🐟 小鲶 总结 / 整理待办」时读本机记录, 用完不存; 不进长期记忆 / 知识库 | (保持) |
| 换电脑 | 迁移清单里 `collab_rooms` 是 Required, 整份带走 | (保持, 加密后连密钥一起迁) |

**界面说法要改** (下个版本先改, 不等加密): 群聊页 / 建群窗口里「中央只转交、看不到内容」不准确 ——
改成「中央只转交、取走即清空, 不保存记录」; 端到端加密做完后再换回「中央看不到内容」。

### 4.1 端到端加密 (邮筒内容, 填表 / 派任务 / 群聊共用)

照手机中转站的做法 (NaCl), 中央库里只剩密文, 管理员也看不到:

- **每台电脑一对密钥** (X25519): Companion 第一次启动生成, 私钥只在本机 (系统钥匙串: macOS 钥匙串 / Windows DPAPI),
  公钥登记到中央。一个人多台电脑 = 多把公钥, 发给他时每台各加密一份。
- **中央公钥目录**: 新表 + 两个接口 (登记我的公钥 / 按邮箱查同事公钥)。目录只存公钥, 不涉内容。
- **发送 / 接收**: `forms_net.post / take` 下面统一一层 —— 发前按收件人每台设备加密 (`crypto_box`, 带发件人身份, 防冒名),
  取到后解密; 信封 `{v: 2, ct, nonce, sender_pk}`。过渡期仍认 `v1` 明文 (老版本同事发来的)。
- **防中央换钥**: 同事公钥第一次见到就记下 (TOFU), 之后变了界面提示「张三换了电脑 / 密钥变了」, 指纹可在成员栏核对。
- **换电脑**: 私钥**不随迁移包走** (换机迁移里 `collab_keys` 是 Secret 级, 跟别的凭证一样: 包丢了也不泄露); 新电脑第一次取邮筒时
  生成新密钥并登记, 同事群里提示一次「密钥变了」; 换之前发给旧电脑、还没取走的那几封新电脑读不了。
- **密钥文件** (11/6 实现时定): 放 `~/.catfish/collab_keys/device.json` (0600), 不放钥匙串 —— tool-bridge 读钥匙串在 macOS 上会弹看不见的
  授权框 (companion_secrets.py 文件头)。原定本机加密 (§4.3) 时一起挪进钥匙串, **做的时候改了主意, 不挪**:
  钥匙串里的东西只有 Companion 开着时 tool-bridge 才拿得到 (§4.3「密钥怎么到 tool-bridge」), 而邮筒收发不只在 Companion 里 ——
  定时 / 周期任务交结果、小鲶接下任务后在后台做完交回, 都在 Companion 没开的时候走 `forms_net`; 私钥锁进钥匙串, 这些就会断。
  私钥文件只有本人可读, 换电脑不随迁移包走; 电脑丢失时的风险靠系统磁盘加密兜 (§4.3 表里第三行)。
- **对方还没有公钥** (没升级 / 升级后没开过): ✅ 11/6 定 **拦住不发** —— 那个人记进「没送到」, 原因写「还没升级到能加密的版本
  (或升级后还没打开过鲶鱼)」; 群里别的已有公钥的人照常收到。收到老版本发来的明文 (`v1`) 照收, 界面标「未加密」。

**✅ 已做 (11/6)** —— 实际做法 (`edge/tool-bridge/.../mailbox_crypto.py` 文件头有全文):
X25519 静态-静态 DH → HKDF-SHA256 → ChaCha20-Poly1305 (用已有的 `cryptography` 库, 不加依赖); 内容先 zlib 再用随机内容密钥加密,
内容密钥给收件人每台电脑各包一份; 附加数据 = 种类 | 发件人 | 收件人 (中央改了 from / to 解密就失败)。
信封 `{v: 2, alg, sd, spk, z, n, c, k: [{d, n, w}]}`; 发件人公钥必须在中央目录或本机记下的里面。
中央: 表 `room_link_keys` (迁移 019), 接口 `PUT / GET /api/room-link/keys`; 邮筒单封上限 64KB → 128KB (密文 + 每台设备一份包装)。
中央是老版本 (没有公钥接口) 时提示「中央端版本太旧, 还不支持加密传输」。

原预计: 开发约 1 天 + 端到端测半天 (「扮演同事」工具改成带密钥) + 打包; 动中央 → 中央版本 / 中央包 / 测试服务器都要升。

### 4.2 本机记录保留期限 (✅ 11/6 定: 默认 180 天; ✅ 已做 `colleague_rooms_retention.py`)

- 每条按消息时间算, **超过期限自动从本机删掉** (同步时顺手清, 最多 10 分钟一次, 不另起定时; 改了设置马上清一次):
  本机库 (§4.3) 里一条 `DELETE FROM messages WHERE at < 期限`; 已读位置按 seq 记, 删旧消息不错位。
- **在哪设**:

  | 层级 | 在哪设 | 规则 |
  |---|---|---|
  | 默认 | 代码常量 `ROOM_RETENTION_DEFAULT = 180` | 没人设时用 |
  | 公司 | 中央管理门户「系统 → 协作设置」(管理员) | 表 `org_policy` (迁移 020); `GET /api/org/policy` → `{room_retention_days}` (登录员工可读), `PUT /api/admin/org/policy` (管理员), 范围 7–3650 天。Companion 最多每小时取一次, 取不到用上次的; 老中央 (404) 按默认。中央只下发这个数, 不碰内容 (以后别的公司级设置也走这张表) |
  | 群 | 群主在「改群名 / 公告」窗口的「本群记录在每个人电脑上保留」下拉 | 只能比公司的短; 跟群名一起随 `room_member` 通知所有成员 (`retention_days` 字段), 群里留一句改动提示 |
  | 个人 | 群聊页左上「记录保留」按钮 (11/6 实现时改到这里: 跟群聊放一起好找; 存本机库 meta `personal_retention_days`) | 只能比公司 / 默认更短; 改短时提示会马上删掉多早以前的记录 |

  **生效 = 取最短** (例: 公司 1 年、群主 90 天、个人没设 → 90 天)。群信息里写明「本群记录在你电脑上保留 90 天 (群主设置)」, 谁定的看得见。
  只能往短里调, 不能突破公司上限; 公司还没设 (老中央 / 没配) 时按默认 180 天。
- 群里派出的任务不受影响: 任务单和交回的结果在「协同事项」里另有记录 (按派任务那边的规则)。
- 群结束 (退群 / 被移出 / 解散) 后, 本机这个群进入同样的倒计时, 期满整群删掉; 「删除本机记录」照旧能马上删。

### 4.3 本机记录改存 SQLite (11/6 定) + 本机加密

现在每个群一个 `messages.jsonl` + `room.json`: 每次打开整份读、删旧消息要整份重写、靠加锁防并发写坏 (11/5 那次「.tmp 找不到」)。
改成**一个本机库** `~/.catfish/collab_rooms/rooms.db`:

- 表 (✅ 11/6 已做, `colleague_rooms_store.py`): `rooms` (room_id × 群的 JSON: 名字 / 公告 / 群主 / 成员 / 我的状态 / 已读到哪) ·
  `messages` (seq 自增 × 群 × msg_id × 种类 × 发件人 × 时间 × 正文 × 整条 JSON, `UNIQUE(群, msg_id)`) · `meta` (上次取邮筒时间 / 公司设置缓存 / 个人保留天数)。
  成员没单独建表 (一个群几十人, 跟群 JSON 放一起够用); 没建 FTS5 —— 搜索见 §4.4。
- 索引 `(room_id, seq)` / `(at)`; WAL 模式, 写都在事务里, 每次调用一个连接 —— 并发写坏的那一类问题没了。
- 不加依赖: tool-bridge 是 Python 自带 `sqlite3`, Mac / Windows 一样; 仓里已有同样用法 (`~/.catfish/outbound_log.db` 数据外发记录)。
- **升级迁移**: 第一次启动把现有 `messages.jsonl` / `room.json` 导进库 (按 msg_id 去重), 原文件改名留作备份 (`.migrated`), 下个大版本再删。
- 换电脑迁移清单: `collab_rooms` 仍是 Required (整目录, 含 `rooms.db`; 加密后连 §4.1 的密钥一起迁)。
- 只放群聊。派任务 / 填表的本机记录量小、不用搜, 先不动, 以后要统一再迁。

**本机加密** (库文件加密存盘, 电脑丢了 / 被拷走 / 备份泄露读不出来), 三种做法:

| 做法 | 能不能搜 | 代价 |
|---|---|---|
| SQLCipher 整库加密 (密钥放系统钥匙串, 跟 §4.1 私钥同处) | 能 | 要带加密版 SQLite (Python 绑定 + 原生库), Mac 两种芯片 / Windows 都要打进安装包 —— **先验证** |
| 只加密 `messages.text` 等正文列 | 不能 (FTS 用不了) | 不加依赖 |
| 靠系统磁盘加密 (FileVault / BitLocker) | 能 | 我们不做, 靠公司 IT 开; 防不了单个文件被拷走 |

定: **先上 SQLite (不加密), 同时验证 SQLCipher 能不能顺利打进三个安装包** —— 能就用它 (加密和搜索都保住); 不行退「只加密正文」, 那样就不做搜索。

**SQLCipher 验证结果 (11/6)**: ✅ 能进三个安装包, 用 `sqlcipher3==0.6.4` (PyPI, 2026-10-13 发布)。
- 三个目标都有现成 CPython 3.14 轮子: `macosx_11_0_arm64` / `macosx_10_15_x86_64` (Intel 最低 10.15, 跟安装包一致) / `win_amd64`, 各 2.5–3 MB。
  按打包脚本的办法 (`uv pip compile --python-platform … --only-binary`, 带 sha256) 三个都解析得出 —— 接入只要在
  `src-tauri/hermes-extra-packages.txt` 加一行 `sqlcipher3==0.6.4  sqlcipher3`, 跟着 wheelhouse 走, 员工机器离线装。
- 静态链接: Mac 的 .so 只依赖系统 `libSystem`; Windows 的 .pyd 只依赖系统 DLL + `python314.dll` / `VCRUNTIME140.dll` (内嵌 Python 自带)。
  不用另带 OpenSSL / SQLCipher 原生库。
- 实测 (arm64 本机 + Intel 用 Rosetta 跑 x86_64 的 CPython 3.14): SQLite 3.53.4 / SQLCipher 4.19.0 community / OpenSSL 3.6.0;
  WAL 正常; 库文件里没有明文; 不给密钥打不开 (`file is not a database`); 中文 `LIKE` 正常; FTS5 trigram 也能用 (以后要全文索引可以直接上);
  `sqlcipher_export` 能把现在的明文库原样转成加密库 (升级迁移就用它)。
- **WAL 损坏漏洞闸** (`scripts/check-embedded-sqlite.py` 同判据): 3.53.4 不在有洞区间 ✅。
  另一个包 `sqlcipher3-wheels 0.5.7` 带的是 SQLite 3.51.1 —— **有洞, 不能用**。
- 许可: sqlcipher3 是 zlib 许可, SQLCipher Community 是 BSD 类, OpenSSL 3 是 Apache 2.0 —— 商用打包都可以, 附带许可文本即可。
- Windows 真机: 本机没有 Windows, 自检脚本 `scripts/smoke_sqlcipher.py` 已加进 `smoke-windows-runtime.ps1` —— 每次在 CI 上打 MSI 时
  用打进包的解释器在真 Windows 上跑一遍, 不过就不出包。Mac 两种芯片在 `build-mac-resources.sh` 里同样跑一遍。

**✅ 本机整库加密已做 (11/6, Companion 1.2.77)**:
- **密钥**: 32 字节随机数, 存系统钥匙串 (service `catfish-collab-rooms` / account `rooms-db-key`), Companion 第一次调群聊时生成
  (`src-tauri/src/services/rooms_db_key.rs`)。只有 Companion 读。
- **密钥怎么到 tool-bridge**: Companion 每次调 `pim/croom_*` / `room/*` / `pim/ctask_*` 时把密钥带在参数 `_rooms_key` 里
  (tool_bridge_rpc 统一塞), tool-bridge `server.py` 进门就摘掉、记在内存 (`colleague_rooms_crypt.py`), 不往下传、不进日志。
  没有反向去钥匙串取 (那条会弹看不见的授权框), 也不在 Windows 上让 Python 另读一份 (两种语言的钥匙串条目名对不齐)。
  tool-bridge 重启后、Companion 下一次调用前, 后台想写群 (定时任务结果自动转群) 会因为「锁着」失败, 只记日志, 不影响收结果。
- **库**: SQLCipher 4 原始密钥 (`PRAGMA key = "x'…'"`, 不走口令派生, 每次开连接 0.3 毫秒), WAL 照旧。
- **升级**: 第一次拿到密钥时把明文库原样转成加密库 (`sqlcipher_export`, 三张表条数核对一致才替换), 明文旧文件 + 老格式备份
  (`r_*.migrated/`、`_sync.json.migrated`) 一起删掉 —— 留着明文备份就白加密了。转的时候等正开着的连接都关掉 (Windows 换不了开着的文件)。
- **什么时候还是明文**: 加密组件没装上 (老机器升级后启动自检会按 `hermes-extra-packages.txt` 补装), 或者还没拿到密钥 ——
  明文库照常用, 「记录保留」窗口里写明「本机记录还没加密」和原因。**已经加密的库**缺密钥 / 缺组件 / 密钥不对就打不开, 明说原因,
  不退回明文。
- **换电脑**: 迁移包 (age 口令加密) 里带上这把密钥 (manifest `collabRoomsKey`), 新机导入时写进它的钥匙串; 新机原来那把另存为
  `rooms-db-key.before-<时间>` (覆盖导入时新机原数据挪去了备份目录, 备份里的库要用原来那把)。加密的库 Companion 自己打不开、
  做不了快照, 导出前先请 tool-bridge 做一份 (`pim/croom_snapshot`, `VACUUM INTO`, 快照同样是加密的); tool-bridge 没起来就提示稍后再导。
- 界面: 「记录保留」窗口显示「🔒 本机记录已加密存放」或「🔓 还没加密: 原因」。

### 4.4 聊久了不卡 + 群内搜索

✅ 11/6 已做:
- 打开群只取最近 300 条 (`ORDER BY seq DESC LIMIT 300`), 顶上「加载更早的 (N 条)」再按 seq 往前取一页 —— 不再整份读, 也不用按月分文件。
- 群头「🔍 搜索」: 搜本机记录, 可按人筛, 新的在前最多 50 条; 点一条跳到那条前后各 30 条, 「回到最新」回来。
  **用 `LIKE` 不用 FTS5** (实现时改的): FTS5 默认分词对中文不友好 (要么整句一个词, 要么得自带分词器), `LIKE` 能搜任意长度的中文片段;
  一个群保留期内几万条, 扫一遍毫秒级。以后量真大了再加 FTS5 trigram。

### 4.5 边界与局限 (要跟客户说清楚)

- **送出去的收不回**: 退群 / 被移出 / 离职的人, 本机仍留着已收到的部分 (按 4.2 到期删)。离职交接配合公司 IT 清理那台电脑。

公司归档库 (只有合规岗的密钥能解), 群里所有人都看得到「本群消息会归档」的提示。

## 4.8 借鉴 hermes 群聊的四样 (11/07, Companion 1.2.109)

对照 hermes 0.23 的 Group Chat (`gateway/hosted_room_*`) 挑了四样, 其余 (AI 自动分派、讨论轮数上限、远程驱动别人的 AI、
多副本接管) 是给「一台机器上几个 AI 轮流发言」用的, 不照搬。

1. **没送到的看得见、能补** (参照它的 prepare_stall: 连续失败在群里说一句、给重试) —— `colleague_rooms_outbox.py`。
   每封没送到的信记一行 (本机库 `outbox` 表, 信封原样存着, 补发时重新加密), 挂在那条消息 / 系统提示下面:
   对方没公钥 → 每 10 分钟看一次, 登记了就补 (7 天为限); 连不上中央 → 1 / 5 / 15 分钟各补一次, 还不行显示「没送到 · 重发」;
   中央太旧 → 群名下面一条细横条, 每小时试; 别的 (403 / 内容太长) → 直接「没送到 · 重发」。
   原来顶上那行红字 (插在群名和聊天之间, 写邮箱 + 原始报错, 换个群就没了) 去掉, 原始报错放鼠标悬停里。
   收件人已经不在群里的不补。1.2.109 之前只记了 `undelivered` 的老消息也显示「没送到 · 重发」, 重发时按消息重拼信封。
2. **群主转让** (参照它的 authority epoch: 换主持 + 版本号) —— `transfer`: 新群主必须已加入, 名单版本 +1 带 `owner` 通知所有人,
   之后只认新群主发的名单 / 群名 / 解散。群主转了才能退群。原群主电脑坏了 / 人走了、没来得及转的: 这一步帮不上 (没有中央裁决),
   群照样能聊, 只是没人能改名单。
3. **群里发文件** (参照它的附件: 消息只带编号, 内容另存, 发送那一刻定好给谁) —— `colleague_rooms_files.py`。
   不开新的中央接口: 文件切 80KB 一块, 每块装进一封普通 `room_msg` (`chunk`), 照样端到端加密 (实测 80KB 随机内容、
   收件人 10 台电脑, 加密后 109KB < 128KB 上限), 期限 7 天; 分块排进 outbox 后台发。消息带清单 `files: [{id, name, size, sha256, n}]`,
   收件人收齐、核对 sha256 才算收到, 存在本机库 `files` 表 (库整库加密, 不落明文文件); 点「打开」才写到
   `~/Downloads/鲶鱼群文件/<群名>/` 用默认程序开。邮筒取走即清空, 取的时候断了会丢块 → 收件人 10 分钟没新块就给发件人发 `need`,
   发件人电脑自动补 (同一个人同一个文件最多 3 轮)。上限: 一条 5 个文件、合计 5MB。文件跟着消息的保留期删。
4. **小鲶后台做到哪了** (参照它把成员 AI 的实时进度单独推出来、不进群记录) —— 接下就开工的任务, 读 hermes `state.db` 里
   `cron_<job_id>_*` 会话 (只读), 显示「小鲶在做 · 第 3 步 搜邮件「拜访记录」」, 只在本人自己的群聊任务卡和「协同事项」里。

顺带: 登记公钥 `PUT /api/room-link/keys` 在数据外发记录里原来显示成「网页请求」, 现在是「同事协作 · 加密公钥」; 群文件是「群聊 · 发文件」。

## 4.9 群里发大文件 (11/07, Companion 1.2.110 + 中央迁移 021)

鸿波: 要能发 20MB 以上的。邮筒分块 (§4.8 第 3 条) 是「每人各投一份、收件人一次取完」, 不适合大文件。改成:

- 一条消息合计 **≤ 5MB 照旧走邮筒分块** (老中央也能发); **超过 5MB 走中央暂存一份**, 单个 / 合计 200MB (跟 nginx 上传上限一致,
  中央 `CATFISH_ROOM_BLOB_MAX_MB` 可改)。
- 发件人电脑: 随机钥匙 K, 1MB 一块 ChaCha20-Poly1305 加密 (nonce = 块号, 附加数据 = 文件编号), 密文先存本机
  `~/.catfish/collab_rooms/blobs/<文件编号>.bin`; 中央 `POST /api/room-link/blobs` 建暂存 (收件人 = 发送那一刻已加入的人,
  建不了整条消息不发) → 群消息照常端到端加密发出, 文件清单带 `{blob: {id, key}}` → 后台一块块 `PUT`, 断了接着传, 传完 `finish`。
- 收件人电脑: 记一行等着, 后台看传完没, 传完一块块 `GET` 到本机 .bin, 解一遍核对 sha256, 对了 `taken`; 中央见大家都取完就删内容,
  不然 7 天到期删; 元数据留 30 天审计。中央每人同时暂存上限 2GB (`CATFISH_ROOM_BLOB_QUOTA_MB`)。
- 中央只有密文和「谁发的、给谁、多大、几块」; K 只在那封端到端加密的群消息里, 本机 .bin 也是密文、K 在本机加密库里。
- Companion 传文件给本机: 先 1MB 一段「暂存」(`pim/croom_stage`, RPC 一行最多 16MB), 进度显示在发送按钮上; 暂存放一天没发清掉。
- 老中央 (没有 021): 超 5MB 的直接报「中央端版本太旧」, 一封不发; 5MB 以内照常。

## 开发机上一个人怎么测 (11/5)

`scripts/dev_fake_colleague.py` 在本机扮演另一位同事: 用本机身份服务器的密钥现签 1 小时凭证, 只连 127.0.0.1 的中央,
同事的数据放 `~/.catfish-dev-colleagues/<邮箱>/`, 不碰真实 `~/.catfish`。走的是跟真同事一样的邮筒。

```bash
edge/tool-bridge/venv/bin/python scripts/dev_fake_colleague.py chenhongco@xxx rooms     # 收邀请、列群
edge/tool-bridge/venv/bin/python scripts/dev_fake_colleague.py chenhongco@xxx join      # 点加入
edge/tool-bridge/venv/bin/python scripts/dev_fake_colleague.py chenhongco@xxx say "收到 @chenhongbo"
edge/tool-bridge/venv/bin/python scripts/dev_fake_colleague.py chenhongco@xxx watch     # 一直收
```

派任务也能扮演 (一次性任务 / 多阶段里的单段; 定时 / 周期的要在真电脑上建 hermes 定时任务, 工具不扮演):
`tasks` · `task-show` · `task-accept` · `task-done "结果"` · `task-decline "原因"` · `task-assign "要做什么" 邮箱 [--deadline 日期] [--room 群名]`。
接下 / 交回 / 不接走界面按钮同一条路, 群里派的任务群里会出现状态。
