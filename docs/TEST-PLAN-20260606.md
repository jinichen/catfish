## Section 1 · Approval button 正向 path (P15 系列核心)

### Test 1.1 · 基础 execute_code approval
- **Steps**:
  1. Companion 新建 chat
  2. 发: `请用 execute_code 跑 import os; print(os.getcwd())`
  3. 等 LLM 转圈 (`...`)
  4. ChatInput 上方应弹 floating banner: `⚠️ hermes 等批准: execute_code`
  5. 点 `✓ 批准`
- **Expected**:
  - banner 消失
  - execute_code ✓ done
  - LLM 给出真实 cwd `/Users/chenhongbo` (不是编的)
- **agent.log 检查**:
  ```
  grep -E "P15.2 chat_approval resolved" ~/.hermes/logs/agent.log | tail -3
  # 期望见 resolved=1 choice=once sid=20260606_xxx
  ```

### Test 1.2 · `✓ 始终批准` (always)
- **Steps**:
  1. 新 chat 发: `请用 execute_code 跑 import subprocess; subprocess.run(['curl','https://example.com'])`
  2. banner 弹后点 `✓ 始终批准`
  3. 同 session 再发: `请用 execute_code 跑 import subprocess; subprocess.run(['curl','https://google.com'])`
- **Expected**:
  - 第 1 次: banner 弹, 点击后 tool 真跑
  - 第 2 次: **banner 不弹** (always 已 whitelist 该 pattern), tool 直接跑
- **agent.log**:
  ```
  P15.2 chat_approval resolved=1 choice=always
  ```

### Test 1.3 · `✗ 拒绝` (deny)
- **Steps**:
  1. 新 chat 发: `请用 execute_code 跑 import os; os.system('echo dangerous')`
  2. banner 弹后点 `✗ 拒绝`
- **Expected**:
  - banner 消失
  - execute_code ✓ done (但 result 含 "BLOCKED: execute_code script denied by user")
  - LLM 看 BLOCKED message, 回复"被拒绝了"或换思路
- **agent.log**:
  ```
  P15.2 chat_approval resolved=1 choice=deny
  ```

### Test 1.4 · `✓ 本会话批准` (session)
- **Steps**:
  1. 新 chat 发 execute_code
  2. 点 `✓ 本会话批准`
  3. 同 session 再发同样 code
  4. **新 chat** 发同样 code
- **Expected**:
  - 步骤 2/3: 同 session whitelist, 不再弹 banner
  - 步骤 4: 新 session, banner 重新弹 (session 级 ≠ always 全局)

## Section 2 · 边界 / 异常场景

### Test 2.1 · LLM 转圈期间用户取消 (Cmd+. 或停止按钮)
- **Steps**:
  1. 发 execute_code, banner 弹
  2. **不点 banner**, 点 Companion 输入框上方"停止"
- **Expected**:
  - stream 中断
  - hermes _gateway_approval 等 60s timeout → fallback 返 "BLOCKED: timed out"
  - banner 不再有效 (点了应该没反应或显错)
- **agent.log**: 见 `decision timeout`

### Test 2.2 · 同时 2 个并发 chat 都触发 approval
- **Steps**:
  1. 打开 chat A, 发 execute_code → banner 弹
  2. **切换到 chat B**, 发 execute_code → banner 应也弹
  3. 切回 chat A, 点 `✓ 批准`
  4. 切回 chat B, 点 `✓ 批准`
- **Expected**:
  - 2 个 banner 独立, 不互相干扰
  - 各自 resolve 自己的 session_id (`approval_session_key` 字段 ≠)
- **agent.log**: 见 2 条 `P15.2 chat_approval resolved` 用不同 sid

### Test 2.3 · 多 tool 一轮 LLM call 内并发
- **Steps**:
  1. 发: `请并发跑: 1) execute_code 跑 print(1) 2) terminal 跑 echo hello`
  2. 看是否 2 个 banner 都弹 (或 1 个 banner 序列化处理)
- **Expected**:
  - hermes 实际 dispatch tool 是串行 (一个 done 再下一个), 所以 banner 应该串行弹
  - banner 1 → 点批准 → tool 1 跑完 → banner 2 弹 → 点批准 → tool 2 跑完
- **Note**: 如果 hermes 并行 dispatch, P15 _approval_notify 可能同时 fire 2 次, stream_q 是 FIFO, banner state 只存最后一个. 这条 case 揭示 P15 多 tool 并发 BL.

### Test 2.4 · 拒绝后 LLM 重发同 code
- **Steps**:
  1. 发 execute_code, banner 弹后点 `✗ 拒绝`
  2. LLM 回复后**继续发**: `重新跑一次`
  3. LLM 重新调 execute_code 同 code
- **Expected**:
  - banner **再次弹** (deny 不 whitelist)
  - 用户可选择再批准或拒绝
