# 鲶鱼 Roadmap

> 给客户看的产品演化路线图. 5 月 demo 收尾时翻到这一页, 让客户感受到"鲶鱼是持续演进的组织 AI 基础设施, 不是一锤子工具".

---

## 一句话定位

**鲶鱼是企业员工的 AI 副手 + 组织 AI 基础设施**.
不是聊天工具, 是工作流自动化 + 跨员工知识沉淀.

---

## 4 个 Phase

### Phase 1 · 单员工 AI 副手 (现在 ship 中, 2026 Q1-Q2)

员工日常工作流自动化, 中央可审计.

- ✅ 内网系统打通 (EIS / OA / 飞书 / 邮件 / CRM)
- ✅ 跨厂商 LLM 路由 (qwen / gemini / 私有 / 你们自己的)
- ✅ 凭据安全 (密码存 Keychain, 永远不进 LLM 上下文)
- ✅ 中央审计 (token 用量 / 模型分布 / 安全事件, **看不到对话内容**)
- ✅ 5-8 个业务 skill (资质数据导出 / 周报 / 汇报材料排版 / ...)

→ **5 月演示这一阶段**, 拿 1-3 家 PoC 客户

---

### Phase 2 · 团队版 (2026 Q3)

部门级管理 + 多员工协作雏形.

- SSO 多用户 (飞书 / 钉钉 / 企微 / 你们自建 SSO)
- RBAC 部门权限隔离 (经理看部门数据 / 员工看自己)
- Quota 配额管理 (按部门 / 按人 / 按模型)
- **Skill share** (Plan D 入门): A 员工教鲶鱼的流程, 自动推给同部门同事
- Win 跨平台 (Mac + Win 全覆盖)

→ 客户从"试用鲶鱼" 到 "部署给整个部门"

---

### Phase 3 · ★ Catfish Federation (2026 Q4 - 2027 Q1)

**鲶鱼真正的护城河 — 跨员工 Agent-to-Agent 协作**.

- 你的鲶鱼能跟同事的鲶鱼**直接对话** (隐私边界严格)

  ```
  例 1: 你: "问下张三老板对项目 X 怎么看, 我下午要汇报"
        → 你的鲶鱼 → 张三的鲶鱼 → 张三公开授权的偏好答复
        → 你拿到答复, 不打扰张三
  
  例 2: 部门一员工教鲶鱼"我们部门标准报销流程"
        → 鲶鱼之间自动学习 → 全部门 50 人的鲶鱼下一秒都会
        → 部门集体知识沉淀 (员工离职带不走)
  ```

- 严格隐私: A 的鲶鱼**只回答** A 显式授权过的事, 默认拒绝
- Federation 协议: agent identity (基于 SSO) + mutual auth + audit

→ **SaaS 做不到这件事** (它们是中心化的, 没有"边缘 agent" 概念)
→ **同质化国内产品没设计** (没组织层 / 没隐私层)

---

### Phase 4 · 集团级网格 (2027 Q2+)

跨部门 / 跨子公司的 agent mesh.

- 集团级 skill 库 (各子公司贡献, 中央审核, 集团内复用)
- 跨部门 agent 协作 (打破部门信息墙)
- 集团审计中心 (合规 / 风控 / 数据治理一次到位)

→ 适合大型集团 / 央国企 / 跨国公司

---

## 商业模式

- **一次性 license** + 年度维护 (按部署规模)
- **私有化部署** (你们自己的机房 + 你们自己的 LLM)
- **不抽 API 流水**: 员工怎么用都不收 token 费, 你们用自己的 LLM
- **客户 IT 自审**: 中央 audit / 配置 / 身份系统全部开源给客户 IT 检查

---

## 跟竞品的差距

| 维度 | 鲶鱼 | SaaS Agent (ChatGPT 类) | 国内同质化产品 |
|---|---|---|---|
| 部署 | ★ 私有化, 数据不出公司 | 公网 SaaS | 部分私有化 |
| 数据流 | ★ 对话全程在员工本机 | 全部上传 | 中央存对话 |
| LLM 选择 | ★ 任意厂商, 随时切 | 锁定单厂商 | 锁定单厂商 |
| 中央可审 | ★ 看 metadata 不看内容 | 客户看不到 audit | 全看或全不看 |
| 跨员工协作 | **★★ Phase 3 Federation** | ❌ 无组织层概念 | ❌ 无设计 |
| 业务 skill | ★ 员工教的流程沉淀 | 通用 chat | 单 skill 库 |

> **Phase 3 Catfish Federation 是真正护城河**:
> SaaS 永远做不到 (它们是中心化架构, 改不出来),
> 国内同质化产品没设计这层 (它们是工具不是基础设施).
> 我们 12 个月内 ship 这个能力 → 客户长期被锁定.

---

## 为啥相信我们能交付

- 现在 ship 的 Phase 1 已经覆盖 90% 单员工场景
- Phase 2 的 SSO / RBAC 是成熟工程问题, 5 月 demo 后立即开干
- Phase 3 的 Federation 是**已经在我们 BACKLOG 上的设计** (BL-E17 / BL-E18, IDEAS #16+#42), 不是临时想出来糊客户
- 团队规模虽小, 但**架构选型已经为 Phase 3 留好接口** (gateway 三层架构 / identity 层独立 / SSO 是 Phase 3 前置)
