# PoC 落地标准化方案

> 5 月 demo 后客户说"我们想试" → 给客户这一份, 1-2-3 周时间表 + 每周交付物 + 验收标准.
> 客户能看到具体计划 → 决策更快.

---

## 总原则

- **小步快跑**: 1 周内必须有"看得见摸得着"的进展, 不让客户等
- **客户参与**: PoC 期间客户 IT 出 1 人配合 (50% 时间), 我们 1 人驻场或远程
- **明确成功标准**: 每周末有验收 demo, 客户拍板"通过 / 不通过"
- **风险控制**: 任何一周客户 say no, PoC 立即停, 双方不绑死

---

## Phase 1A: 准备期 (Week 1, 5 天)

### 目标

环境就绪 + SSO 接通 + 1 个员工能登录 Companion.

### 任务

| 谁 | 做什么 | 交付物 |
|---|---|---|
| **客户 IT** | 准备 1 台 Mac (M1+, 16GB+, macOS 14+) | 测试机 |
| **客户 IT** | 给 SSO 接入信息 (issuer / client_id / jwks_uri) | 邮件确认 |
| **客户 IT** | 加 1 个员工到 SSO 能登录 catfish 的 ACL | LDAP entry |
| **我们** | 装 catfish-gateway / catfish-identity / Companion | 4 卡片全绿 |
| **我们** | 配 .env / models.yaml / users.yaml | 配置文件 |
| **我们** | 接入客户 SSO 跑 1 次端到端 | curl 拿 access_token 成功 |

### 验收 (Week 1 末)

- [ ] 1 个员工浏览器登录 Companion → 看到主界面
- [ ] Companion 仪表盘 4 卡片全绿
- [ ] curl 调 gateway /v1/catalog 返 authenticated:true
- [ ] audit JSONL 有数据

**不通过 → PoC 暂停, 排查 SSO 或网络问题, 不浪费客户时间**

---

## Phase 1B: 基础适配 (Week 2-3, 10 天)

### 目标

接入客户 1 个内网系统 (优先级最高的) + 跑通 1 个业务 skill.

### 任务

#### Week 2

| 谁 | 做什么 | 交付物 |
|---|---|---|
| **客户 IT** | 给我们 1 个内网系统的访问 (例 EIS) | 测试账号 |
| **我们 + 客户** | 调研内网系统的 selector / API / 字段 | 一份字段映射表 |
| **我们** | 写第 1 个业务 skill (适配客户系统) | SKILL.md + 测试 |
| **我们** | 浏览器自动化跑通 (catfish_browser_*) | 现场跑 1 次 |
| **客户员工** | 用鲶鱼跑 1 次实际工作流 | 反馈 |

#### Week 3

| 谁 | 做什么 | 交付物 |
|---|---|---|
| **我们 + 客户** | 根据 Week 2 反馈优化 skill | SKILL.md v2 |
| **我们** | 接入第 2 个内网系统 (如有) | 第二个 skill |
| **我们 + 客户** | 联调 LLM 调用 / 凭据 / audit log | 全套日志 |
| **我们** | docx skill 套客户部门模板生成 1 份汇报材料 | .docx 文件 |

### 验收 (Week 3 末)

- [ ] 员工能用鲶鱼自动化 1-2 个真实工作流 (从口头需求到完成)
- [ ] 凭据 secret_ref 验证: 员工密码不进 LLM context (审计日志确认)
- [ ] 至少 1 份**真生成**的汇报材料 .docx, 客户部门负责人验收说"能用"
- [ ] audit JSONL 收集 50+ 条真实调用 (用作 Companion 仪表盘演示)

**不通过 → 一起评估**: 是 skill 设计问题, 还是模型能力问题, 还是流程不适合自动化. 决定改方案 / 换 skill / 停 PoC.

## Phase 1C: 团队铺开 (Week 4-6, 15 天)

### 目标

5-10 个员工试用 + 收集真实使用数据 + 确认商业条款.

### 任务

#### Week 4

| 谁 | 做什么 | 交付物 |
|---|---|---|
| **客户 IT** | 部署 .app + LaunchAgent 到 5 个员工电脑 | 装机完成 |
| **客户 IT** | 加 5 个员工到 SSO ACL | LDAP entry |
| **我们** | 给员工 30 分钟培训 (1 个 demo + 5 分钟摸索) | 培训完成确认 |
| **客户员工 (5)** | 每人用 1-2 个流程, 提反馈 | 反馈表 |

#### Week 5-6

| 谁 | 做什么 | 交付物 |
|---|---|---|
| **客户员工** | 每天用鲶鱼至少做 1 件真实工作 | audit log 数据 |
| **我们** | 每周看 audit metrics 优化 (TTFT / 模型分布 / 错误率) | 优化报告 |
| **我们 + 客户 IT** | 一起看 dashboard, 讨论团队级使用模式 | 数据洞察 |
| **客户业务部门** | 确认价值 + 商业条款讨论 | 商务对接 |

### 验收 (Week 6 末)

- [ ] 5+ 员工**主动**使用鲶鱼 ≥ 5 次 / 周 (audit log 验证)
- [ ] 鲶鱼每周帮员工节省**可量化**时间 (员工自报 + 系统数据交叉验证)
- [ ] 客户部门负责人书面 / 邮件确认: "PoC 通过, 进商务流程"
- [ ] 我们交付 PoC 报告: 数据 + 案例 + 优化建议

**通过 → 进商务流程, 谈合同**
**不通过 → 复盘, 决定改方案重 PoC 还是终止**

## 部署 (商务签约后, 1-2 周)

### 标准部署 50 人以下部门

| Day | 任务 |
|---|---|
| Day 1 | 中央服务器装 catfish-gateway / catfish-identity (Linux 服务器, Docker / 直装都行) |
| Day 2 | 部门 SSO 接入, 50 个员工 ACL 加好 |
| Day 3-4 | 50 台员工电脑装 .app + LaunchAgent (远程脚本批量) |
| Day 5 | 全员培训 (1 小时讲 + 1 小时实操) |
| Day 6-7 | 跟踪问题修, 第 1 周看 audit 异常 |

### 集团级部署 (1000+)

需要单独方案. 关键点:
- 中央 gateway 高可用 (多副本 + load balancer)
- 多部门 SSO 集成 (集团统一 SSO 还是部门各自 OIDC)
- audit 数据中心化收集 + ELK 之类
- 多模型路由策略 (集团统一采购 vs 部门自选)

集团级部署 PoC 周期更长 (~2 个月), 单独签 PoC 合同.

## 双方权责

### 客户出

- 1 台测试机 (PoC 期)
- 1 个 IT 同事 (50% 时间, PoC 期)
- 1 个内网系统访问权限
- 1 个 SSO 接入额度
- 5 个种子员工 (Phase 1C 试用期)
- 反馈 / 决策权 (每周 review 拍板)

### 我们出

- 1 个工程师 (驻场或远程, PoC 期 1-2 周, 之后远程支持)
- catfish 全套软件 + 部署
- 适配客户 1-2 个内网系统的 skill
- 培训 + 文档 + 持续优化

### 双方不出

- 客户**不必**: 提前买 license, 修改现有系统, 改员工工作习惯
- 我们**不必**: 承诺 100% 准确率, 替代你们现有 LLM 厂商, 兼容所有内网系统 (PoC 阶段挑 1-2 个最痛的)

---

## 风险点 + 应对

| 风险 | 概率 | 应对 |
|---|---|---|
| 客户 SSO 配置撞坑 | 高 | 第 1 周专门解决, dev_token 兜底先跑别的 |
| 内网系统 selector / API 找不到 | 中 | Phase 1B 加缓冲 1 周 |
| 模型幻觉 / 答错 | 中 | 关键操作员工 review 设计已就位, audit 可复盘 |
| 员工不愿意用 | 中 | 选**最痛**的工作流先做, 看到价值自然愿意 |
| 你们公司 LLM 不可达 / 慢 | 低 | gateway fallback 链自动切公网模型, 降级不停服 |
| 我们交付不及时 | 低 | 每周 5 拍板进度, 客户 IT 看得到 |

## 商务条款标准 (PoC 通过后)

### Tier 1: 部门版 (50 人以下)

- License: 一次性 X 万
- 年度维护: License 的 15-20%
- 部署: 我们驻场 1-2 周 (含)
- 培训: 全员 1 天 (含)
- 后续: 远程支持, P0 bug 24 小时响应

### Tier 2: 大部门 / 子公司版 (50-500 人)

- License: 一次性 X-Y 万 (按员工数 step pricing)
- 年度维护: License 的 15-20%
- 部署: 我们驻场 2 周
- 培训: 全员 2 天
- 高可用: 中央服务多副本 (中央 LB 加价)

### Tier 3: 集团级 (1000+)

单独谈. 包含:
- 集团 LLM 统一采购协议
- 多租户支持
- 集团审计中心 (跨部门 audit 聚合)
- 定制 skill (集团特有流程)

### 不收的钱

- ❌ API token 流水
- ❌ 员工每月使用费
- ❌ 中央服务器云费 (你们自己机房)
- ❌ LLM 调用费 (你们用自己 LLM)

我们靠**装得久 + 推广到其他部门**赚钱.

## 给客户的"PoC 决策清单" (单页打印)

```
□ Q1. 鲶鱼能解决我们部门的痛点吗?       (看 demo 后决定)
□ Q2. 我们 IT 能配合 50% 时间 6 周吗?    (内部资源协调)
□ Q3. 我们能给 1 个内网系统访问吗?       (合规批准)
□ Q4. 我们能加 5-10 个员工到 SSO 吗?    (LDAP 操作)
□ Q5. 我们能接受 6 周后没通过就停吗?    (双方权责)

5 个 yes → 启动 PoC, 6 周后看结果
任意 no → 等条件成熟再说, 我们不催
```

---

## PoC 之后

通过 → 商务 → 部署 → Phase 2 升级路径自动到位 (SSO + RBAC + Skill share + Win 跨平台)

不通过 → 复盘报告 → 客户决定再做 PoC 还是放弃 → 我们也吸收教训改产品

无论结果, **我们都给客户留下一份 PoC 全程文档** — 客户 IT 之后想自己 fork 也能拿这份文档启动.
