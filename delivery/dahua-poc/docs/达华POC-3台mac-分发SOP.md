## 为什么留这个空壳而不是直接删

同名的 SOP 一共有过**三份**。8/1 发现了两份并处理过一次, 但只找到其中两份 ——
这第三份藏在 `docs/` 下, 一直没人注意, 停在 v0.18.1 (2026-07-18)。

| 路径 | 版本 | 状态 |
|------|------|------|
| `delivery/dahua-poc/companion/…` | v0.20.0 | ✅ 在维护 |
| `edge/companion-app/scripts/…` | v0.18.1 | 空壳指针 (8/1 处理) |
| `delivery/dahua-poc/docs/…`（本文件） | v0.18.1 | 空壳指针 (8/8 处理) |

三份都叫「达华POC-3台mac-分发SOP.md」, 编辑器里按文件名搜会同时跳出来,
谁也看不出哪份是活的。

**照这份走会出什么事**: 它里面写着给员工装
`Catfish Companion_0.18.0_aarch64.dmg`, 而现在的包叫
`Catfish-Companion-0.20.0-aarch64.dmg` —— 版本号、文件名分隔符、所在目录
三样全变了。走到「发给员工」那一步会去找一个不存在的文件。

留空壳而不是删掉, 是因为**删掉解决不了走错门的问题**: 书签、聊天记录里贴过
的路径、别处文档的链接仍然指向这里, 删了得到的是「文件不存在」, 而不是
「往那边走」。

本文件不再更新。原内容见 git 历史 (`git log --follow` 这个路径)。
